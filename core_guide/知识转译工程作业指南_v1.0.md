## 概述

本规范定义了知识转译的标准作业流水线。

**三步流水线（不可逆、不可跳跃）：**
`Step 1: 知识采集` → `Step 2: 知识建模` → `Step 3: 知识具象化`

**用词说明**：
- "story"一词代指知识载体的抽象，可以是一篇博客，一张图片，一个故事，一段动画等等。

---

## 一、核心理念与边界

### 1.1 理论底座
- **认知同化**：用已知理解未知。
- **因果重构**：不解释知识，让读者通过"story"感受知识的运行过程。

### 1.2 解决的四个问题
1. **认知过载**：将复杂信息打包为四个正交维度的"概念块"，降低工作记忆压力。
2. **术语壁垒**：剥离术语伪装，直击事物的物理/逻辑实体。
3. **缺乏锚点**：通过四维锚点（结构/时序/实体/边界）为抽象概念建立物理级别的确定性联想。
4. **碎片化**：强制知识卡片依附于领域模型的骨架（核心法则）。

### 1.3 严格的效力边界（必须声明）
本流程的产出物能达到"及格的常识性理解"和"建立全局地图"的目的。
**绝对不能**让读者直接达到"专家级的应用能力"。专家能力需要在本流程之后，加上大量的"刻意练习"和"去具象化"（回到专业术语的精确世界中实操）。

## 二、三步流水线详述

### Step 1: 知识采集
- **输入**：官方文档、稳定版本源码、权威规范。
- **执行**：定位关键章节，提取概念名称、概念定义（原文）、概念属性、概念间关系。
- **输出**：`提取清单_{领域名}.md`（纯客观摘录，不加主观转译）。

### Step 2: 知识建模（产出领域模型）

- **输入**：提取清单 + [知识降维方法论](./知识降维方法论_v1.0.md)
- **执行**：
  ```
    1. **判定主导维度**：将提取清单的提取内容映射到四维矩阵（结构/时序/实体/边界），命中频率最高的 1-2 个维度即为主导维度。判定后必须为每个维度撰写1行**理解目标**（即该维度在该领域中的认知必要性，如"时序：理解协程挂起/恢复和调度循环"）。
    
    2. **提炼核心法则**：基于提取清单，归纳 1-3 条该领域的"第一性原理"或"核心矛盾"。（例：Python 底层的核心法则——"LEGB 是编译期决策，不是运行时查找"）。每条法则声明下必须展开至少1个子项，说明该法则的**生效条件或失效后果**（如矛盾点、约束条件、协作模式、关键生命周期、流控机制等），子项类型由法则性质决定。
    
    3. **推导分类规则**：根据核心法则，推导出概念的分类规则与知识卡片类型。
   
    4. **推导关系词表**：定义概念间的连接方式（必须覆盖四个维度，基础词表见附录）。
  ```
  
- **输出**：`领域模型_{领域名}.md`。
  - 包含：核心法则声明、主导维度权重、分类规则表、关系词表、关系图示。
  - **检验标准**：用该领域模型预测 3 个提取清单中未明确提及的概念分类或行为。预测准确，则模型有效。

### Step 3: 知识具象化（产出最终交付物）

- **输入**：提取清单 + 领域模型。
- **执行**：
  1. **生成知识卡片**：用四维矩阵拆解概念，填入卡片模板。薄概念按合并规则（见附录）合并。
  2. **撰写story（分两阶段）**：
   - 阶段 A：生成骨架（内部验证用）：严格按story骨架模板填写。目的是通过 S1-S3 验证清单，确保不遗漏动态交互和法则印证。此阶段允许干瘪、机械。
   - 阶段 B：润色成文（最终交付用）：基于骨架加入隐喻、场景、拟人等修辞。约束条件：润色不能引入骨架中没有的逻辑分支，不能违背目标法则，但可以改变叙述视角和修辞手法。

  !!! warring 
      阶段 B 因**缺乏合适的映射方案**达到**吸引人**和**严谨**之间的平衡，暂时使用该文档中的方式(效果不理想)产出'story'。
    
  3. **双向验证**：执行卡片工程验证（V1-V7）与story效力验证（S1-S2）。
- **最终交付物**：`story/*.md`（附带引用的知识卡片作为附录）。

## 三、知识卡片模板系统

### 3.1 卡片标准结构
废除泛化的"【属性】"字段，强制使用四维锚点
当四维锚点中的默认描述字段不属于关键描述或不能解释时，应当扩展

```
╔═══════════════════════════════════════════════════════════╗
║  【{卡片类型}】{名称}                                     ║
║  编号: {编号} | 来源: {源资料位置}                        ║
╚═══════════════════════════════════════════════════════════╝

【定义】 {一句精确的工程化描述}

【结构】"它长什么样？"  {★★★/★★/★}{按设计语义分组、拓扑位置、继承/组合关系、...；分组必须揭示字面以下的设计意图}
【时序】"它按什么顺序动？" {★★★/★★/★} {控制流、状态变迁、...}
【实体】"它的最小数据单元？" {★★★/★★/★}{关键字段、内存布局、...}
【边界】"它在哪里交出控制权？" {★★★/★★/★} {I/O断点、外部依赖、...}

【内部关联】 {关系词表中的标准关系 + 衔接点}
【外部类比】 {和其他模块的概念是否有相似性, 如果没有：精准简要地描述；没有则不包含此项}
【示例】 {代码或场景}
```
*注：主导维度标 ★★★，优先展开，篇幅最长。非主导维度标 ★ 或 ★★，简述。*

### 3.2 卡片合并策略
当概念满足以下全部条件时，合并为一个文件（避免信息碎片化）：
1. 同一卡片类型。 2. 四维锚点中 ≥2 个维度只有 1-2 行描述（极薄）。 3. 共享强配对或继承关系。 4. 独立成卡不增加新的关系边。
*操作：合并文件命名为 `{核心概念}_{类型}.md`，内部按编号分节。*

## 四、"story"模板系统（最终交付物）

### 4.1 **story标准结构**
本模板是干瘪的逻辑骨架，用于保证story的工程正确性，不作为最终交付物。

**维度-图表映射规则**：有动态过程的维度，图必须体现过程而非终态；无动态过程的维度，图锚定终态、文补充构建过程。

```
【story】{story名称}
【主导维度】{时序/边界/结构/实体}
【目标法则】{引用领域模型中的核心法则N}

【运转追踪】
  {按主导维度的逻辑展开，而非按时间流水账展开：}
  {时序主导 → 时序图：横轴时间、纵轴参与对象，箭头标注控制权流转与中间存储}
  {边界主导 → 边界交互图：类似DFD，但箭头标注时序序号，追踪数据穿界路径（外部进入→内部处理→输出到外部）}
  {结构主导 → 剖析图（锚定终态拓扑） + 构建过程文字追踪（先骨架→再填充→最后连接），图主文辅}
  {实体主导 → 数据演化图：字段-阶段矩阵（横轴阶段/纵轴字段，单元格标注状态），追踪字段从初始到完整的关系构建}

【关联见证】
  {具体场景中，A 与 B 的关系是如何运行的。必须引用知识卡片中的衔接点。}

【引用卡片】
  - {卡片1}, {卡片2}, {卡片3}...
```

### 4.2 story选材规则（按优先级）
- **S1**：每条核心法则至少 1 篇。
- **S2**：主导维度的"反直觉点"必须有story。
- **S3**：强配对/耦合关系优先写协作型story。
- **S4**：薄概念不写独立story，在相关story中带过。

### 4.3 成文润色约束（最终交付用）
基于骨架成文时，必须遵守以下约束：

1. 逻辑封闭：不得出现骨架【运转追踪】中不存在的因果节点（含图表中的箭头/标注与文字追踪中的步骤）。
2. 法则唯一性：全篇只允许一条主线印证目标法则，禁止在润色时引入新法则。
3. 视角自由：允许将骨架中的技术实体替换为隐喻实体（如 EventLoop 映射为调度中心，Task 映射为工人），但必须在文末附带"隐喻映射表"，覆盖文本实体与图表中的节点名/箭头标注。

## 五、验证机制

验证分为两层：卡片工程质量验证（V系列）与story效力验证（S系列）。**只有两层均通过，Step 3 才算结束。**

### 5.1 卡片验证（V系列）
| 编号 | 验证项 | 检查方法 |
|---|---|---|
| V1 | 覆盖完整性 | 提取清单中每个概念编号是否在某文件中有对应段落（处理合并情况）。 |
| V2 | 分类互斥性 | 每个概念是否只匹配一条分类规则。 |
| V3 | 引用完整性 | 卡片中引用的其他卡片是否存在。 |
| V4 | 关系一致性 | 关系图是否有向无环（除非逻辑允许环）。 |
| V5 | 模板完整性 | 四维锚点是否全部填充。 |
| V6 | 来源可追溯 | 每张卡片是否标注源文档位置。 |
| V7 | 语义自洽 | 定义段与四维描述无矛盾；时序的每步有因果驱动者；边界的控制权去向明确。 |

### 5.2 story验证（S系列）—— **最终交付门禁**
| 编号 | 验证项 | 检查方法 |
|---|---|---|
| S1 | 法则印证 | 读完story后，读者能否用一句话复述目标核心法则？ |
| S2 | 动态目睹 | story中是否包含了至少 2 个知识卡片间的动态交互（衔接点运行），而非静态概念罗列？ |
| S3 | 误解消除 | story是否直接回应了【认知靶点】中声明的误解？ |

## 附录（细节参考，不放入主流程）

### 附录 A：四维基础关系词表
*注：主流程中遇到关系判定时，优先在此 4 种中匹配。不满足时再扩展。*

| 关系 | 语义 | 维度 | 判定标准 |
|---|---|---|---|
| **包含** | A 生命周期持有 B | 结构 | 销毁 A 时 B 必然销毁。 |
| **触发** | A 状态变化导致 B 发生 | 时序 | A 发生后 B 必然发生（无选择权，因果链）。 |
| **配对** | A 与 B 1:1 绑定 | 边界 | 移除 B 后 A 的接口语义直接崩塌（非功能降级）。 |
| **使用** | A 依赖 B 完成功能 | 实体 | 移除 B 后 A 只是功能降级，接口语义仍在。 |

### 附录 B：关系衔接点标注协议
*注：用于卡片【关联】字段和story【关联见证】字段。*

格式：`A.{方法/状态} --[关系词]--> B.{方法/状态}`
要求：两侧粒度对等；时序关系必须有因果方向；边界关系必须标注控制权去向。

### 附录 C：V7 语义自洽子检验
- **V7a 定义独立**：定义段与结构段不矛盾。
- **V7b 关系双向**：A 标注关系 R，B 必有反向标注。
- **V7c 时序有因**：时序中每个 `→` 左侧必须是具体动作。
- **V7c+ 时序流向精确**：时序中每个 `→` 右侧必须明确数据/控制权的完整去向（中间存储、耗时步骤不可省略）。禁止用"触发回调"等模糊表述替代精确的流转路径（如"回调被添加到_ready队列"）。
- **V7d 边界闭合**：边界点必须明确"交给谁"。

### 附录 D：知识卡片视觉渲染映射协议
注：本协议用于将四维锚点的文本数据映射为视觉"形状"，利用视觉皮层分担语义认知负荷。

D.1 面积映射主导维度（★★★）的锚点区块，在视觉上必须占据卡片最大的物理面积（不小于卡片总宽度的 50%）。

D.2 边界视觉特征【边界】锚点区块必须带有视觉上的"断裂"或"警示"特征（如红色虚线边框、锯齿边缘、渐变消失）。因为边界本质上是系统与外部不可控世界的物理断层，视觉上必须传达"到此为止"的语义。

D.3 关联视觉特征【关联】字段中的衔接点（如 A.method() --[触发]--> B.method()），不能是纯文本。必须渲染为带箭头的连线或流程节点，因为它的本质是控制流/数据流的物理通道。
