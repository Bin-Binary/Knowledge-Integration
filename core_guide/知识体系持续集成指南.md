# 《知识体系持续集成指南》

## 核心理念

以持续集成的思维理解知识体系：**允许不完美，接受增量改进。** 一套方法论的价值在于它能解决部分问题并持续演化，而非一次性达到完备。

当新的认知缺口被发现时，不回推推翻已有工作，而是**定位最小影响范围、局部修订、连锁验证、记录变更**。

---

## 触发条件

| 触发类型 | 表现 | 示例 |
|---------|------|------|
| 认知缺口发现 | 现有框架无法推导某个已知现象 | EventLoop无法从代价集群推导 |
| 外部新知注入 | 接触到新的同类系统、文献、观点 | 分析tokio后发现新的转换层 |
| 边界模糊发现 | 已有分类/判定标准在新场景下失效 | 某项影响既可归为主也可归为辅 |
| 推导演绎失败 | 按流程推导的结论与源码/事实不符 | 推导出的设计与实际实现矛盾 |

满足任一即触发集成流程。

---

## 集成流程

### 1. 记录发现

在对应产物的附录中记录发现：

- **现象**：客观事实描述
- **现有框架解释**：当前框架如何(或无法)解释此现象
- **失效位置**：框架在哪个环节断裂

### 2. 分类影响层级

| 影响层级 | 表现 | 处理方式 |
|---------|------|---------|
| **协议层** | 分析方法缺失或不足 | 新增/修订协议文档(如core_guide中的协议) |
| **模型层** | 推导链断裂或遗漏 | 修订具体模型产物(S0/S1/S2/S3) |
| **图示层** | 约束绕过/违反判断错误 | 修订约束图示 |
| **验证层** | 验证项不充分 | 增强验证标准 |

影响可能跨多个层级，逐一判定。

### 3. 局部修订

按**最小影响范围**原则：

- 协议层变更：先修订协议，再评估哪些已有产物需要按新协议重新执行
- 模型层变更：定位受影响的最小节点范围，只修订该节点及其下游
- 图示层变更：只修订受影响的图示文件
- 验证层变更：增加验证项，对已有产物补充验证

### 4. 连锁检查

修订后沿依赖链检查：

```
协议修订 ---> 所有使用该协议的模型产物
S0修订  ---> S3的N0节点(继承影响是否变化)
S1修订  ---> S2(0号约束是否受影响)
S2修订  ---> S3所有引用该约束的节点
S3某节点修订 ---> 下游所有节点的构建依赖是否仍成立
```

### 5. 验证闭环

修订后重新执行受影响范围内的验证：

| 验证项 | 验证内容 | 来源 |
|-------|---------|------|
| 目标达成验证 | G是否仍满足 | 现有S3 |
| 约束守恒验证 | 所有0号约束是否仍守恒 | 现有S3 |
| 内生动力真实性验证 | 动力来源是否仍可追溯 | 现有S3 |
| **完整代价覆盖验证** | 继承影响+自身代价是否全部有设计响应 | 新增(范式转换约束提取协议) |
| **转换前提满足验证** | 本源转换的前提条件是否全部在上游转换中满足 | 新增(范式转换约束提取协议) |

## 变更记录规范

每次集成写入变更记录，格式：

```markdown
## [日期] 集成记录 #{序号}

### 触发
{触发类型}: {触发描述}

### 分析
- 现象: {客观事实}
- 失效位置: {哪个产物/环节}
- 影响层级: {协议/模型/图示/验证}

### 变更
- [新增/修订]: {文档名} - {变更摘要}
- [新增/修订]: {文档名} - {变更摘要}

### 连锁检查
- {产物A}: {已检查/无需修订/已修订}
- {产物B}: {已检查/无需修订/已修订}

### 验证
- [ ] 目标达成验证
- [ ] 约束守恒验证
- [ ] 内生动力真实性验证
- [ ] 完整代价覆盖验证
- [ ] 转换前提满足验证

### 待处理
{尚不确定的问题，标注"待定"}
```

---

## 不确定部分处理原则

1. 不确定部分写入附录，标注"待定"
2. "待定"不阻塞当前分析流程，允许在不确定中继续前进
3. 后续集成时可升级"待定"为"确定"，也可降级为"不适用"
4. "待定"项经3次迭代仍未解决，标记为"长期待定"，在下一次全面复核时重新评估
5. 所有"待定"项追踪清单存于模型产物的附录末尾

---

## 迭代节奏

不做强制的定期迭代，而是**事件驱动**：发现即集成。

但以下时机宜进行全面复核：
- 完成新框架的完整分析后(可在不同框架间交叉验证方法论)
- "待定"项累积超过5个时
- 协议层修订超过2次且未做连锁检查时
