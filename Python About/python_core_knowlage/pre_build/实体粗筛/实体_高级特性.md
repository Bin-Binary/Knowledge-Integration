╔═══════════════════════════════════════════════════════════╗
║  【元编程】装饰器 decorator                                ║
║  编号: E030 | 来源: 提取清单C110+C111                     ║
╚═══════════════════════════════════════════════════════════╝

【定义】 装饰器是接受可调用对象并返回新可调用对象的高阶函数/类, @语法糖在编译时将紧随其后的函数/类传递给装饰器, 等价于 func=decorator(func)。

【结构】"它长什么样？"
- 装饰器本质: callable → callable (函数/类/带__call__的对象)
- @decorator: 等价于 target = decorator(target)
- @decorator(args): 等价于 target = decorator(args)(target) — 装饰器工厂返回真正的装饰器
- 装饰器可堆叠: @d1/@d2/@d3 从下往上应用: f = d1(d2(d3(f)))
- functools.wraps: 将原函数的__name__/__doc__/__module__等元信息复制到包装函数

【时序】"它按什么顺序动？"
- 导入/执行时: 定义被装饰函数时立即执行装饰器(非调用被装饰函数时)
- 调用时: 被装饰后的函数每次调用都经过包装函数的逻辑
- 堆叠装饰器执行顺序: 从内向外(bottom-up)

【实体】"它的最小数据单元？"
- decorator: Python可调用对象

【边界】"它在哪里交出控制权？"
- @语法是纯语法糖: 完全等价于手动包装, 无特殊运行时支持
- wraps不存在时: 包装函数丢失原函数的元信息(破坏自省)
- 装饰器class: 若用于装饰普通函数可能破坏__call__语义
- 装饰器工厂: 两层嵌套, 外层在import时执行, 内层每次调用时执行

【内部关联】
- @decorator --[触发(包装→替换)]--> target = decorator(target)
- functools.wraps --[使用(元信息→复制)]--> __name__/__doc__/__wrapped__

【薄概念合并】 C110+C111

【示例】
```python
import functools

def trace(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        result = func(*args, **kwargs)
        print(f"Returned {result}")
        return result
    return wrapper

@trace
def add(a, b):
    return a + b

print(add(3, 4))  # Calling add → Returned 7 → 7

# 装饰器工厂
def repeat(n):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(n):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def greet(name):
    print(f"Hi {name}")

greet("World")  # 打印3次
```

╔═══════════════════════════════════════════════════════════╗
║  【元编程】注解 annotations                                ║
║  编号: E031 | 来源: 提取清单C112+C114                     ║
╚═══════════════════════════════════════════════════════════╝

【定义】 注解是附加在函数参数/返回值上的元数据表达式, Python本身不做类型检查, 存储在__annotations__字典中。PEP 604(Python 3.10)和PEP 695(Python 3.12)增强了类型提示语法。

【结构】"它长什么样？"
- __annotations__: dict, key为参数名(含"return"), value为注解表达式求值结果
- 位置: func.__annotations__, class.__annotations__, module.__annotations__
- from __future__ import annotations: 所有注解变为字符串(延迟求值, Python 3.11+默认)
- typing模块: 类型提示的官方支持(List[int], Dict[str, float], Optional[X], Union[A,B])

【时序】"它按什么顺序动？"
- 函数定义时: 注解表达式立即求值并存为__annotations__ dict
- 若启用__future__ annotations: 注解保留为字符串(不执行表达式)
- 运行时: 注解只是存储在__annotations__里的普通数据, 毫无运行时作用

【实体】"它的最小数据单元？"
- func.__annotations__: dict {"param1": int, "return": str}

【边界】"它在哪里交出控制权？"
- 注解无运行时类型检查: 必须用typeguard/pydantic/mypy等外部工具
- annotations字符串化: 启用后注解中的类型需 import typing.get_type_hints()获取真实类型
- 内存: __annotations__是普通dict, 无额外开销

【薄概念合并】 C112+C114

【示例】
```python
def greet(name: str, age: int) -> str:
    return f"{name} is {age}"

print(greet.__annotations__)  # {'name': <class 'str'>, 'age': <class 'int'>, 'return': <class 'str'>}

# typing模块
from typing import List, Dict, Optional

def process(items: List[str], config: Optional[Dict[str, int]] = None) -> List[str]:
    return [i.upper() for i in items]

# get_type_hints (处理字符串化注解)
import typing
hints = typing.get_type_hints(greet)
print(hints)  # {'name': str, 'age': int, 'return': str}
```

╔═══════════════════════════════════════════════════════════╗
║  【字符串格式化】f-string                                  ║
║  编号: E032 | 来源: 提取清单C113                          ║
╚═══════════════════════════════════════════════════════════╝

【定义】 f-string (formatted string literal) 是 f"..." 前缀字符串, 花括号{}内嵌Python表达式, 运行时求值并格式化, 性能优于传统%格式化和.format()。

【结构】"它长什么样？"
- f"{expr}" → 表达式expr求值 → __format__()魔术方法 → 格式化 → 字符串
- f"{expr=}" → 打印表达式的文本+等号+值 (Python 3.8+)
- f"{expr:spec}" → 格式化说明符(spec): .2f, .0%, >10, 0>5d等
- 编译: f-string编译为字节码FORMAT_VALUE, 比"{}".format()少一次方法查找
- 嵌套: f"{value:{width}.{precision}f}" 支持嵌套表达式

【时序】"它按什么顺序动？"
- 编译时: 解析f-string文本, 生成FORMAT_VALUE字节码
- 运行时: 求值每个expr → 调用obj.__format__(spec) → 拼接
- 性能: 比 % 快(无解析), 比 .format() 快(无查找)

【实体】"它的最小数据单元？"
- 无独立类型, 纯语法糖编译为字节码

【边界】"它在哪里交出控制权？"
- 仅限字面量: f-string必须在源码定义时写定(不可从变量动态生成格式字符串)
- 反斜杠限制: f-string花括号内不能有反斜杠(\)
- 安全问题: f"{user_input}" 不存在注入(非SQL), 但f"eval({expr})"危险

【示例】
```python
name = "Python"
version = 3.14
print(f"{name} {version}")           # Python 3.14

# 格式说明符
pi = 3.1415926
print(f"{pi:.2f}")                   # 3.14

# 表达式+调试
x = 10
print(f"{x+5=}")                     # x+5=15

# 嵌入格式
value = 12.34567
width, prec = 10, 3
print(f"{value:{width}.{prec}f}")    # "    12.346"

# 日期格式化
from datetime import datetime
print(f"{datetime.now():%Y-%m-%d %H:%M:%S}")
```
