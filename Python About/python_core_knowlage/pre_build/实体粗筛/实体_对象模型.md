# 实体粗筛: Python对象模型

> Step 2 产出 | 来源: 提取清单 C000-C005, C123

---

╔═══════════════════════════════════════════════════════════╗
║  【概念模型】Python对象模型                                ║
║  编号: E001 | 来源: 提取清单C001+C000+C005+C123           ║
╚═══════════════════════════════════════════════════════════╝

【定义】 Python中一切数据均为对象，每个对象由id(标识)、type(类型)、value(值)三元组唯一确定；变量名是对对象的引用绑定。

【结构】"它长什么样？"
- CPython中每个对象继承自PyObject基类: ob_refcnt(引用计数) + ob_type(指向类型对象指针)
- 类型对象(PyTypeObject)记录类型的元信息: tp_name, tp_basicsize, tp_dealloc, tp_hash等
- id()返回对象在CPython中的内存地址(PyObject*指针)
- type()返回对象的类型对象; __class__属性指向相同对象
- 对象图是二分图: 实例对象 ↔ 类型对象, 所有类型对象的type是type, type的type是自身

【时序】"它按什么顺序动？"
- 赋值(=): 计算右侧表达式(创建或获取对象) → 将左侧名字绑定到对象引用 → 若旧引用的refcnt-1
- 属性访问(obj.attr): 在obj.__dict__中查找 → 未找到则在type(obj).__dict__中查找 → 沿MRO链上溯
- 对象销毁: refcnt→0时 → tp_dealloc被调用 → 释放内存
- is比较: 直接比对两个PyObject*指针值, O(1)
- ==比较: 调用对象的__eq__方法 → 默认(未定义时)退化为is比较

【实体】"它的最小数据单元？"
- PyObject: ob_refcnt(ssize_t, 引用计数器) + ob_type(PyTypeObject*, 类型指针)
- PyVarObject: 继承PyObject, 增加ob_size(Py_ssize_t, 变长对象元素数)
- 类型对象关键字段: tp_name(名称), tp_basicsize(实例大小), tp_dictoffset, tp_alloc, tp_free
- 不可变对象: int/str/tuple/frozenset — 值创建后不可原地修改
- 可变对象: list/dict/set/bytearray/自定义类实例 — 值可原地修改
- 可哈希对象: 不可变且所有子元素均可哈希 — 可作dict key和set元素

【边界】"它在哪里交出控制权？"
- 对象创建(tp_alloc): 调用C内存分配器(malloc), 可能触发GC
- 对象销毁(tp_dealloc): 触发引用计数递减, 可能触发gc.collect
- 属性查找失败: __getattr__/__getattribute__钩子 → 可能抛AttributeError
- 类型检查: isinstance/issubclass需要遍历整个MRO链(开销随继承深度线性增长)
- 对象的__hash__调用: 若对象未定义则退回id()(仅不可变类型可自定义hash)

【内部关联】
- PyObject.ob_refcnt --[配对(持有者→被持有者)]--> GC追踪
- PyObject.ob_type --[配对(实例→元类型)]--> PyTypeObject
- type.__class__ --[配对(类型→元类型)]--> type自身
- name --[使用(名字→对象)]--> PyObject (通过名字空间字典)
- is运算符 --[触发(身份比较→指针比较)]--> id()地址值
- __eq__ --[触发(值比较→用户定义)]--> 自定义等值判定

【薄概念合并】 C002(id) + C003(动态类型) + C004(name binding) + C005(可变vs不可变) + C123(is vs ==) 均共享对象模型母题, 四维锚点高度重合, 合并于此。

╔═══════════════════════════════════════════════════════════╗
║  【概念模型】Python语言哲学                                ║
║  编号: E001a | 来源: 提取清单C000                        ║
╚═══════════════════════════════════════════════════════════╝

【定义】 Python设计遵循"可读性>简洁性>性能"优先级, 用强制缩进替代花括号, 用异常替代错误码, 用动态类型和鸭子类型实现灵活的多态。

【结构】"它长什么样？"
- 编译时: 源码→AST→符号表→CFG→字节码(PyCodeObject)
- 运行时: 字节码→PVM(主循环在ceval.c的_PyEval_EvalFrameDefault)
- 解释型: 无需显式编译步骤, 但内部有自动.py→.pyc编译缓存

【时序】"它按什么顺序动？"
- 源码→词法解析(tokenize)→语法分析(parse to AST)→语义分析(符号表)→编译(字节码)→执行(PVM)
- import时自动生成.pyc缓存于__pycache__目录

【实体】"它的最小数据单元？"
- PyCodeObject: co_code(字节码), co_consts(常量元组), co_names(变量名元组), co_varnames+co_freevars
- 栈帧: PyFrameObject包含上一帧指针、指令指针、栈顶指针、locals/globals字典

【边界】"它在哪里交出控制权？"
- 字节码执行: 每条字节码分派是CPU控制权的交还点(解释循环)
- 异常抛出: 跳出正常执行流程, 沿调用栈回溯寻找except
- 系统调用: 任何I/O操作穿越至OS内核

【内部关联】
- PyCodeObject --[包含(代码→字节码)]--> co_code
- PyFrameObject --[包含(帧→代码)]--> PyCodeObject (通过f_code)
- 异常 --[触发(异常传播→栈展开)]--> 帧链回溯

【示例】
```python
# 对象模型
a = 256         # 创建int对象, a绑定到它
b = 256         # 小整数(-5~256)被缓存, b指向同一对象
print(a is b)   # True (CPython优化)

a = 257
b = 257
print(a is b)   # False (不同对象)
print(a == b)   # True (值相等)

# 类型对象关系
print(type(int))    # <class 'type'>
print(type(type))   # <class 'type'>  自指
```
