# Python核心基础(十一): 写更Pythonic的代码——装饰器、注解与f-string

## 引言

在 Java 中,注解(Annotation)是**纯粹的元数据**——通过 `@Retention` 策略(SOURCE/CLASS/RUNTIME)控制生命周期,由注解处理器(Annotation Processor)在编译期或反射 API 在运行期消费,注解本身**不会修改**被标注元素的任何行为。在 Rust 中,属性(Attribute)和宏(Macro)是 **AST 变换**——`#[derive(Debug)]` 是声明式宏,`proc_macro` 是过程宏,编译器在语法树层面插入/替换代码,零运行时开销但编译期认知负担重。在 JavaScript 中,模板字面量(Template Literal)是字符串插值——`` `Hello ${name}` `` 在运行时求值,支持标签函数(tag function)自定义处理,但没有编译期优化。在 C# 中,特性(Attribute)是元数据+反射——`[Serializable]` 编译为元数据,运行时通过反射读取,与 Java 类似。

Python 做了一个**足够激进的三个选择**:

1. **装饰器是高阶函数**——`@decorator` 在**定义时**立即执行,`def f(): pass` 被替换为 `f = decorator(f)`。这不是元数据标注,而是**运行时变换**,装饰器可以完全替换函数、修改行为、注入依赖、注册组件。装饰器必须是可调用对象(函数、带 `__call__` 的类、任何实现了调用协议的对象)。

2. **类型注解是可选的元数据**——`def f(x: int) -> str:` 将注解存入 `f.__annotations__` 字典,但 Python 运行时**完全不强制类型检查**。类型提示是"文档+静态分析工具的契约",opt-in 使用 `mypy`、`pyright` 等工具在开发期检查,运行期零开销。

3. **f-string 是编译期优化的字符串插值**——`f"{x + y}"` 在编译期解析为 `FORMAT_VALUE` 字节码,表达式在当前作用域直接求值并格式化,不经过 `eval()`,比 `%` 格式化和 `str.format()` 更快更安全,但牺牲了模板的可复用性。

**Tradeoff 三元组**:

| 特性 | 灵活性 | 性能 | 安全性 | 典型代价 |
|:---|:---|:---|:---|:---|
| 装饰器 | **极高**(可任意修改函数/类) | 中等(调用多一层间接) | 中等(装饰器可能有副作用) | 调试时 `__name__` 丢失需 `functools.wraps` 修复 |
| 类型注解 | 高(静态类型系统的表达力) | **零运行时开销** | 低(运行时不强制) | 依赖外部工具(mypy),多一种认知负担 |
| f-string | 中(表达式内嵌但无模板) | **最快**(编译期优化) | 高(编译期解析,无 `eval` 风险) | 不可复用,无法动态构建格式串 |

理解这三个特性,不只是知道 `@decorator` 是语法糖、`: type` 是类型提示、`f"{x}"` 是格式化字符串这些表面语法。它是写出 **Pythonic 代码**的核心能力:为什么装饰器必须返回可调用对象?为什么类型注解存为字符串(PEP 563)?为什么 f-string 比 `str.format()` 快?为什么 `@functools.lru_cache()` 可以缓存任意函数?这些问题的答案回溯到同一个根——Python 的**运行时元编程能力**与**编译期优化策略**的平衡。

本文将追踪装饰器从**语法糖展开、字节码执行、高阶函数变换**的完整过程,揭示类型注解在 `__annotations__` 中的存储与延迟求值机制,解剖 f-string 从**词法分析、AST 构建、字节码生成**的编译期优化路径。你将亲手实现手写装饰器、注解验证器、性能对比实验,理解 Python 如何在"动态语言的灵活性"与"静态语言的性能/安全"之间找到第三条路。

## 一、装饰器——@语法糖的高阶函数机制

### 1.1 装饰器的本质——从语法糖到高阶函数

装饰器本质上非常简单:**`@decorator` 是一个语法糖,将被装饰的对象作为参数传递给装饰器,用返回值替换原对象**。

**语法糖展开**:

```python
@decorator
def f():
    pass

# 完全等价于 ↓

def f():
    pass
f = decorator(f)    # ← 唯一的真相
```

**关键点**:

1. **装饰器必须在定义时可调用**——`decorator` 必须实现 `tp_call` 槽(函数、带 `__call__` 的类、`functools.partial` 等)
2. **装饰器的返回值成为新的绑定**——`f` 被重新绑定到 `decorator(f)` 的返回值,原函数对象可能被丢弃、被包装、被注册
3. **应用时机是函数定义时**——不是调用时,是 `def` 语句执行的那一刻

**CPython 字节码验证——`MAKE_FUNCTION` → `CALL_FUNCTION` → `STORE_NAME`**:

```python
import dis

def my_decorator(func):
    return func

@my_decorator
def greet(name):
    return f"Hello, {name}"

# 查看字节码
print("=== 装饰后的函数定义字节码 ===")
dis.dis(compile(
    "@my_decorator\ndef greet(name):\n    return f'Hello, {name}'",
    "<string>", "exec"
))
```

**输出**:

```
=== 装饰后的函数定义字节码 ===
  2           0 LOAD_NAME                0 (my_decorator)
              2 LOAD_CONST               0 ('greet')
              4 BUILD_TUPLE              0
              6 BUILD_MAP                0
              8 MAKE_FUNCTION            8 (name, defaults, kwdefaults, annotations)
             10 LOAD_NAME                1 (f)
             12 LOAD_CONST               2 ('Hello, ')
             14 FORMAT_VALUE             0
             16 BUILD_STRING             2
             18 RETURN_VALUE
             20 CALL_FUNCTION            1    # ← 调用装饰器
             22 STORE_NAME               1 (greet)  # ← 将返回值绑定到 greet
             24 LOAD_CONST               3 (None)
             26 RETURN_VALUE
```

**字节码执行流程**:

```
栈操作:
1. LOAD_NAME my_decorator  → 栈:[my_decorator]
2. MAKE_FUNCTION           → 栈:[my_decorator, <function greet>]
3. CALL_FUNCTION 1         → 弹出 my_decorator 和 <function greet>,调用 my_decorator(<function greet>),结果压栈
4. STORE_NAME greet        → 弹栈顶,绑定到变量 greet
```

**实验 1:手动应用装饰器——绕过 `@` 语法**:

```python
def log_calls(func):
    """记录函数调用次数的装饰器"""
    call_count = 0
    
    def wrapper(*args, **kwargs):
        nonlocal call_count
        call_count += 1
        print(f"[{func.__name__}] 调用 #{call_count}: args={args}, kwargs={kwargs}")
        result = func(*args, **kwargs)
        print(f"[{func.__name__}] 返回: {result}")
        return result
    
    return wrapper

# 方式 1: 使用 @ 语法
@log_calls
def add(a, b):

def multiply(a, b):

print("\n=== 测试手动装饰的函数 ===")

multiply(4, 5)

# 验证:两种方式得到的对象类型相同
print(f"\nadd 的类型: {type(add)}")
print(f"multiply 的类型: {type(multiply)}")
print(f"add 是 wrapper: {add.__name__}")
print(f"multiply 是 wrapper: {multiply.__name__}")
```

### 1.2 函数装饰器——包装行为与身份保留

函数装饰器最常见的形式:**接收函数,返回包装函数,包装函数添加额外行为后调用原函数**。

**简单装饰器模式**:

```python
def timing_decorator(func):
    """计时装饰器:测量函数执行时间"""
    import time
    
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        end = time.perf_counter()
        print(f"{func.__name__} 执行耗时: {(end - start) * 1000:.2f} ms")
        return result
    
    return wrapper

@timing_decorator
def slow_function(n):
    """一个故意延迟的函数"""
    import time
    time.sleep(n * 0.1)
    return n * 100

result = slow_function(3)
print(f"结果: {result}")
```

**问题:装饰后函数"身份丢失"**:

```python
def identity_decorator(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@identity_decorator
def important_function(x):
    """这是一个非常重要的函数"""
    return x ** 2

print(f"函数名: {important_function.__name__}")  # 输出: wrapper  ← 错误!
print(f"文档字符串: {important_function.__doc__}")  # 输出: None  ← 错误!
print(f"原函数名: {important_function.__wrapped__.__name__}")  # AttributeError  ← 没有 __wrapped__
```

**解决方案:`functools.wraps`——复制函数元数据**:

```python
import functools

def proper_decorator(func):
    @functools.wraps(func)  # ← 复制 func 的元数据到 wrapper
    def wrapper(*args, **kwargs):
        """Wrapper 的文档(会被覆盖)"""
        return func(*args, **kwargs)
    return wrapper

@proper_decorator
def important_function(x):
    """这是一个非常重要的函数"""
    return x ** 2

print(f"函数名: {important_function.__name__}")  # 输出: important_function  ✓
print(f"文档字符串: {important_function.__doc__}")  # 输出: 这是一个非常重要的函数  ✓
print(f"是否保留原函数: {hasattr(important_function, '__wrapped__')}")  # True
```

**`functools.wraps` 的实现原理**:

```python
# functools.wraps 的简化实现
WRAPPER_ASSIGNMENTS = ('__module__', '__name__', '__qualname__', '__annotations__',
                       '__doc__', '__wrapped__')
WRAPPER_UPDATES = ('__dict__',)  # 字典合并,而非覆盖

def wraps(wrapped):
    """装饰器:将 wrapped 的属性复制到 wrapper"""
    def decorator(wrapper):
        # 复制属性
        for attr in WRAPPER_ASSIGNMENTS:
            try:
                value = getattr(wrapped, attr)
            except AttributeError:
                pass
            else:
                setattr(wrapper, attr, value)
        
        # 更新 __dict__
        for attr in WRAPPER_UPDATES:
            getattr(wrapper, attr).update(getattr(wrapped, attr, {}))
        
        return wrapper
    return decorator
```

**被复制的属性详解**:

| 属性 | 含义 | 不保留的后果 |
|:---|:---|:---|
| `__name__` | 函数名 | 调试时看到 `wrapper` 而非原函数名,混淆 |
| `__qualname__` | 限定名(含类名) | 嵌套函数时无法追溯定义位置 |
| `__module__` | 所属模块 | `pickle` 序列化失败,无法找到函数 |
| `__doc__` | 文档字符串 | `help()` 看不到文档 |
| `__annotations__` | 类型注解 | 类型检查器丢失信息,`__wrapped__` 丢失 |
| `__dict__` | 函数属性字典 | 自定义属性丢失 |

**堆叠装饰器——应用顺序是自底向上**:

```python
def decorator_a(func):
    print(">>> 装饰器 A 被应用")
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print("[A] Before")
        result = func(*args, **kwargs)
        print("[A] After")
        return result
    return wrapper

def decorator_b(func):
    print(">>> 装饰器 B 被应用")
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print("[B] Before")
        result = func(*args, **kwargs)
        print("[B] After")
        return result
    return wrapper

# 堆叠顺序:自底向上应用
@decorator_a
@decorator_b
def func():
    print("[Original] Function body")

# 等价于:func = decorator_a(decorator_b(func))

print("\n=== 调用被装饰的函数 ===")
func()
```

**输出**:

```
>>> 装饰器 B 被应用    ← 先应用底部的装饰器
>>> 装饰器 A 被应用    ← 再应用顶部的装饰器

=== 调用被装饰的函数 ===
[A] Before
[B] Before
[Original] Function body
[B] After
[A] After
```

**执行流程图解**:

```
定义阶段:
func = decorator_a(decorator_b(func_original))
       ↑                    ↑
       |                    └── 先执行:返回 wrapper_b
       └── 后执行:包装 wrapper_b,返回 wrapper_a

调用阶段:
wrapper_a()
  → print("[A] Before")
  → wrapper_b()
      → print("[B] Before")
      → func_original()
          → print("[Original] Function body")
      → print("[B] After")
  → print("[A] After")
```

### 1.3 装饰器工厂——参数化装饰器的三层嵌套

当装饰器需要参数时,需要**三层函数嵌套**:

```python
@decorator(arg1, arg2)
def func():
    pass

# 展开为 ↓
func = decorator(arg1, arg2)(func)

# 即 ↓
factory_result = decorator(arg1, arg2)  # 第一次调用:返回装饰器
func = factory_result(func)              # 第二次调用:装饰函数
```

**装饰器工厂模式**:

```python
import functools

def repeat(times):
    """装饰器工厂:让函数重复执行 times 次"""
    print(f">>> 装饰器工厂被调用,参数 times={times}")
    
    def decorator(func):  # 真正的装饰器
        print(f">>> 装饰器被应用,包装函数 {func.__name__}")
        
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            results = []
            for i in range(times):
                print(f"  [第 {i+1}/{times} 次执行]")
                result = func(*args, **kwargs)
                results.append(result)
            return results[-1] if results else None  # 返回最后一次结果
        
        return wrapper
    
    return decorator

@repeat(3)  # ← 注意这里有括号!
def greeting(name):
    print(f"Hello, {name}!")
    return name.upper()

print("=== 调用被装饰的函数 ===")
result = greeting("Alice")
print(f"最终返回: {result}")
```

**输出**:

```
>>> 装饰器工厂被调用,参数 times=3
>>> 装饰器被应用,包装函数 greeting

=== 调用被装饰的函数 ===
  [第 1/3 次执行]
Hello, Alice!
  [第 2/3 次执行]
Hello, Alice!
  [第 3/3 次执行]
Hello, Alice!
最终返回: ALICE
```

**三层函数的角色映射**:

```
repeat(times)           ← 工厂函数(接收装饰器参数)
    └── decorator(func)     ← 装饰器(接收被装饰的函数)
        └── wrapper(*args, **kwargs)  ← 包装函数(运行时调用)

参数流动:
times → decorator → wrapper → func
```

**实验 2:实现带条件的装饰器工厂**:

```python
import functools

def conditional(condition):
    """根据条件决定是否应用装饰"""
    def decorator(func):
        if not condition:
            # 条件不满足,返回原函数(无装饰)
            print(f">>> 条件 {condition} 为假,跳过装饰")
            return func
        
        print(f">>> 条件 {condition} 为真,应用装饰")
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            print(f"[条件装饰] 执行 {func.__name__}")
            return func(*args, **kwargs)
        
        return wrapper
    
    return decorator

DEBUG_MODE = True

@conditional(DEBUG_MODE)
def debug_func():
    return "Debug result"

@conditional(not DEBUG_MODE)
def release_func():
    return "Release result"

print(f"debug_func 被装饰: {debug_func.__name__ != 'debug_func'}")
print(f"release_func 被装饰: {release_func.__name__ != 'release_func'}")
```

### 1.4 类装饰器——用类替代函数作为装饰器

装饰器可以是**任何可调用对象**——类只要实现 `__call__` 方法就能作为装饰器。

**类作为装饰器的两种形式**:

#### 形式 1:类装饰函数

```python
class CountCalls:
    """类作为装饰器:计数器类"""
    
    def __init__(self, func):
        print(f">>> CountCalls 初始化,接收函数 {func.__name__}")
        self.func = func
        self.count = 0
        functools.update_wrapper(self, func)  # 复制元数据
    
    def __call__(self, *args, **kwargs):
        """实例变为可调用"""
        self.count += 1
        print(f"[{self.func.__name__}] 第 {self.count} 次调用")
        return self.func(*args, **kwargs)

@CountCalls
def say_hello(name):
    """问候函数"""
    return f"Hello, {name}!"

# say_hello 现在是 CountCalls 的实例
print(f"say_hello 的类型: {type(say_hello)}")  # <class '__main__.CountCalls'>
print(f"say_hello 是 CountCalls 实例: {isinstance(say_hello, CountCalls)}")  # True

# 调用
print(say_hello("Alice"))
print(say_hello("Bob"))
print(f"总调用次数: {say_hello.count}")
```

**输出**:

```
>>> CountCalls 初始化,接收函数 say_hello
say_hello 的类型: <class '__main__.CountCalls'>
say_hello 是 CountCalls 实例: True
[say_hello] 第 1 次调用
Hello, Alice!
[say_hello] 第 2 次调用
Hello, Bob!
总调用次数: 2
```

#### 形式 2:函数装饰类

```python
def add_logging(cls):
    """装饰类:为所有公有方法添加日志"""
    import functools
    
    for name, method in cls.__dict__.items():
        if callable(method) and not name.startswith('_'):
            # 包装每个公有方法
            @functools.wraps(method)
            def logged_method(self, *args, _method=method, **kwargs):
                print(f"[LOG] 调用 {cls.__name__}.{_method.__name__}")
                return _method(self, *args, **kwargs)
            
            setattr(cls, name, logged_method)
    
    return cls

@add_logging
class Calculator:
    def add(self, a, b):
        return a + b
    
    def multiply(self, a, b):
        return a * b
    
    def _private_method(self):
        """私有方法不会被装饰"""
        return "private"

calc = Calculator()
print(calc.add(1, 2))
print(calc.multiply(3, 4))
print(calc._private_method())  # 无日志
```

**输出**:

```
[LOG] 调用 Calculator.add
3
[LOG] 调用 Calculator.multiply
12
private
```

#### 形式 3:类装饰类——单例模式

```python
def singleton(cls):
    """单例装饰器:确保类只有一个实例"""
    instances = {}
    
    @functools.wraps(cls)
    def get_instance(*args, **kwargs):
        if cls not in instances:
            print(f">>> 创建单例实例: {cls.__name__}")
            instances[cls] = cls(*args, **kwargs)
        else:
            print(f">>> 返回已存在的单例: {cls.__name__}")
        return instances[cls]
    
    return get_instance

@singleton
class Database:
    def __init__(self, connection_string):
        self.connection_string = connection_string
        print(f"Database 初始化: {connection_string}")
    
    def query(self, sql):
        return f"Executing: {sql}"

# 测试单例
db1 = Database("mysql://localhost")
db2 = Database("mysql://localhost")  # 不会重新初始化

print(f"db1 is db2: {db1 is db2}")  # True
print(db1.query("SELECT * FROM users"))
```

**输出**:

```
>>> 创建单例实例: Database
Database 初始化: mysql://localhost
>>> 返回已存在的单例: Database
db1 is db2: True
Executing: SELECT * FROM users
```

**注意**:singleton 装饰器将类替换为函数,`isinstance` 检查会失败:

```python
print(f"isinstance(db1, Database): {isinstance(db1, Database)}")  # False!
# 因为 Database 现在是 get_instance 函数,不是类
```

**修复:保留原类的单例实现**:

```python
def singleton_preserve_class(cls):
    """单例装饰器:保留类的身份"""
    original_init = cls.__init__
    instance = None
    
    def new_init(self, *args, **kwargs):
        nonlocal instance
        if instance is None:
            print(f">>> 创建单例实例: {cls.__name__}")
            original_init(self, *args, **kwargs)
            instance = self
        else:
            print(f">>> 返回已存在的单例: {cls.__name__}")
            self.__dict__ = instance.__dict__.copy()
    
    cls.__init__ = new_init
    return cls

@singleton_preserve_class
class ProperDatabase:
    def __init__(self, conn_str):
        self.conn_str = conn_str

db3 = ProperDatabase("postgres://localhost")
print(f"isinstance(db3, ProperDatabase): {isinstance(db3, ProperDatabase)}")  # True
```

### 1.5 标准库装饰器——Python 工具箱

#### 1.5.1 `@property`——描述符实现的属性访问拦截

`@property` 不是普通的装饰器,而是**描述符**的语法糖:

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius
    
    @property
    def radius(self):
        """Getter"""
        print(">>> radius getter")
        return self._radius
    
    @radius.setter
    def radius(self, value):
        """Setter"""
        print(f">>> radius setter: {value}")
        if value < 0:
            raise ValueError("半径必须为正")
        self._radius = value
    
    @radius.deleter
    def radius(self):
        """Deleter"""
        print(">>> radius deleter")
        del self._radius
    
    @property
    def area(self):
        """只读属性"""
        return 3.14159 * self._radius ** 2

c = Circle(5)
print(f"半径: {c.radius}")    # 触发 getter
c.radius = 10                  # 触发 setter
print(f"面积: {c.area}")       # 只读,无 setter
```

**property 的本质**:

```python
# property 是一个类
print(type(Circle.radius))  # <class 'property'>

# property 实例存储了 fget/fset/fdel
print(Circle.radius.fget)   # getter 函数
print(Circle.radius.fset)   # setter 函数
```

#### 1.5.2 `@functools.lru_cache`——记忆化装饰器

```python
import functools

@functools.lru_cache(maxsize=128, typed=False)
def fibonacci(n):
    """缓存计算的斐波那契数"""
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

# 第一次计算
print(f"fib(30) = {fibonacci(30)}")

# 查看缓存信息
print(fibonacci.cache_info())
# 输出: CacheInfo(hits=28, misses=31, maxsize=128, currsize=31)

# 清空缓存
fibonacci.cache_clear()
```

**lru_cache 的实现原理**:

```python
def lru_cache_manual(maxsize=128):
    """手动实现 LRU 缓存装饰器"""
    def decorator(func):
        cache = {}  # 缓存字典
        order = []  # 访问顺序(LRU 队列)
        
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            # 创建缓存键
            key = (args, frozenset(kwargs.items()))
            
            if key in cache:
                # 缓存命中
                order.remove(key)
                order.append(key)  # 移到最后(最近使用)
                return cache[key]
            
            # 缓存未命中
            result = func(*args, **kwargs)
            cache[key] = result
            order.append(key)
            
            # 超过 maxsize,移除最久未使用
            if len(cache) > maxsize:
                old_key = order.pop(0)
                del cache[old_key]
            
            return result
        
        # 添加缓存管理方法
        wrapper.cache_info = lambda: f"size={len(cache)}/{maxsize}"
        wrapper.cache_clear = lambda: (cache.clear(), order.clear())
        
        return wrapper
    
    return decorator
```

#### 1.5.4 `@dataclasses.dataclass`——自动生成特殊方法

```python
from dataclasses import dataclass, field
from typing import List

@dataclass
class Person:
    name: str
    age: int
    email: str = "unknown@example.com"  # 默认值
    tags: List[str] = field(default_factory=list)  # 可变默认值
    _internal: int = field(repr=False, compare=False, default=0)  # 内部字段
    
    def __post_init__(self):
        """初始化后钩子"""

            raise ValueError("年龄不能为负")
```

| 方法 | 生成条件 |

#### 1.5.5 `@contextlib.contextmanager`——生成器变上下文管理器

```python
from contextlib import contextmanager

@contextmanager
def timer(name):
    """计时上下文管理器"""
    import time
    start = time.perf_counter()
    print(f"[{name}] 开始...")
    
    try:
        yield  # 控制权交给 with 块
    finally:
        end = time.perf_counter()
        print(f"[{name}] 完成,耗时 {(end - start) * 1000:.2f} ms")

with timer("数据处理"):
    import time
    time.sleep(0.1)
    print("处理中...")

# 带异常处理的上下文管理器
@contextmanager
def database_transaction(conn):
    """数据库事务管理器"""
    try:
        yield conn
        conn.commit()
        print("事务提交")
    except Exception as e:
        conn.rollback()
        print(f"事务回滚: {e}")
        raise

# 模拟数据库连接
class MockConnection:
    def commit(self): print("Mock: commit")
    def rollback(self): print("Mock: rollback")

with database_transaction(MockConnection()) as conn:
    print("执行 SQL...")
    # raise Exception("SQL 错误")  # 取消注释测试回滚
```

## 二、注解与类型提示——`__annotations__`的运行时真相

### 2.1 `__annotations__`字典——运行时存储,零强制

类型注解的核心机制极其简单:**存储在函数对象的一个字典中,运行时完全忽略**。

```python
def func(x: int, y: str = "default", *args: float, z: bool = True, **kwargs: complex) -> list:
    """带有完整类型注解的函数"""
    return [x, y, args, z, kwargs]

# 查看 __annotations__ 字典
print("=== __annotations__ 字典 ===")
for key, value in func.__annotations__.items():
    print(f"{key}: {value}")

print("\n=== 其他属性 ===")
print(f"位置参数默认值: {func.__defaults__}")
print(f"关键字参数默认值: {func.__kwdefaults__}")
```

**输出**:

```
=== __annotations__ 字典 ===
x: <class 'int'>
y: <class 'str'>
args: <class 'float'>
z: <class 'bool'>
kwargs: <class 'complex'>
return: <class 'list'>

其他属性 ===
位置参数默认值: ('default',)
关键字参数默认值: {'z': True}
```

**`__annotations__` 字典的结构**:

```
__annotations__ = {
    '参数名': 类型对象,        # 位置参数
    '*args名': 类型对象,        # 可变位置参数
    '**kwargs名': 类型对象,     # 可变关键字参数
    'return': 返回类型          # 返回值类型
}
```

**关键点**:

1. **类型对象是运行时的真实对象**——`int`、`str` 是类对象,不是字符串(除非 PEP 563 延迟求值)
2. **Python 运行时不强制类型**——调用 `func("not int", 123)` 不会报错
3. **类型注解不影响性能**——只是一个字典,零运行时开销

**实验 3:证明运行时不强制类型**:

```python
def strict_add(a: int, b: int) -> int:
    """类型注解提示这是一个整数加法"""
    return a + b

# 调用时不匹配类型,Python 不报错
result1 = strict_add(1, 2)  # 正常
result2 = strict_add("hello", " world")  # 不报错!
result3 = strict_add([1, 2], [3, 4])  # 不报错!

print(f"int: {result1}, str: {result2}, list: {result3}")
# 输出: int: 3, str: hello world, list: [1, 2, 3, 4]
```
