## 一、C结构体速览
通过学习对象模型的前置知识，我们逐步理解对象模型。不懂C也没关系，刚开始你只需要记住`PyObject`即可，其余的在脑海里有个大概印象即可。

### PyObject，对象模型的起点
Python中创建一个对象，无论是在字面量中写 `42`，还是调用 `int(42)`，亦或是 `class Foo: pass` 产生一个类对象——CPython都在堆上分配一块内存，强制其开头永远是同一个头部结构：
```
typedef struct _object {
    Py_ssize_t ob_refcnt;      // 引用计数 → 决定对象生命周期
    PyTypeObject *ob_type;     // 类型指针 → 决定对象行为
} PyObject;                    // 16B (64位)
```
Python统一对象的根因就是`PyObject`。结构决定其功能，ob_refcnt给予了任何对象天生自带计数器的特性，赋值、函数传参等本质都是操作其对象的ob_refcnt; 
ob_type固定存在,永远指向一个具体的PyTypeObject。"解释型、动态类型、强类型"等语言特性和ob_type紧密相关，比如强类型(禁止隐式跨类型转换)：
ob_type指向的`PyTypeObject`严格定义了操作槽位。`"3" + 4`运行时`str.__add__`发现右操作数的ob_type不是str，返回PyNotImplemented，最终抛出TypeError, Python选择让PyTypeObject的槽位严格匹配，不做隐式跨类型转换。这和同为强类型的语言JAVA在实现机制上有本质区别，这就牵扯出"动态类型"的概念，第三节展开。

我前面说"**理解Python对象模型是读懂Python一切行为的起点**"，拒绝喊口号。试着用`PyObject`来回答几个看似不相关的问题：
1. 为什么数字、字符串、函数都可以查类型 --> ob_type固定存在,永远指向一个具体的PyTypeObject
2. 为什么Python中没有泛型但List能混存数字、字符串、函数、实例 --> 统一封装成`PyObject`, 容器只存指针。"看，这就是统一的魅力"
3. 为什么Python是基于C实现却不需要手动释放内存 --> ob_refcnt给予了任何对象天生自带计数器的特性，支撑统一逻辑释放

然后我们再从其副作用的角度来看看有什么问题：
1. 从内存角度解释一下为什么Python比其他同类语言效率低 --> 任何对象都被强制挂载`PyObject`(16B), 任何对象至少占用16B内存(比如`None`)。

### PyVarObject，变长对象的基结构
在Python中`PyObject`是一切对象在C层面的内存布局起点，但它只能表示固定大小的对象。对于元素数量不定的容器（如列表、字符串、元组），内存大小随元素变化，`PyObject`无法表达。同时"Python一切皆对象"，类型本身也需要被表示为对象。

为了解决上述两个问题，C层面需要有支持变长对象和支持表示类型对象的结构体：
```
// CPython Include/object.h
typedef struct _varobject {
    PyObject ob_base;           // 继承 PyObject (16B)
    Py_ssize_t ob_size;        // 元素数量 (非字节数!)
} PyVarObject;                  // 24B
```

**ob_size的含义因类型而异：**
| 类型 | ob_size含义 | 示例 |
|------|-------------|------|
| `list` | 列表元素个数 | `[1,2,3] → ob_size=3` |
| `str` | 字符数（UTF-8码点数） | `"abc" → ob_size=3` |
| `tuple` | 元组元素个数 | `(1,2) → ob_size=2` |
| `int` | digit数组长度（含符号） | `-100 → ob_size=-2` |

**对应Python对象对比：**
```python
# 定长对象（继承PyObject）
int, float, complex, NoneType, bool  # 大小固定

# 变长对象（继承PyVarObject）
list, str, tuple, bytes, bytearray   # ob_size决定实际大小
dict, set, frozenset                 # ob_size表示元素个数
```

**注意**：变长≠可变！`str`和`tuple`是变长对象但不可变，`list`是变长对象且可变。这是两个独立维度：
- **定长/变长**：结构层面，`ob_size`是否参与内存分配
- **可变/不可变**：语义层面，创建后内容能否原地修改

### PyTypeObject，类型对象
"Python一切皆对象"，类型本身也是对象。每个类型（如`int`、`list`、自定义类）在C层面都是`PyTypeObject`实例：
```
// CPython Include/cpython/object.h (简化版)
typedef struct _typeobject {
    PyObject_VAR_HEAD                        // 24B: refcnt + type + size

    const char *tp_name;                     // 类型名，如 "int"
    Py_ssize_t tp_basicsize;                 // 实例的基本大小(字节)
    Py_ssize_t tp_itemsize;                  // 每个元素的额外大小(变长对象)

    destructor tp_dealloc;                   // 析构函数, 引用计数归零时触发释放

    PyNumberMethods *tp_as_number;           // 数值协议子结构 ★
    PySequenceMethods *tp_as_sequence;       // 序列协议子结构 ★
    PyMappingMethods *tp_as_mapping;         // 映射协议子结构 ★

    hashfunc tp_hash;                        // __hash__
    ternaryfunc tp_call;                     // __call__
    reprfunc tp_str;                         // __str__
    getattrofunc tp_getattro;                // __getattribute__
    setattrofunc tp_setattro;                // __setattr__

    PyObject *tp_bases;                      // 基类元组
    PyObject *tp_mro;                        // MRO 元组 (C3 线性化结果)
    PyObject *tp_dict;                       // 类的 __dict__

    Py_ssize_t tp_dictoffset;                // 实例 __dict__ 在实例中的偏移
    initproc tp_init;                        // __init__
    allocfunc tp_alloc;                      // 内存分配器
    newfunc tp_new;                          // __new__
    freefunc tp_free;                        // 内存释放器

    PyObject *tp_subclasses;                 // 子类弱引用列表
    // ... 更多字段
} PyTypeObject;
```

**关键理解：**
1. **类型实例的ob_type指向谁？** → `PyType_Type`（类型的类型，即`type`对象）
2. **type对象的ob_type指向谁？** → 自己（`type`是自己的类型，这是Python元模型的基石）
3. **所有类型的ob_type都指向PyTypeObject实例** → 这就是"一切皆对象"在C层面的实现

### 协议方法表（Protocol Method Tables）
`PyTypeObject`中的三个指针指向协议方法表，定义对象支持的操作：
```
// 数值协议 (支持 +、-、*、/ 等)
typedef struct {
    binaryfunc nb_add;           // __add__
    binaryfunc nb_subtract;      // __sub__
    binaryfunc nb_multiply;      // __mul__
    binaryfunc nb_true_divide;   // __truediv__
    // ... 更多数值操作
} PyNumberMethods;

// 序列协议 (支持 []、len、in 等)
typedef struct {
    lenfunc sq_length;           // __len__
    ssizeargfunc sq_item;        // __getitem__
    ssizeobjargproc sq_ass_item; // __setitem__
    // ... 更多序列操作
} PySequenceMethods;

// 映射协议 (支持键值访问)
typedef struct {
    lenfunc mp_length;           // __len__
    binaryfunc mp_subscript;     // __getitem__
    objobjargproc mp_ass_sub;    // __setitem__
    // ... 更多映射操作
} PyMappingMethods;
```

**核心概念：槽位（Slot）**
这些结构体中的每个函数指针字段称为**槽位**：
- **是什么**：函数指针，指向实现具体操作的C函数
- **在哪里**：定义在`PyTypeObject`或协议方法表中
- **影响什么**：决定对象支持哪些操作，以及操作的行为

**示例：list的赋值实现**
```c
// list类型定义 (Objects/listobject.c)
PyTypeObject PyList_Type = {
    // ...
    &list_as_sequence,        // tp_as_sequence槽位
    // ...
};

// 序列方法表
static PySequenceMethods list_as_sequence = {
    // ...
    list_ass_item,            // sq_ass_item槽位 → 赋值函数
    // ...
};

// 赋值函数实现
static int list_ass_item(PyListObject *a, Py_ssize_t i, PyObject *v) {
    // lst[i] = v 的底层实现
    Py_SETREF(a->ob_item[i], v);
    return 0;
}
```

**调用链路：**
```
Python代码: lst[i] = val
    ↓
PyObject_SetItem(lst, i, val)
    ↓
lst->ob_type->tp_as_sequence->sq_ass_item(lst, i, val)
    ↓
list_ass_item函数执行
```

### 五类结构体关系图
```
PyObject (16B)                    所有对象的起步
    ↓ 继承
PyVarObject (24B)                 变长对象基结构
    ↓ 继承
PyTypeObject                      类型对象（也是变长对象）
    ↓ 包含指针
PyNumberMethods                   数值协议方法表
PySequenceMethods                 序列协议方法表
PyMappingMethods                  映射协议方法表
```

**设计精髓：**
1. **数据实例**（`PyObject`/`PyVarObject`）：存储数据，共享行为
2. **类型对象**（`PyTypeObject`）：存储行为定义，所有实例共享
3. **协议方法表**：将操作分类组织，实现多态

这种设计让Python实现了：
- **统一性**：所有对象都以`PyObject`开头，操作统一为指针解引用
- **多态性**：不同类型只需填充不同槽位函数，接口统一实现各异
- **可扩展性**：新类型只需定义新`PyTypeObject`实例并填充槽位

## 二、对象生命周期
### 2.1 创建对象

Python的对象的创建有两条路径：888、'888'、[8,8,8]，这是字面量的创建方式；int(888)、str(888)、list([8,8,8]),这是显示创建。区别在于是否经过 `type.__call__`分派。字面量直接调用C构造函数（PyLong_FromLong），显式调用走 type.__call__ → tp_new → tp_init 三步。
后者多一层函数调用开销，但行为完全一致——最终都分配内存、写入 PyObject 头部（ob_refcnt + ob_type）。
这一小节我们回答一个问题：拿到一个对象后，怎么从 ob_type 出发，推导它能做什么、不能做什么？
