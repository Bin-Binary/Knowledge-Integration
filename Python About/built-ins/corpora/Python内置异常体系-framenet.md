## 原文和翻译
> 来源：Python 3.14 官方文档 builtins/exceptions.txt

1.
> Original: In Python, all exceptions must be instances of a class that derives from "BaseException". In a "try" statement with an "except" clause that mentions a particular class, that clause also handles any exception classes derived from that class (but not exception classes from which *it* is derived). Two exception classes that are not related via subclassing are never equivalent, even if they have the same name.
> 翻译：在Python中，所有异常都必须是派生自"BaseException"的类的实例。在带有"except"子句的"try"语句中，如果该子句提到了某个特定类，则该子句也会处理从该类派生的任何异常类（但不处理它本身从中派生的异常类）。两个不通过子类化关联的异常类永远不会等价，即使它们具有相同的名称。

2.
> Original: The built-in exceptions listed in this chapter can be generated by the interpreter or built-in functions. Except where mentioned, they have an "associated value" indicating the detailed cause of the error. This may be a string or a tuple of several items of information (e.g., an error code and a string explaining the code). The associated value is usually passed as arguments to the exception class's constructor.
> 翻译：本章列出的内置异常可以由解释器或内置函数生成。除另有说明外，它们都有一个"关联值"来指示错误的详细原因。这可以是一个字符串或包含若干信息项的元组（例如，错误代码和解释该代码的字符串）。关联值通常作为参数传递给异常类的构造函数。

> 翻译：用户代码可以引发内置异常。这可用于测试异常处理器或报告"就像"解释器引发相同异常时的错误条件；但请注意，没有任何东西可以阻止用户代码引发不适当的错误。

> 翻译：内置异常类可以被子类化以定义新的异常；鼓励程序员从"Exception"类或其子类派生新异常，而不是从"BaseException"派生。有关定义异常的更多信息，请参阅Python教程中的"用户自定义异常"。

5.
> Original: Three attributes on exception objects provide information about the context in which the exception was raised: BaseException.__context__, BaseException.__cause__, BaseException.__suppress_context__. When raising a new exception while another exception is already being handled, the new exception's "__context__" attribute is automatically set to the handled exception. ... The expression following "from" must be an exception or "None". It will be set as "__cause__" on the raised exception. Setting "__cause__" also implicitly sets the "__suppress_context__" attribute to "True", so that using "raise new_exc from None" effectively replaces the old exception with the new one for display purposes, while leaving the old exception available in "__context__" for introspection when debugging.
> 翻译：异常对象上的三个属性提供关于异常引发上下文的信息：BaseException.__context__、BaseException.__cause__、BaseException.__suppress_context__。当在另一个异常已被处理时引发新异常，新异常的"__context__"属性会自动设置为被处理的异常。……"from"后面的表达式必须是异常或"None"。它将被设置为被引发异常的"__cause__"。设置"__cause__"也会隐式将"__suppress_context__"属性设置为"True"，因此使用"raise new_exc from None"会有效地用新异常替换旧异常（用于显示目的），同时在"__context__"中保留旧异常以便调试时内省。

> 翻译：用户代码可以创建从异常类型继承的子类。建议一次只子类化一个异常类型，以避免基类处理"args"属性时可能出现的冲突，以及由于可能的内存布局不兼容性。**CPython实现细节：**大多数内置异常为效率用C实现，部分有自定义内存布局，使得无法创建继承多个异常类型的子类。

## 事实
> 全部从 Python 3.14 官方文档 builtins/exceptions.txt 提取的客观事实，作为框架FE的填充值，属于分析中间产物

1. 所有异常必须是派生自BaseException的类的实例（←片段1）
2. except子句捕获指定类时，也自动捕获其派生类（←片段1）
3. 不通过子类化关联的异常类即使同名也不等价（←片段1）
4. 内置异常可由解释器或内置函数生成（←片段2）
5. 内置异常通常有关联值来指示错误详细原因，关联值通过构造函数参数传递（←片段2）
6. 用户代码可以引发内置异常，但可能引发不适当的错误（←片段3）
7. 内置异常类可被子类化；鼓励从Exception而非BaseException派生新异常（←片段4）
8. 异常上下文由三个属性提供：__context__、__cause__、__suppress_context__（←片段5）
9. 处理一个异常时引发新异常，新异常的__context__自动设置为被处理异常（←片段5）
10. "raise new_exc from original_exc"设置__cause__和__suppress_context__为True（←片段5）
11. "raise new_exc from None"用新异常替换旧异常显示，但旧异常保留在__context__中（←片段5）
12. 建议一次只子类化一个异常类型，因args处理冲突和内存布局不兼容（←片段6）
13. CPython中大多数内置异常用C实现，部分有自定义内存布局（←片段6）
14. BaseException是所有内置异常的基类，不打算被用户类直接继承（←片段7）
15. Exception是所有内置非系统退出异常的基类，所有用户异常应派生自此（←片段8）
16. ArithmeticError是算术错误异常的基类，含OverflowError、ZeroDivisionError、FloatingPointError（←片段9）
17. BufferError在缓冲区操作无法执行时引发（←片段10）
18. LookupError是键/索引无效异常的基类，含IndexError、KeyError（←片段11）
19. AssertionError在assert语句失败时引发（←片段12）
20. AttributeError在属性引用或赋值失败时引发；对象不支持属性时引发TypeError（←片段13）
21. EOFError在input()遇到EOF且未读数据时引发（←片段14）
22. FloatingPointError当前未使用（←片段15）
23. GeneratorExit在生成器或协程关闭时引发，继承BaseException而非Exception（←片段16）
24. ImportError在import语句加载模块出问题时引发（←片段17）
25. ModuleNotFoundError是ImportError子类，模块无法定位时引发（←片段18）
26. IndexError在序列下标超出范围时引发（←片段19）
27. KeyError在字典键未找到时引发（←片段20）

## 误解
> 从原始语料推导的学习者**潜在错误理解**，属于分析中间产物

1. 认为"所有异常都是Exception的子类"——实际KeyboardInterrupt、SystemExit、GeneratorExit直接继承BaseException（←片段21/37/16诱导）
2. 认为"except Exception可以捕获所有异常"——实际无法捕获BaseException的直接子类如KeyboardInterrupt（←片段8诱导，因强调"所有内置非系统退出异常"）
3. 将NotImplementedError与NotImplemented常量混淆——两者不可互换（←片段24中名称相似性诱导）
4. 认为"OSError仅表示文件系统错误"——实际涵盖所有系统相关错误包括网络、进程等（←片段25中"file not found"举例诱导）
5. 认为整数运算永远不会引发OverflowError——实际"由于历史原因，整数超出所需范围时有时也会引发"（←片段26第一句"cannot occur for integers"诱导）
6. 认为生成器中可以安全地raise StopIteration——实际在生成器中直接/间接引发StopIteration会被转换为RuntimeError（←片段31中StopIteration定义诱导）
7. 认为ExceptionGroup可以包含BaseException子类——实际ExceptionGroup只能包装Exception子类（←片段45中"exception group"名称诱导）
8. 认为"raise ... from None"完全删除了旧异常——实际旧异常仍保留在__context__中（←片段5"replaces"一词诱导）
9. 认为"自定义异常可以多重继承多个内置异常类"——实际因内存布局不兼容可能无法实现（←片段6/4"可以子类化"表述诱导）
10. 认为Warning与普通异常在处理机制上完全不同——实际Warning也是Exception的子类，可以用except捕获（←片段44"warning categories"概念诱导）
