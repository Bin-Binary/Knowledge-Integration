# overview.md 生成器

## 概述

基于视图模板体系生成 overview.md 全局视图文档。核心原则：

1. **意图优先**：先澄清用户想观察什么，x/y 轴决定观察角度，不同轴组合 = 不同视图类型
2. **对象&职责是前提**：对象及其职责是全局视图质量的前提，必须根据 x/y 深度挖掘
3. **禁止幻觉**：每一个对象必须有可追溯来源（文件路径 / 文档引用 / 已有产物），无法追溯的对象必须询问用户，禁止自行猜测
4. **逐步思考**：严格按工作流推进，每步确认后再进入下一步

## 资源路径

本技能内置模板位于当前 skill 目录下的 `resources/templates/`。**模板发现按以下优先级：**

| 优先级 | 路径 | 说明 |
|--------|------|------|
| 1（高） | `<project_root>/tmplate/` | 项目自定义模板，覆盖内置同名模板 |
| 2（低） | `<skill_dir>/resources/templates/` | 内置模板，作为兜底 |

读取模板时优先使用项目路径，不存在则回退到内置路径。

## 适用场景

**何时使用：** 用户说"生成overview""写全局视图""生成总览文档""做overview""给xxx做个总览"等需要产出全局视图文档的需求。

**不适用：** 术语速查表（用 terminology-quick-ref 模板）、README、详细设计文档、单点问题排查。

## 核心工作流

> **思维链模式**：在每一步执行前，必须先进行逐步推理并在 thinking 中输出：
> 1. 当前步骤目标是什么？
> 2. 有哪些前置条件需要验证？
> 3. 可能的歧义点是什么？是否需要与用户澄清？
> 4. 输出内容是否与 x/y 轴语义一致？
> 5. 自检：每个对象是否有可追溯来源？是否有幻觉风险？

### 步骤 1：用户意图澄清 & 视图类型选择（必须先做）

**目的：** 确定观察角度。x/y 轴决定观察视角，不同轴组合 = 不同视图类型，直接决定全局视图的形态与深度。

**必须向用户提出澄清问题，给出建议并引导选择，禁止跳过：**

澄清问题示例：
1. **观察对象**：你想观察什么？(一个系统 / 一个模块 / 一条链路 / 一个领域)
2. **认知目标**：你想从这个全局视图中获得什么？(理解整体结构 / 看清生命周期 / 理清请求流转 / 看清分层职责)
3. **覆盖范围**：边界在哪里？(单模块 / 多模块 / 整个领域)
4. **坐标轴**：如果用二维坐标系，你希望 x 轴和 y 轴各代表什么？
5. **"层级/结构"语义**：y 轴的"层级"你理解为什么？(物理架构分层 / 逻辑概念层级 / 创建过程快照 / 包含嵌套层级) —— 同一组坐标可能被不同用户理解为不同语义，必须明确澄清

**展示可用视图类型**，格式如下：

```
发现 N 种视图类型：

1. 2D-CCS 坐标系 — x=生命周期/阶段, y=物理结构/层级. "谁在某时某地干了某事"
2. 分层架构视图 — 展示架构分层，每层职责与产物
3. 请求链路视图 — 请求经过的组件链，每跳职责与故障行为
4. 流程阶段视图 — 处理流程的阶段序列，每阶段主调/产出/验收
5. 层次结构视图 — 资源/对象的嵌套层级，容量/带宽等关键属性

请选择视图类型，或描述你的自定义观察角度。
```

**关键规则：**
- 客观列举所有可用类型，根据用户的认知目标给出建议（如"想同时看结构和生命周期 → 建议 2D-CCS"）
- 用户描述与现有类型都不匹配时，主动建议自定义 x/y 轴
- 用户意图模糊时，必须追问，禁止假设
- **"层级/结构"语义歧义是高危区**：同一组坐标名可被不同用户理解为物理实体、逻辑概念层级、或创建过程快照；必须追问明确真实意图后再设定 y 轴标注方式

### 步骤 2：明确坐标轴语义

根据所选类型，明确观察维度的具体含义：

**2D-CCS 坐标系：**
- x 轴 = 生命周期 / 阶段
- y 轴 = 物理结构 / 层级
- 坐标描述公式："谁在某时某地干了某事"
- **"物理结构"精确定义**：指真实存在的物理硬件实体——如CPU 执行单元/寄存器、缓存(SRAM L1/L2/L3)、主存(DRAM 内存条)、存储(SSD/HDD)等硬件组件。为展示内存管理语义，可辅以虚拟内存分区（代码段/堆/栈）作为 y 轴主标签，并标注其到硬件的映射路径（如"栈 → DRAM栈区 + Cache + CPU 寄存器"）。核心原则：每个虚拟分区必须对应到具体硬件，不能停留在 OS 抽象层。

**其他类型：** 明确对应的观察维度（分层 / 链路跳数 / 阶段顺序 / 包含关系）。

必须向用户确认坐标轴语义，避免歧义。记录下来，后续挖掘以该语义为基准。

### 步骤 3：确定覆盖范围

- 明确视图覆盖的系统/模块边界（目录、文档、代码范围）
- 明确需要挖掘的深度（到组件 / 到文件 / 到类）
- 记录来源清单，作为挖掘和追溯的依据

### 步骤 4：深度挖掘对象 & 职责（核心步骤）

**前提：** 对象和其职责是决定全局视图质量的前提条件，必须根据 x/y 深度挖掘。

**挖掘方法：**
1. 遍历覆盖范围内的实际材料（禁止凭记忆或常识编写）：
   - 文档目录（README、docs/、各模块 .md）
   - 已有产物（已存在的 overview-graph.md、SVG 图表、terminology-quick-reference.md）
   - 代码结构（目录划分、类/组件定义、API 定义）
2. 按 x/y 坐标定位对象：
   - 对每个 y 轴结构位置，找到"对象是谁"（有真实来源）
   - 对每个 x 轴阶段，找到"对象何时参与"
   - 交叉点即职责：该对象在该阶段承担的职责
3. 为每个对象记录**来源**：文件路径 + 关键行号，或文档引用
4. 可使用 task 代理并行探索不同子目录，加快挖掘

**禁止行为：**
- 禁止凭 LLM 先验知识补充对象
- 禁止用"通用架构常识"填充职责
- 对象必须来自覆盖范围内可验证的材料

### 步骤 5：来源可追溯性验证（反幻觉闸门）

建立"对象-来源"映射表，逐项核对：

| 对象 | 职责 | 来源（文件:行号 / 文档引用） | 状态 |
|------|------|------------------------------|------|
| HAProxy | VIP 入口，leastconn 选节点 | AI-about/ai-infra/platform/overview-graph.md:12 | ✅ |
| xxx | yyy | — | ❌ 待确认 |

- ✅ 有明确来源 → 保留
- ❌ 无来源 → **标记"待确认"，必须询问用户**，禁止自行补充
- 来源矛盾（不同材料职责描述冲突）→ 与用户核对，以最新/权威材料为准
- 验证通过后，向用户汇报挖掘结果与来源清单，用户确认后再进入下一步

### 步骤 6：生成 overview.md

基于所选视图类型对应的模板（步骤 5 验证通过的对象&职责），生成 overview.md：

1. 读取模板：优先 `<project_root>/tmplate/{类型}-overview-template.md`，回退内置模板
2. 填充：
   - 标题（xxx全局视图）
   - 一句话概述（来自步骤 1 的认知目标）
   - 视图引用（SVG 或 ASCII 图，路径需根据输出位置计算相对路径）
   - 对象 & 职责表（步骤 5 验证过的内容）
3. 若对象&职责表数据量适合表格则用表格，否则按类型选择合适表达（链路表 / 指标表等）

### 步骤 7：输出前确认 & 写入

- 展示生成的 overview 完整内容、输出路径、关键决策摘要
- **等待用户明确确认后**才写入文件
- 默认输出：`<项目根>/<领域目录>/overview.md`（或用户指定路径）
- 写入后告知用户完整路径
- 同步检查 `<项目根>/<领域目录>/svg/` 目录下是否存在配套 SVG，若 overview 引用了 SVG 则相应更新引用路径

### 文档结构强制要求

1. **一级标题**必须包含视图名称 + "全局视图"，示例：`# xxx全局视图：视角A、视角B × 生命周期`
2. **必须包含 `## 概述` 节**：一段话总结观察对象、x/y 轴语义、覆盖范围，以及各读法对应的 SVG 引用
3. **多视角支持**：若用户选择多个观察角度（如读法 A / 读法 B），每种视角对应一个独立 SVG 视图文件，在概述中列出视角对照表。当两个视角的 y 轴语义不同时，其 y 轴坐标对象完全不同，SVG 必须独立绘制，数据和标注均不可共用

## 扩展指南

### 新增视图类型模板

在 `<project_root>/tmplate/` 下添加 `{类型}-overview-template.md`，定义新的 overview 文档模板。若需内置兜底，在 `<skill_dir>/resources/templates/` 下同步一份，并更新本文件「内置视图类型速查」表格。

## 常见错误

| 错误 | 根因 | 纠正 |
|---------|------|-----|
| 跳过意图澄清直接生成 | 认为"用户已经说了要做什么" | 必须澄清观察角度，x/y 决定视图形态 |
| 对象无来源（幻觉） | 凭 LLM 先验知识补充对象 | 每个对象必须有文件/文档可追溯来源 |
| 对象与坐标轴无关 | 未按 x/y 深度挖掘 | 只保留该坐标下真实存在的对象 |
| 职责来自通用常识 | 用"架构惯例"填充 | 职责必须来自可验证材料的实际描述 |
| 生成后不经确认直接写入 | 流程遗漏 | 必须等用户明确确认后才写入 |

## 红旗警告

- 🚩 用户想跳过意图澄清直接生成 → **禁止**，必须先澄清视图类型与 x/y 轴语义
- 🚩 对象无法追溯来源 → **STOP**，标记"待确认"，询问用户
- 🚩 x/y 轴含义不明确 → **STOP**，先确认坐标语义再挖掘
- 🚩 材料不足无法挖掘对象 → **STOP**，告知用户材料缺口，请求补充
