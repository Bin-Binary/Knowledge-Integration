# SVG 图表生成器

## 概述

基于内置模板体系生成 SVG 技术图表。支持多风格选择，风格可独立扩展；输出前需用户确认；产物输出到当前领域目录的 `svg/` 下。

## 资源路径

本技能内置模板位于当前 skill 目录下的 `resources/templates/svg/`。**风格发现按以下优先级：**

| 优先级 | 路径 | 说明 |
|--------|------|------|
| 1（高） | `<project_root>/tmplate/svg/style/` | 项目自定义风格，覆盖内置同名风格 |
| 2（低） | `<skill_dir>/resources/templates/svg/style/` | 内置风格，作为兜底 |

读取资源时优先使用项目路径，不存在则回退到内置路径。

## 适用场景

**何时使用：** 用户说"画个 SVG""生成架构图""做一张映射图""画个示意图""画个数据流图"等需要产出 SVG 图表的需求。

**不适用：** 流程图（用 Mermaid）、思维导图、非技术图表、需要交互的网页图形。

## 核心工作流

> **思维链模式**：生成任何 SVG 之前，必须先进行逐步推理并在 thinking 中输出：
> 1. 布局计算：x/y 坐标规划、网格对齐验证
> 2. 间距检查：所有元素间距 ≥ 20px，禁止边框/线条/文字任意两两重叠
> 3. 色彩验证：不使用 opacity，颜色直接取色值
> 4. 字体检查：中文文本必须有中文字体回退
> 5. 自检：逐项核对设计红线清单，确认无违规后输出

### 步骤 1：扫描可用风格

同时扫描以下两个路径的风格目录：
- `<project_root>/tmplate/svg/style/` 下的子目录
- `<skill_dir>/resources/templates/svg/style/` 下的子目录

风格名冲突时，项目路径覆盖内置路径。每个子目录为一个风格。

对每个风格，检查是否存在：
- `background template.svg` — 空白底图模板
- `pretty design.md` — 风格设计规范
- `Excellent Example/` — 优秀示例目录

将可用风格整理为列表，包含：

| 字段 | 来源 |
|------|------|
| 风格名 | 子目录名 |
| 来源 | 项目自定义 / 内置 |
| 画布尺寸 | 从 `background template.svg` 的 `width/height` 属性提取 |
| 底色 | 从 `<rect>` 的 `fill` 提取 |
| 示例数量 | `Excellent Example/` 下 `*.svg` 文件数 |
| 示例列表 | 文件名及图表类型 |
| 设计说明 | `pretty design.md` 关键要点摘要 |

### 步骤 2：列出风格供用户选择

将扫描结果展示给用户，格式如下：

```
发现 N 种可用风格：

1. {风格名} [内置] — {底色}背景, {画布尺寸} 画布, {示例数量} 个参考示例
2. ...

请选择风格，或输入"AI设计"让 AI 设计新风格。
```

**关键规则：**
- 风格名仅为代号（如 "linglong"），使用时应客观列举所有可用风格，不推荐特定风格
- 当用户描述的需求与任何现有风格都不匹配时，主动建议选择 "AI设计" 选项
- "AI设计" 表示：AI 从现有示例中提取通用法则，结合用户需求自主设计配色、字体、布局方案。AI设计的风格应直接嵌入生成的 SVG 中

### 步骤 3：收集内容需求

选定风格后，向用户确认以下信息：

1. **图表类型**：架构图 / 数据流图 / 映射图 / 坐标系矩阵图 / 自定义
2. **图表标题**：主标题、副标题
3. **核心内容**：用户描述实体、关系、层次等
4. **特殊要求**：配色偏好、文字方向、是否添加图例等

### 步骤 4：参考示例

若选用现有风格，必须 **读取该风格 `Excellent Example/` 下全部示例 SVG**，学习其：
- 布局模式（左右栏、上下分层、矩阵网格）
- 配色方案（语义色彩、标签色、连接线色）
- 线条样式（箭头定义、虚线参数、路径命令）
- 字体与排版（字号层次、对齐方式、中文回退字体）
- **图例设计**：图例是详细信息的唯一存放区，需为每层/每种颜色提供完整的行为描述（各生命阶段职责的链式说明）

读取步骤：
1. 优先读取 `<project_root>/tmplate/svg/style/{风格名}/` 下的文件
2. 项目路径不存在则读取 `<skill_dir>/resources/templates/svg/style/{风格名}/`

同时必须读取 `pretty design.md`，严格遵守设计红线。

### 步骤 5：生成 SVG

基于选定的模板（或 AI 设计的新模板）和用户需求，生成 SVG。

**强制规范：**
1. **圆点优先**：矩阵/坐标系视图优先使用有色圆点（`<circle>`）标记数据点，仅在圆点旁保留 2-6 字符的关键词标签；所有详细描述必须移至底部图例区域，禁止在矩阵单元格内堆放多行文字
2. **y 轴语义决定 SVG 内容**：不同 y 轴语义（物理实体 vs 逻辑层级 vs 过程快照）必须使用独立 SVG、独立数据点和独立图例，不可混用
3. 所有 CSS 样式必须 inline，不得使用 `<style>` 块或外部样式表
4. 不得使用 CSS `opacity` 属性；颜色必须直接取值
5. 边框、线条、文字任意两两之间禁止重叠（设计红线）
6. 使用 `<defs>` + `<marker>` 定义箭头
7. 分组使用 `<g id="main-drawing">` 和 `<g id="annotations">`
8. 中文文本需添加中文回退字体（如 `font-family="sans-serif"` 或 `"Microsoft YaHei","SimHei",sans-serif"`）
9. 标注引线使用 `stroke-dasharray="6 4"`、`stroke="#555555"`、`stroke-width="1"`

### 步骤 6：输出前确认

生成 SVG 后，告知用户：
- 输出文件路径：`<project_root>/<领域>/svg/<filename>.svg`（当前工作目录为领域根时，则为 `<project_root>/svg/<filename>.svg`）
- 文件大小（预估行数）
- 关键设计决策摘要

**等待用户明确确认后**，才执行文件写入。若用户要求修改，返回步骤 5 调整后重新确认。

### 步骤 7：写入文件

用户确认后，将 SVG 写入 `<project_root>/<领域>/svg/<filename>.svg`。若目标 `svg/` 目录不存在则先创建。

写入后告知用户完整路径。

## 扩展指南

### 新增风格（项目级）

在项目 `tmplate/svg/style/` 下新建目录，目录名即风格名：

```
tmplate/svg/style/{新风格名}/
├── background template.svg    # 必选：空白底图模板（含画布、背景、网格）
├── pretty design.md           # 可选：风格专属设计规范
└── Excellent Example/         # 必选：至少1个参考示例
    └── *.svg
```

`background template.svg` 必须包含：
- 固定画布尺寸（`width`/`height`/`viewBox`）
- 背景层（`<rect>` 底色 + `<g>` 网格/装饰）
- 两个预留分组：`<g id="main-drawing">` 和 `<g id="annotations">`

### 新增风格（内置级）

在 skill 目录 `resources/templates/svg/style/` 下按上述结构新建，并更新本文件「内置风格速查」表格。

### 新增参考示例

将新 SVG 放入对应风格的 `Excellent Example/` 目录即可（项目级优先于内置级）。`pretty design.md` 中应同步记录该示例的设计亮点。

### 新增图示类型模板

在 `resources/templates/svg/` 下添加 `*-SVG-design.md` 文件，定义特定图示类型（如 2D-CCS 坐标系）的 SVG 设计说明，包含坐标系含义、轴线定义、设计规则等。配套的 overview.md 文档模板不属于 SVG 技能范畴，应放置于项目 `tmplate/` 下。

## 设计红线

必须遵守 `pretty design.md`（项目级优先于内置级）中定义的所有规则。当前红线：

1. **禁止元素重叠**：边框、线条、文字任意两两之间禁止重叠
2. **禁止单元格堆文字**：矩阵/坐标系视图禁止在单元格内堆放多行描述文字，必须使用圆点+关键词，详细说明放入图例
2. **禁止 opacity**：不使用 CSS opacity/透明，颜色直接取色值
3. **禁止空标注**：`<g id="annotations">` 仅在有实际引线内容时才填入，否则保持空 `<g>`

## 常见错误

| 错误 | 根因 | 纠正 |
|---------|------|-----|
| 跳过风格扫描直接使用默认风格 | 认为"只有一个风格=不用问" | 必须扫描展示所有可用风格，即使只有一个 |
| 使用 `<style>` 块定义样式 | 忽略内联样式要求 | 所有样式用 attribute 内联书写 |
| 元素间距不足导致重叠 | 未做布局计算 | 先规划坐标网格，确保元素间最小间距 ≥ 20px |
| 颜色使用 opacity | 为方便直接用 opacity 叠加 | 取实际叠加后的颜色值直接填写 |
| 单元格内堆放多行文字 | 图省事直接在矩阵格内写详细描述 | 用圆点+关键词标记，详细描述放入图例 |
| 未读取参考示例直接生成 | 认为"已知模板长什么样" | 每次都必须读取该风格的示例和设计规范 |
| 生成后不经确认直接写入 | 流程遗漏 | 必须等用户明确确认后才写入文件 |

## 红旗警告

- 🚩 用户想跳过风格选择直接生成 → **禁止**，必须展示全部可用风格
- 🚩 生成的 SVG 中元素有重叠 → **STOP**，布局计算以 120px 网格为基准对齐
- 🚩 内置 & 项目模板均不可用 → **STOP**，建议用户使用 "AI设计" 模式
- 🚩 用户要求输出到非 `svg/` 目录 → 提醒默认输出路径，用户坚持则以用户路径为准
