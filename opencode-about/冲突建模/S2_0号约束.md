# S2 0号约束 — opencode v1.15.10
# Step 3 产出：递归停止后的不可再分事实
# 来源：仅 S1 维度约束矩阵递归到底

## 递归推演

### A1(时序+实体): LLM 推理是慢速远程调用，上下文是有限资源
- **源自**: C_Phys_1 (时序鸿沟) + C_Phys_2 (上下文窗口有限)
- **递归追问**: 为什么 LLM 慢？→ 因为模型推理需要 GPU 集群运算 + 网络传输 token 流，这是物理限制，非软件可绕过。
- **递归追问**: 为什么上下文有限？→ 因为 Transformer 架构的 self-attention 计算复杂度 O(n²)，扩展窗口需要平方级资源增长，这是数学限制。
- **停止条件**: 物理极限 (计算资源) + 数学极限 (O(n²)复杂度)
- **归属维度**: 时序 + 实体
- **反证检验**: 若移除此约束 (假设 LLM 无限快且无限窗口)，还需要 Session 压缩机制吗？不需要。约束成立。

### A2(边界): LLM 与执行环境之间存在不可逾越的文本边界
- **源自**: C_Phys_4 (LLM仅输出文本) + C_Arch_1 (文本声明 vs 实际执行)
- **递归追问**: 为什么 LLM 不能直接执行代码？→ 因为 LLM 是远端推理服务，不在用户机器上运行，无法访问本地文件系统/进程——这是部署架构决定的，而非设计选择。
- **递归追问**: 为什么 tool_call 只是 JSON 声明？→ 因为 LLM API 协议的本质是文本序列到文本序列的映射——输出 JSON 声明是模型唯一的沟通手段。OpenAI/Anthropic/Google 无一例外使用此模式。
- **停止条件**: 环境约束 (模型部署在远端，非本地进程)
- **归属维度**: 边界
- **反证检验**: 若 LLM 可以直接调用本地系统调用，还需要 Tool 系统和 ToolRegistry 吗？不需要。约束成立。

### A3(边界): 工具执行具有潜在破坏性，人不能完全退场
- **源自**: C_Arch_2 (工具执行可能修改文件系统)
- **递归追问**: 为什么需要权限控制？→ 因为 shell 命令可以删除文件、git push --force 可以覆盖远程分支——工具执行的结果不可逆，这是操作系统设计决定的：文件系统操作不具有原生的撤销机制。
- **递归追问**: 为什么不能完全自动化？→ 因为 AI 可能产生幻觉或误解意图，错误的工具调用可能造成数据丢失。AI 的输出本质上是从训练分布中采样，不是确定性的正确结果。
- **停止条件**: 环境约束 (操作系统无原生撤销) + 物理极限 (AI 输出非确定性)
- **归属维度**: 边界
- **反证检验**: 若所有工具执行天然可逆 (如事务性文件系统)，还需要 Permission 体系吗？不需要。约束成立。

### A4(边界+结构): LLM 提供者生态是异构的、不可统一的
- **源自**: C_Arch_3 (不同提供者 API 协议不同) + C_Biz_2 (必须支持多提供者)
- **递归追问**: 为什么不能统一 API？→ 因为 LLM 提供者是独立公司/组织，各自定义自己的 API 协议和功能——不存在跨提供者的标准。OpenAI Chat、Anthropic Messages、Google Gemini 是不同的协议。
- **递归追问**: 为什么需要支持多提供者？→ 因为单一提供者存在容量限制、价格差异、模型特性差异——用户需要根据任务选择最适合的模型。
- **停止条件**: 环境约束 (没有跨提供者强制标准)
- **归属维度**: 边界 + 结构
- **反证检验**: 若所有 LLM 使用同一协议，还需要 Provider.Service 的协议适配层吗？不需要。约束成立。

### A5(结构+边界): 自定义扩展与核心系统的协作者分布在不同的信任域
- **源自**: C_Biz_3 (用户自定义扩展) + C_Arch_4 (MCP 独立进程) + C_Arch_5 (Effect 与外部桥接)
- **递归追问**: 为什么扩展在独立进程中？→ 因为 MCP 是跨进程协议——服务器可以是任意语言编写的独立程序。这是 MCP 规范的设计意图，非 opencode 特有。
- **递归追问**: 为什么 Effect 与外部回调需要桥接？→ 因为 Effect-TS 的 Fiber 运行时维护了请求上下文 (InstanceRef/WorkspaceRef)，外部 JS 回调没有这些上下文——这是 Effect 生态的技术限制。
- **停止条件**: 环境约束 (MCP 规范强制进程边界) + 架构约束 (Effect Runtime 上下文传播)
- **归属维度**: 结构 + 边界
- **反证检验**: 若 MCP 服务器都在同进程内运行且 Effect 运行时自动传播上下文，还需要 Plugin Bridge / MCP Transport 管理吗？不需要。约束成立。

### G(边界+时序): 构建一个可与文件系统/Shell 交互并完成软件工程任务的 AI 编程 Agent
- **源自**: C_Biz_1 (多轮工具调用) + C_Biz_4 (子Agent并行) + C_Biz_5 (持久化) + C_Biz_6 (多入口)
- **归属维度**: 边界 (需要跨越 LLM 文本边界) + 时序 (多轮交互循环)
- **反证检验**: 若只做单轮纯文本对话 (如 ChatGPT)，openode 不需要存在。
