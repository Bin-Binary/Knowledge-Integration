# S1 维度约束矩阵 — opencode v1.15.10
# Step 3 产出：三层拓扑约束扫描
# 来源：三源协议 (源码机制 / 官方文档 / LLM推演)

## 物理层 (不变量)

| 约束编号 | 扫描层级 | 约束描述 | 压迫维度 | 来源 (三源协议) |
| :--- | :--- | :--- | :--- | :--- |
| C_Phys_1 | 物理层 | LLM 推理需要网络往返 (RTT 100ms-10s)，本地文件操作 < 1ms，存在数量级速度鸿沟 | 时序 | 体系结构常识 |
| C_Phys_2 | 物理层 | LLM 上下文窗口有限 (8K-200K tokens)，大型代码库远超窗口容量 | 实体 | 体系结构常识 |
| C_Phys_3 | 物理层 | LLM 是状态无关的推理引擎，每次调用独立无记忆，无法跨调用保持执行状态 | 边界 | LLM推演 |
| C_Phys_4 | 物理层 | LLM 仅输出文本(token流)，无法直接触发文件I/O或进程执行 | 边界 | LLM推演 |

## 架构层 (环境囚笼)

| 约束编号 | 扫描层级 | 约束描述 | 压迫维度 | 来源 (三源协议) |
| :--- | :--- | :--- | :--- | :--- |
| C_Arch_1 | 架构层 | LLM 通过 HTTP API 交互，工具调用以 JSON tool_call 格式声明——声明与执行之间存在文本到行为的鸿沟 | 结构 | 源码机制 (provider.ts AI SDK) |
| C_Arch_2 | 架构层 | 工具执行可能修改文件系统或运行任意命令，具有破坏性，需要人机交互审批 | 边界 | 源码机制 (permission/index.ts) |
| C_Arch_3 | 架构层 | 不同 LLM 提供者 (OpenAI/Anthropic/Google/...) 的 API 协议格式不同 (Chat/Responses/Messages/Converse)，工具调用格式互不兼容 | 边界 | 源码机制 (provider.ts provider loaders) |
| C_Arch_4 | 架构层 | MCP 服务器是独立进程，通过 STDIO/SSE/StreamableHTTP 通信，存在进程边界和连接生命周期 | 边界 | 源码机制 (mcp/index.ts transports) |
| C_Arch_5 | 架构层 | Effect-TS 生态系统使用 Fiber-based 依赖注入和 Effect 生成器，所有服务需在 Effect Runtime 中运行——外部回调 (如 Plugin 的 Promise API) 需要桥接 | 结构 | 源码机制 (effect/bridge.ts) |
| C_Arch_6 | 架构层 | opencode 自身是用 Bun 运行的 TypeScript 进程，单线程事件循环，所有 I/O (文件/网络/shell) 必须是非阻塞的 | 时序 | 源码机制 (package.json: bun) |

## 业务层 (目标诉求)

| 约束编号 | 扫描层级 | 约束描述 | 压迫维度 | 来源 (三源协议) |
| :--- | :--- | :--- | :--- | :--- |
| C_Biz_1 | 业务层 | AI 编程 Agent 必须在单次会话中支持多轮工具调用，LLM 可能需要多次读写才能完成任务 | 时序 | 官方文档/源码 |
| C_Biz_2 | 业务层 | 必须支持多种 LLM 提供者，用户可自由切换模型，不同 Agent 可绑定不同模型 | 边界 | 官方文档 (agent.model字段) |
| C_Biz_3 | 业务层 | 必须支持用户自定义扩展：自定义 Tool、Agent、Skill、MCP Server、Plugin | 结构 | 官方文档 (config 系统) |
| C_Biz_4 | 业务层 | 必须支持子 Agent 并行执行 (task 工具)，子 Agent 结果需传回父会话 | 时序 | 源码机制 (task.ts background/sync) |
| C_Biz_5 | 业务层 | 必须持久化会话历史到 SQLite，支持跨重启恢复和会话分享 | 实体 | 源码机制 (storage/db.ts, session.sql.ts) |
| C_Biz_6 | 业务层 | 必须支持 Terminal UI (TUI)、Web UI、CLI、Headless Server 四种入口形态 | 结构 | 源码机制 (index.ts entry commands) |
