| :---- | :---- | :---- | :---- | :---- |

### 示例
| 1 | **PD分离** | Prefill-Decode Disaggregation | 将大模型推理的[预填充阶段（Prefill）](#jump-Prefill)与[解码阶段（Decode）](#jump-Decode)拆分到不同硬件上独立运行的架构。| 核心目的是彻底消除长文本输入和逐字输出之间的资源抢占与相互干扰。|
| 2 | **FFN** | Feed-Forward Network | 模型内部用于对特征进行非线性变换和知识映射的全连接网络层[详解](#jump-FFN) | 紧跟在自注意力（Self-Attention） 层之后 |
| 3 | **SA** | Self-Attention | 模型用于捕捉序列内部上下文关联的核心机制[详解](#jump-SA) | 大模型（Transformer）能够理解长文本的核心秘诀 |

## 核心概念拆解
| 序号 | 缩写 | 全称 | 含义 | 备注 |
| :---- | :---- | :---- | :---- | :---- |

### 示例
| 序号 | 缩写 | 全称 | 含义 | 备注 |
| :---- | :---- | :---- | :---- | :---- |
| 01 | W | <span id="jump-Weights"> 权重（Weights）</span> | 大模型经训练后冻结在网络中的静态参数矩阵，包含模型对知识的全部记忆与语义法则。推理时属于静态只读常量，是隐藏状态（激活值）进行矩阵乘法变换的映射底座 |
| 01-Ⅰ | | 动态全量读取（Full-Weight Loading）| 在Decode阶段，由于自回归无法并行，每生成一个新Token，隐藏状态都必须完整流经所有网络层。由于GPU计算核心（SRAM）存不下数十GB的权重，硬件每蹦一个字，都必须把全量静态权重从显存（HBM）中重新拉取、搬运进核心一次 |
| 02 | A | <span id="jump-Activations"> 激活值（Activations）</span> | 激活值是 AI 在思考、计算时的临时数据，相当于模型大脑正在“实时运算的思维草稿”。 |
| 03 |  | 分块预填充（Chunked Prefill）| 推理优化中一项关键技术。核心思想：将超长的新用户输入（Prompt）切分成多个较小的“数据块”（Chunks），分批次送入 GPU 进行计算 |

## 总结

### 示例
为了实现极高的智商 ➔ 科学家设计了万亿参数的 MoE 模型 ➔ 因为太庞大 ➔ 工程师用 TP+PP+EP+DP 把它拆分并克隆到全球的数据中心进行训练与部署 ➔ 为了在线上迎接高并发（QPS） ➔ 推理引擎开启 异步调度 与 连续批处理，用 PagedAttention 将显存切成固定页并消灭碎片 ➔ 为了应对企业级 RAG 和长提示词 ➔ 框架利用 Automatic Prefix Cache 跨用户共享显存块，配合 解耦部署 和 Chunked Prefill 彻底消灭长文本带来的卡顿 ➔ 最后，在芯片微观层面 ➔ 通过 Fullgraph 静态图 抹平 CPU 驱动开销，利用 MLP 权重预取 隐藏硬件搬运延迟，再套上 投机采样 让小模型盲猜，最终将大模型的蹦字速度拉到了物理极限
