## 脑裂
引子："x.xxx.xx.xx网关崩溃，问题根因：ARP 脑裂....."
### 资料查询
1. "“脑裂”（Split-Brain）一词源自神经科学和医学中的一个真实术语。
被计算机科学借用，用于形容分布式系统或高可用（HA）集群中，由通信中断导致系统分裂的现象。" 
2. 医学上的起源：裂脑人:
"神经科学家罗杰·斯佩里（Roger Sperry）等人研究了一群特殊的癫痫患者。
为了阻止癫痫在左右脑之间扩散，医生通过手术切断了患者连接左右脑的“桥梁”——胼胝体（Corpus Callosum）"
- "独立运作：术后，左脑和右脑失去了直接通信的能力，变成了两个独立的意识主体"
- "信息无法同步：由于左脑控制右手和语言，右脑控制左手和空间识别，当两个半脑接收到不同的指令时，身体会做出互相矛盾的行为（例如：左手正在穿裤子，右手却在解扣子）"
3. 计算机科学的借用:
- "胼胝体 -> 心跳网络（Heartbeat Network）：负责集群各节点之间同步状态和信息"
- "左/右脑 -> 主节点/备节点（Master/Backup）：共同控制整个系统的运作"
"当心跳网络中断时，集群的两个部分无法得知对方的存在。它们都以为对方已经“死”了，于是同时升级为主节点去争夺共享资源（如 VIP、磁盘、数据库）出现了两个独立且互相冲突的指挥官，导致系统行为彻底陷入混乱"

问题根因：VIP 双主冲突（ARP 脑裂）
7.212.76.27 (VIP)  ←  node0 (priority 100) + node1 (priority 90) 同时持有！
事件链：
node0（7.212.76.8）在 01:06 被宿主机强制重启
node1（7.212.77.195）的 keepalived 检测到 node0 下线，在 01:04 抑制 09:21 抢占为 MASTER，绑定 VIP
node0 重启后恢复，keepalived 以 priority 100 重新成为 MASTER，也绑定了 VIP
两台机器同时绑定 7.212.76.27/32，ARP 响应来回切换 → 外部请求被随机路由到两台机器的 HAProxy → 部分 TCP 连接收到 RST → ECONNRESET"

    ↓

    ↓ kubelet crash-loop（01:06~09:21, 持续 8 小时 15 分钟）

    ↓
[4] piglet 无法从 apiserver 获取 configmap:
    "get configmap failed: timed out waiting for the condition"
    "create controller failed: timed out waiting for the condition"
    ↓ piglet crash-loop（01:06~09:22, 每 ~9 分钟一次, 共 53 次）
[5] piglet 每次启动都会执行 HAController 初始化:
    - 监听 configmap `kube-system/cluster-info-smartkube-update`
    - 生成新的 haproxy 配置 + keepalived 配置
    - 调用 `cluster.sh systemctl_service reload haproxy`
    - 同时写 `/etc/keepalived/keepalived.conf` 并触发 keepalived reload
    ↓
[6] keepalived reload 时 VRRP 实例重置为 BACKUP(init)，释放 VIP
    → node1 抢占为 MASTER
    → node0 9 秒后回到 MASTER，但因 unicast_peer 空 + 多播不通，node1 收不到 advert 不退回
    → 双主脑裂（09:21:55~10:15:29）"

4. "[01:01] node0 宕机（华为云平台侧强制重启）
[01:04] node1 检测到 node0 下线，进入 MASTER，绑定 VIP
[01:06] node0 重启，keepalived 加载配置（有 unicast_peer）
        → unicast 通信正常
        → node0 priority 100 > node1 priority 90，抢占为 MASTER
        → node1 收到 advert，退回 BACKUP ✅ 正常收敛

[01:06~09:21] kubelet crash-loop（cgroup hugetlb 缺失）
              → piglet crash-loop（无法获取 configmap）
              → 但 piglet 的 HAController 没启动成功，不会重写配置
              → keepalived 配置正常（有 peer）✅

[09:21:18] 用户修复 cgroup，kubelet 恢复
[09:21:55] piglet HAController 首次成功启动，读取 configmap
           → 生成新的 keepalived.conf（从 piglet 模板，unicast_peer 为空）
           → 覆盖了人工修改的配置 ❌
           → keepalived reload，VRRP fallback 到 multicast
           → node0 进入 BACKUP(init)，VIP 被释放
           → node1 收不到 node0 的 advert（multicast 不通），进入 MASTER，绑定 VIP

[09:22:04] node0 9秒后回到 MASTER，重新绑定 VIP
           → 但 node0 发的 advert node1 收不到（multicast 不通）

           → 双主形成，无法收敛 ❌

[09:22:35] piglet 第二次 reload，再次重写配置（同样无 peer）
           → 配置被彻底固定为无 peer 版本

[10:15:29] 另一个 Agent 手动从 node1 删除 VIP + 停止 keepalived
           → 双主结束"
