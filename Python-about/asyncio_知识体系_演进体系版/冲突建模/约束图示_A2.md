# A2 约束图示

> A2 = C_Arch_1(时序:单线程串行) + C_Arch_2(结构:栈帧连续压栈不可中断)
> 归属维度: 时序 + 结构
> 不可再分事实: 遇到I/O等待时，无法保存断点切换执行其他任务

---

## 图1: A2 合效果 — 串行指针 × 连续栈帧的双重封锁

将时间轴(时序维度)与调用栈(结构维度)画在同一个坐标系中：
**上方是时间推进方向，下方是对应时刻的调用栈快照**。

```

                  C_Arch_1: 串行指针只能沿时间轴前进 ───┤   │  A2 的双重封锁机制:    │  │

```

**C_Arch_1 与 C_Arch_2 的封锁是正交且互补的**：
- C_Arch_1 封锁了"横向逃逸"——不能绕过等待点去执行别的代码
- C_Arch_2 封锁了"纵向逃逸"——不能把上面的栈帧拆出来移走
- 双重封锁的合力效应：**指针卡在等待点(时序)，栈帧卡在同一个等待点(结构)，两者互相锚定，谁也动不了**

## 图2: D2 的突破机制 — A2 被遵守而非被违反

**核心认知：A2是不可逾越的物理/架构事实，D2不是违反A2，而是换了一条不走入A2陷阱的路径。**

传统函数触发A2的原因：`sock.recv()` 是**阻塞系统调用**——调用后就卡住，直到数据到来。
协程的解法：用 `await` 把阻塞调用替换成**非阻塞检查 + 合作式返回**，整个过程中A2的两条规则从未被打破。

### 2c: 核心机制——coroutine对象如何保存断点(不在栈上!)

传统函数断点无法保存的原因：断点信息(局部变量、指令位置)只存在于**栈帧**中，栈帧是不可拆分的连续结构。

协程的解法：断点信息不再存放在栈上，而是存放在**堆上的coroutine对象**中。

```
┌─────────────────── 传统函数: 断点在栈上 ───────────────────┐
│                                                            │
│   调用栈                                               │
│   ┌─────────────────┐                                     │
│   │ main()          │                                     │
│   │  local: conn    │  ← 局部变量在栈帧中                 │
│   ├─────────────────┤                                     │
│   │ read_data()     │                                     │
│   │  local: buf     │  ← 局部变量在栈帧中                 │
│   ├─────────────────┤                                     │
│   │ sock.recv()     │  ← 阻塞在此                        │
│   │  (无局部变量)    │                                     │
│   └─────────────────┘                                     │
│         │                                                  │
│         │  栈帧是连续实心结构                               │
│         │  无法单独"取出"read_data的帧                      │
│         │  要返回read_data的结果，recv必须先返回             │
│         ▼                                                  │
│   ✗ 断点被锁死在栈中，无法保存                             │
└────────────────────────────────────────────────────────────┘

┌─────────────────── 协程: 断点在堆上 ──────────────────────┐
│                                                            │
│   调用栈 (运行时短暂存在)          堆内存 (持久化)          │
│   ┌─────────────────┐             ┌─────────────────┐     │
│   │ EventLoop       │             │ coroutine 对象   │     │
│   │   _run_once()   │             │  (堆上分配)       │     │
│   ├─────────────────┤             │                  │     │
│   │ Task.__step()   │   send()    │ ┌──────────────┐│     │
│   │                 │────────────►│ │ cr_frame      ││     │
│   │  coro.send()   │             │ │ ┌────────────┐││     │
│   └─────────────────┘             │ │ │ f_locals   │││     │
│         │                          │ │ │ {buf:...} │││ ← 断点信息
│   await时 coro yield               │ │ │ f_lasti:42│││    不在栈上!
│   → __step 返回                    │ │ └────────────┘││    在堆上的
│   → stack 完整弹出                  │ └──────────────┘│    coroutine对象中
│                                    │                  │     │
│   栈已清空!                        │ 生命周期: 跨越   │     │
│   EventLoop可执行其他任务           │ 多次send()调用   │     │
│   ✓ A2的两条规则没有被触碰          │ 而持续存在       │     │
│                                    └─────────────────┘     │
│                                                            │
│   恢复时:                                                  │
│   EventLoop → Task.__step → coro.send(None)               │
│   → coro对象从cr_frame恢复执行 → 从f_lasti=42继续         │
│   → 栈重新push——这是一次全新的函数调用，不是"恢复冻结的栈"  │
│   ✓ 栈帧仍然是连续push/pop，C_Arch_2完全遵守               │
└────────────────────────────────────────────────────────────┘
```

## 图3: A2在推导链中的传导位置(修正版)

             G + A1 → D1                        D1 + A2 → D2

## 总结

| 维度 | 约束 | 封锁效果 | 绕过方式(非违反!) |
|---|---|---|---|
| 时序(C_Arch_1) | 单线程串行控制流 | 指针不能绕过I/O等待 | D1+D2: await时函数**主动返回**，EventLoop**正常调用**下一个函数——指针始终沿调用链串行推进 |
| 结构(C_Arch_2) | 栈帧连续压栈不可中断 | 不能中途取出栈帧 | D2: await = **合作式return**——栈帧**正常弹出**，断点存在**堆上coroutine对象**而非栈上 |
| **A2合力** | **双重封锁** | **遇到I/O时既不能绕过也不能取帧** | **D2的全部机制都在A2规则内运作: 非阻塞I/O让函数可以正常返回, coroutine在堆上保存断点, EventLoop正常调度下一个函数** |

**一句话**: A2说"不能中途打断函数"，D2说"我没有打断——我让函数自己愿意返回，然后调用下一个函数。栈帧始终正常push/pop，指针始终沿调用链串行推进。"
