# Python 3.11 asyncio 实体粗筛 —— 核心机制

> 主导维度：**时序**（asyncio 的核心挑战是打断顺序时间轴以重叠 I/O 等待）
> SOP 顺序：时序 → 边界 → 结构 → 实体
> 合并规则：同一类型、≥2 维只有 1-2 行、共享强配对/继承、独立成卡不增加关系边

╔═══════════════════════════════════════════════════════════╗
║  【核心机制】EventLoop                                    ║
║  编号: E01 | 来源: base_events.py:387, selector_events.py:43, events.py ║
╚═══════════════════════════════════════════════════════════╝

【定义】 事件循环，主动轮询 I/O 就绪事件并调度回调执行的中心调度器

【时序】`run_forever()` → 循环调用 `_run_once()` → [清理定时回调 → 计算超时 → `selector.select(timeout)` → `_process_events()` → 到期定时回调移入 `_ready` → 逐个执行 `_ready` 中回调]

【边界】`selector.select()` 交出控制权给操作系统内核等待 I/O 事件；`run_in_executor()` 将阻塞操作交出给线程池；`call_soon_threadsafe()` 接受跨线程回调注入（通过 self-pipe 唤醒）

【结构】包含 `_ready` 双端队列（立即可执行回调）、`_scheduled` 最小堆（定时回调）、`_selector`（多路复用器）、`_transports` 弱引用字典

【实体】`_ready`(deque[Handle]), `_scheduled`(list[TimerHandle]), `_selector`(selectors.BaseSelector), `_thread_id`, `_closed`, `_stopping`, `_timer_cancelled_count`, `_default_executor`

【内部关联】
- EventLoop.call_soon() --[触发]--> Handle._run()
- EventLoop.create_task() --[包含]--> Task
- EventLoop._run_once() --[触发]--> Handle._run()
- EventLoop --[使用]--> _selector

【示例】
```python
loop = asyncio.new_event_loop()
loop.run_until_complete(coro())
```

╔═══════════════════════════════════════════════════════════╗
║  【核心机制】Handle + TimerHandle                         ║
║  编号: E02 | 来源: events.py:24, events.py:98             ║
╚═══════════════════════════════════════════════════════════╝

【定义】 回调的封装对象，TimerHandle 增加了定时调度能力（Handle 的时序特化，薄概念合并）

【时序】Handle: `call_soon()` 创建 → 加入 `_ready` → `_run_once()` 中取出 → `_run()` 执行；TimerHandle: `call_at()` 创建 → 加入 `_scheduled` 堆 → `_when` 到期 → 移入 `_ready` → `_run()` 执行；`cancel()` → 从队列移除/标记

【边界】`Handle._run()` 在事件循环线程内执行，异常由 `loop.call_exception_handler()` 处理，不跨边界传播

【结构】Handle → TimerHandle（继承）；Handle._callback + ._args → TimerHandle 增加 `_when` + `._scheduled`

【实体】Handle: `_callback`, `_args`, `_cancelled`, `_loop`, `_context`；TimerHandle: +`_when`, +`_scheduled`

【内部关联】
- EventLoop.call_soon() --[包含]--> Handle
- EventLoop.call_at() --[包含]--> TimerHandle
- TimerHandle._when 到期 --[触发]--> EventLoop._ready.append()

【示例】
```python
handle = loop.call_soon(callback, arg)
handle.cancel()
```

╔═══════════════════════════════════════════════════════════╗
║  【核心机制】Future                                       ║
║  编号: E03 | 来源: futures.py:30, base_futures.py         ║
╚═══════════════════════════════════════════════════════════╝

【定义】 异步结果的状态容器，通过状态机（PENDING → CANCELLED / FINISHED）锚定未来值，提供跨任务唤醒回调通道

【时序】创建(PENDING) → `set_result()`/`set_exception()`(FINISHED) → `__schedule_callbacks()` → 遍历 `_callbacks` → `loop.call_soon(每个callback)`；或者 `cancel()`(CANCELLED) → `__schedule_callbacks()`；`__await__()` 时 `yield self` → `Task.__wakeup()` 被注册为 callback

【边界】`__schedule_callbacks()` 通过 `loop.call_soon()` 将回调注入 EventLoop；`add_done_callback()` 在非 PENDING 时直接调度；与 `concurrent.futures.Future` 需通过 `wrap_future()` 桥接（跨线程边界）

【结构】独立对象，持有回调列表 `_callbacks[]`，绑定到单个 EventLoop

【实体】`_state`(PENDING/CANCELLED/FINISHED), `_result`, `_exception`, `_loop`, `_callbacks[]`, `_cancel_message`, `_cancelled_exc`, `_asyncio_future_blocking`

【内部关联】
- Future._state=FINISHED --[触发]--> Future.__schedule_callbacks()
- Future.__schedule_callbacks() --[触发]--> EventLoop.call_soon(callback)
- Task.__wakeup --[配对]--> Future
- Future.__await__() --[触发]--> Task.__step()

【示例】
```python
fut = loop.create_future()
await fut
```

╔═══════════════════════════════════════════════════════════╗
║  【核心机制】Task                                         ║
║  编号: E04 | 来源: tasks.py:78                            ║
╚═══════════════════════════════════════════════════════════╝

【定义】 协程的执行载体，继承 Future 的状态容器，通过 `__step()` 驱动协程运行并在 yield 点保存断点

【时序】`__init__()` → `call_soon(__step)` → `__step(None)`: `coro.send(None)` →
- 返回 Future: `fut.add_done_callback(__wakeup)`, `_fut_waiter=fut` → Future 完成 → `__wakeup()` → `__step()` → ...
- 返回 None（裸 yield）: `call_soon(__step)` → ...
- StopIteration: `super().set_result(exc.value)` → Future 完成 → 回调链
- 异常: `super().set_exception(exc)` → Future 完成 → 回调链
`cancel()` → 若 `_fut_waiter` 存在则 `cancel _fut_waiter`；否则 `_must_cancel=True` → 下次 `__step` 抛 CancelledError

【边界】`__step()` 中 `coro.send()`/`coro.throw()` 交出控制权给协程；协程 yield Future 时将控制权还给 EventLoop；`cancel()` 通过 `_fut_waiter.cancel()` 跨越 Task 边界传播取消

【结构】继承 Future，增加协程引用 `_coro` 和等待器 `_fut_waiter`；与 Future 配对：Task 禁止 `set_result`/`set_exception`

【实体】继承 Future 所有字段 + `_coro`(coroutine), `_fut_waiter`(Future|None), `_must_cancel`, `_cancel_message`, `_name`(str), `_num_cancels_requested`(int), `_context`(contextvars.Context)

【内部关联】
- Task --[包含]--> Future（继承）
- Task.__step() --[触发]--> coro.send()
- Task.__wakeup() --[触发]--> Task.__step()
- Task._fut_waiter --[配对]--> Future
- Task.cancel() --[触发]--> Future.cancel()

【示例】
```python
task = loop.create_task(coro())
await task
```

╔═══════════════════════════════════════════════════════════╗
║  【接口对】Protocol + Transport                           ║
║  编号: E05 | 来源: protocols.py, transports.py            ║
╚═══════════════════════════════════════════════════════════╝

【定义】 Protocol 是业务逻辑处理接口（接收数据回调），Transport 是 I/O 传输接口（发送数据/管理连接），二者 1:1 配对形成用户态与内核态的边界桥接层

【时序】连接建立: `loop._start_serving()` → 接受连接 → `transport=Transport(sock)` → `protocol=ProtocolFactory()` → `protocol.connection_made(transport)` → 数据到达: selector 检测 → `transport._read_ready()` → `protocol.data_received(data)` → 应用处理 → protocol 通过 `transport.write(data)` 发送；关闭: `transport.close()` → flush → `protocol.connection_lost(exc)`

【边界】Transport 封装 socket fd，通过 `selector.select()` 跨越内核/用户态边界；`Transport.write()` 缓冲后异步发送；Protocol 是纯粹的用户态逻辑，不直接接触 I/O

【结构】Protocol(Business) ↔ Transport(I/O) 1:1 配对；Transport(TCP) 层级: BaseSelectorEventLoop → _SelectorSocketTransport ↔ Protocol；Transport._protocol 持有 Protocol 引用，Protocol 通过 transport 参数获得 Transport

【实体】Transport: `_extra{}`, `_loop`, `_protocol`, `_sock`, `_buffer`(bytearray), `_closing`, `_paused`(读), `_protocol_paused`(写), `_high_water`, `_low_water`；Protocol: 无状态（纯接口）

【内部关联】
- Transport._read_ready() --[触发]--> Protocol.data_received()
- Protocol --[配对]--> Transport
- _FlowControlMixin._maybe_pause_protocol() --[触发]--> Protocol.pause_writing()

【示例】
```python
class MyProtocol(asyncio.Protocol):
    def data_received(self, data):
        self.transport.write(data)
```

║  【接口对】Selector + Proactor                            ║
║  编号: E06 | 来源: selector_events.py, proactor_events.py, windows_events.py ║
╚═══════════════════════════════════════════════════════════╝

【定义】 两种 I/O 事件感知模式——Selector 是"告诉我谁就绪了"（Reactor），Proactor 是"告诉我操作完成了"（Proactor，Windows IOCP）；薄概念合并

【时序】Selector: `select(timeout)` → [可读 fd 列表] → `_read_ready()` → 读取 → `data_received()`；Proactor: `recv()` → 发起 overlapped 读 → `IOCP._poll()` → 完成通知 → `_OverlappedFuture.set_result()`

【边界】Selector: `select()` 系统调用跨越内核边界；Proactor: IOCP 的 `PostQueuedCompletionStatus`/`GetQueuedCompletionStatus` 跨越内核边界

【结构】Selector 模式: 单 `selector.get_key(fd)` → events → callback；Proactor 模式: `IocpProactor._cache{}` → overlapped 操作 → IOCP 完成通知 → Future 结果

【实体】Selector: `_selector`(selectors.BaseSelector), `_internal_fds`；Proactor: `_iocp`(handle), `_cache{address:(fut,ov,obj,cb)}`, `_results[]`

【内部关联】
- Selector --[使用]--> EventLoop
- Proactor --[使用]--> EventLoop
- Proactor.recv() --[触发]--> Future.set_result()

【示例】
```
Unix 默认使用 SelectorEventLoop
Windows 默认使用 ProactorEventLoop
```

【定义】 单线程环境下的协程同步机制，通过 Future 实现让出-唤醒模式；结构高度相似，合并为一个族群

【示例】
```python

    ...
```

- TaskGroup._abort() --[触发]--> Task.cancel()
- TaskGroup.__aexit__() --[使用]--> Future(await)

【示例】
```python
async with asyncio.TaskGroup() as g:

```

