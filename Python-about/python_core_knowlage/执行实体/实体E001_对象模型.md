# 执行实体: Python统一对象模型

> Step 4 | N0→D1 | 突破维度: 结构

---

╔═══════════════════════════════════════════════════════════╗
║  【概念模型】Python统一对象模型                            ║
║  编号: E001 | 来源: C000-C005,C123                       ║
╚═══════════════════════════════════════════════════════════╝

【定义】 Python中一切数据均为PyObject, 由id(标识)、type(类型)、value(值)三元组唯一确定, 变量名是对对象的引用绑定。

【冲突溯源】 归属于 N0: 动态统一对象模型 → D1(一切皆对象+强类型+鸭子类型), 突破维度: 结构

【设计内因】 D1工程目标: 用统一对象模型消除内置类型与用户类型的二元鸿沟, 在无类型声明前提下提供运行时类型反射能力。
  通用困境:
  - (结构) 类型系统一致性困境: 为内置类型(int)和用户类型(class)维护两套机制破坏反射/序列化等通用工具
  - (实体) 变量绑定语义选择: 值语义导致深拷贝代价大, 引用语义导致共享修改风险

  SC1(结构): [归属困境: 类型一致性] 若int/str与自定义class类型机制不同, 则type()/id()/dir()等通用反射API无法统一操作 ← 破坏"一切皆对象"承诺 [统一性约束] → 选择: 所有值(含int/bool/None)均继承PyObject共用ob_refcnt+ob_type头部, type(obj)始终有效 | 代价: 小整数/None有16+byte头部开销

  SC2(实体): [归属困境: 引用vs值语义] 赋值/传参若复制数据, 大型对象代价不可接受; 若仅复制引用, 则共享修改可能意外 [语义折中约束] → 选择: 赋值=INCREF+绑定引用(无拷贝), 增设is(指针比较)与==(值比较通过__eq__)分离 | 代价: is vs ==混用是经典陷阱; 函数内修改可变参数溢出影响调用者

【结构】"它长什么样？" {★★★}
- PyObject统一基类: ob_refcnt(引用计数) + ob_type(类型指针)
- 类型对象PyTypeObject: tp_name, tp_basicsize, tp_call, tp_getattr…
- 二分对象图: 实例↔类型; type的type=自身 (元循环闭合)
- id()返回CPython内存地址; type()返回类型对象指针

【时序】"它按什么顺序动？" {★★}
- 赋值(=): 计算右值 → 绑定名字 → INCREF新 → DECREF旧
- 属性查询obj.attr: obj.__dict__ → type(obj).__dict__ → MRO上溯
- 对象析构: DECREF → ob_refcnt=0 → tp_dealloc → 释放内存

【实体】"它的最小数据单元？" {★★}
- PyObject: ob_refcnt(ssize_t) + ob_type(PyTypeObject*)
- PyVarObject: 继承PyObject + ob_size(Py_ssize_t)

【边界】"它在哪里交出控制权？" {★}
- 属性查询失败: AttributeError → 异常传播
- isinstance/issubclass: 遍历MRO链 O(n)
- 类型对象创建: 元类__new__/__init__拦截

【内部关联】
- PyObject.ob_type --[配对(实例→元类型)]--> PyTypeObject
- 名字绑定 --[使用(名字→对象引用)]--> PyObject (通过名字空间dict)
- is运算符 --[触发(身份比较→指针比对)]--> id()内存地址
- ==运算符 --[触发(值比较→用户定义)]--> __eq__方法

【示例】
```python
a = 256; b = 256
print(a is b)    # True (小整数池缓存同一对象)
a = 500; b = 500
print(a is b)    # False (不同对象)
print(a == b)    # True (值相等)
print(type(int))       # <class 'type'>
print(type(type))      # <class 'type'> (自指)
```
