# S2_0号约束: Python核心

> Step 3.2 产出 | 递归终点: 不可再分的约束事实

## 0号约束表

| 0号约束编号 | 源自S1约束 | 递归终点描述 (不可再分事实) | 归属维度 |
|:---|:---|:---|:---|
| A1: 动态统一对象模型 | C_Lang_1, C_Lang_3, C_Lang_4 | 所有数据均为PyObject, 变量是对象引用(指针), 类型绑定在对象上, 无静态类型保证 | 结构+实体 |
| A2: 强制可读性准则 | C_Biz_1, C_Biz_2 | 语法/API设计必须优先考虑人类可读性, 缩进即代码块, 避免隐式魔法 | 结构 |
| A3: 强类型界墙 | C_Lang_2, C_Lang_6 | 类型不可隐式转换, 错误通过异常传播, 阻止模糊语义的静默传播 | 实体+时序 |
| A4: 单线程安全保证(GIL) | C_Arch_2 | CPython同一时刻只能有一个线程执行字节码, 引用计数操作本质安全 | 时序 |
| A5: 内存确定性释放(RC) | C_Arch_1, C_Phys_1 | 对象引用计数归零时立即释放内存, 是CPython内存管理的默认策略 | 时序+实体 |
| A6: 解释型执行模型 | C_Arch_5 | 源码在运行时被编译为字节码执行(非预先编译为原生代码), 允许动态import/exec/eval | 时序+边界 |
| A7: 抽象代价最小化 | C_Phys_2, C_OS_2, C_Biz_3 | 高级抽象不能显著牺牲性能, 通过C扩展使性能敏感路径绕过解释器开销 | 边界+时序 |
