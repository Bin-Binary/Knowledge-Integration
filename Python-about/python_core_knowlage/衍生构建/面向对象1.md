# Python核心基础（七）：面向对象Python式——类/继承/描述符/MRO

## 引言

面向对象编程（OOP）是工业界最主流的编程范式之一，但每种语言对OOP的实现截然不同，背后折射的是各自的设计哲学与工程取舍：

- **C++**：class定义vtable（虚函数表），支持多重继承，菱形继承需用`virtual`关键字解决二义性。编译期确定布局，运行期多态通过vtable间接跳转。代价：内存布局复杂、指针调整（thunk）、ABI脆弱。
- **Java**：单继承 + 接口。所有类继承自`Object`，接口是纯行为契约（Java 8后有default method）。代价：值类型无法继承、接口无法携带状态、default method引发钻石问题的新变体。
- **Rust**：traits（特征），无继承，纯组合。trait是静态分派的泛型约束（`impl Trait for Type`），dyn Trait做动态分派。代价：学习曲线陡峭、孤儿规则限制、无运行时反射。
- **Go**：结构化类型（structural typing），无class。接口是隐式满足（duck typing的编译期版本），组合通过embedding。代价：无多态方法重写、无泛型（1.18之前）、embedding非真正继承。

**Python的激进选择**：class是一个**可调用的类型对象**（`type.__call__`），继承 = **MRO线性化**（C3算法），属性访问 = **描述符协议**（不只是dict查找）。这意味着：

1. **类本身是对象**：`type`是自己的实例（`type(type) is type`），元类可以拦截类的创建过程
2. **继承是线性化的**：C3算法将菱形图压为一条线性链，消除二义性，同时保证单调性
3. **属性访问是协议驱动的**：`obj.x`不是简单的dict查找，而是经过descriptor协议的层层调度

**Tradeoff**：极致的灵活性（元类、描述符、动态修改类） vs 无编译期类型安全。Python的OOP是"运行时协议"的典范——一切皆协议，一切皆可拦截，但代价是运行时才能发现类型错误。

## 一、类对象与实例对象——type造万物的OOP版

### 1.1 class语句的执行过程

Python中，`class`语句不是声明，而是**可执行语句**。执行`class Foo:`时，Python运行类体代码、构建名字空间、调用元类创建类对象。

**完整流程**：

```
class Foo(Base, metaclass=Meta):
    x = 1
    def method(self): pass

↓ 执行过程 ↓

1. 解析基类列表 → bases = (Base,)
2. 解析元类 → metaclass = Meta（若无，则取bases中第一个类型的type，最终回退到type）
3. 执行类体代码，构建namespace字典：
   exec(class_body_code, namespace)  # namespace = {'__module__': ..., '__qualname__': ..., 'x': 1, 'method': <function>}
4. 调用元类创建类对象：
   Foo = metaclass('Foo', (Base,), namespace)
   → 等价于 Meta.__call__('Foo', (Base,), namespace)
   → Meta.__new__(Meta, 'Foo', (Base,), namespace)  # 创建类对象
   → Meta.__init__(Foo, 'Foo', (Base,), namespace)   # 初始化类对象
5. 计算MRO：Foo.__mro__ = (Foo, Base, object)  # C3算法
6. 返回Foo类对象
```

**CPython内部——PyTypeObject的创建**：

```c
// CPython Objects/typeobject.c
// type.__call__ 的核心实现（简化版）
static PyObject *
type_call(PyTypeObject *type, PyObject *args, PyObject *kwds)
{
    PyObject *obj;
    // 1. 调用 tp_new 分配内存
    obj = type->tp_new(type, args, kwds);
    if (obj == NULL) return NULL;

    // 2. 如果 tp_new 返回的类型与 type 不一致，跳过 tp_init
    if (Py_TYPE(obj) != type) return obj;

    // 3. 调用 tp_init 初始化
    int res = type->tp_init(obj, args, kwds);
    if (res < 0) {
        Py_DECREF(obj);
        return NULL;
    }
    return obj;
}
```

`PyTypeObject`是C层表示Python类型的结构体，包含大量**类型槽（type slots）**：

```c
// CPython Include/cpython/object.h （简化版）
typedef struct _typeobject {
    PyObject_VAR_HEAD
    const char *tp_name;           // 类型名 "Foo"
    Py_ssize_t tp_basicsize;       // 实例基本大小
    Py_ssize_t tp_itemsize;        // 每个元素的大小（变长对象用）
    destructor tp_dealloc;         // 析构函数
    Py_ssize_t tp_vectorcall_offset;
    getattrfunc tp_getattr;
    setattrfunc tp_setattr;
    PyAsyncMethods *tp_as_async;
    reprfunc tp_repr;              // __repr__
    PyNumberMethods *tp_as_number; // 数值运算 (__add__, __mul__ 等)
    PySequenceMethods *tp_as_sequence; // 序列操作 (__len__, __getitem__ 等)
    PyMappingMethods *tp_as_mapping;   // 映射操作 (__getitem__, __setitem__ 等)
    hashfunc tp_hash;              // __hash__
    ternaryfunc tp_call;           // __call__
    reprfunc tp_str;               // __str__
    getattrofunc tp_getattro;      // __getattribute__
    setattrofunc tp_setattro;      // __setattr__
    PyObject *tp_bases;            // 基类元组
    PyObject *tp_dict;             // 类的 __dict__
    descrgetfunc tp_descr_get;     // 描述符 __get__
    descrsetfunc tp_descr_set;     // 描述符 __set__/__delete__
    Py_ssize_t tp_dictoffset;      // 实例 __dict__ 的偏移量
    initproc tp_init;              // __init__
    allocfunc tp_alloc;            // 内存分配
    newfunc tp_new;                // __new__
    freefunc tp_free;              // 内存释放
    PyObject *tp_mro;              // MRO元组！C3线性化结果
    // ... 更多字段
} PyTypeObject;
```

关键字段解读：
- `tp_new`：对应`__new__`，负责**分配内存**并返回对象
- `tp_init`：对应`__init__`，负责**初始化**已分配的对象
- `tp_mro`：对应`__mro__`，C3线性化结果，是一个**元组**，属性查找按此顺序遍历
- `tp_dict`：类的`__dict__`，存储类属性、方法、描述符等
- `tp_descr_get`/`tp_descr_set`：类型本身的描述符槽

**实验：元类__new__拦截与名字空间检查**

```python
class MetaInspect(type):

        print(f"  基类: {bases}")
        print(f"  名字空间键: {list(namespace.keys())}")

        cls = super().__new__(mcs, name, bases, namespace)
        print(f"  MRO: {cls.__mro__}")
        print(f"  tp_basicsize (实例大小): {cls.__basicsize__}")
        return cls

class Base(metaclass=MetaInspect):

    def method(self):
        return self.x

# 输出:
```

### 1.2 __new__与__init__——创建的两阶段

Python的对象创建分为两个明确阶段：

| 阶段 | 方法 | C层槽位 | 职责 | 返回值 | 是否可选 |
|------|------|---------|------|--------|------------|
| 分配 | `__new__(cls, ...)` | `tp_new` | 分配内存、构造对象 | 新对象 | 是（默认`object.__new__`） |
| 初始化 | `__init__(self, ...)` | `tp_init` | 设置属性、初始化状态 | `None` | 是（默认空操作） |

**为什么需要两阶段？核心原因：不可变类型**

```python
# 不可变类型（tuple, str, int, frozenset）必须在创建时就确定值
# 因为创建后无法修改，所以值必须在 __new__ 阶段设置

class MyTuple(tuple):
    # 错误做法：试图在 __init__ 中修改 tuple 内容
    # def __init__(self, items):  # 无效！tuple已创建，无法追加元素

    # 正确做法：在 __new__ 中设置值
    def __new__(cls, items, separator=','):
        instance = super().__new__(cls, items)
        instance._separator = separator  # 附加属性可以在 __new__ 中设
        return instance

    def __str__(self):
        return self._separator.join(str(x) for x in self)

t = MyTuple([1, 2, 3], separator=' | ')
print(t)  # 1 | 2 | 3
```

**单例模式——利用__new__控制实例创建**

```python
class Singleton:
    _instance = None
    _initialized = False

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            print(f"[__new__] 首次创建实例")
            cls._instance = super().__new__(cls)
        else:
            print(f"[__new__] 返回缓存的实例")
        return cls._instance

    def __init__(self, value):
        # 注意：每次 Singleton() 都会调用 __init__！
        # 必须手动防止重复初始化
        if not self._initialized:
            print(f"[__init__] 初始化实例, value={value}")
            self.value = value
            self._initialized = True
        else:
            print(f"[__init__] 跳过重复初始化 (value={value} 被忽略)")

s1 = Singleton(42)
# [__new__] 首次创建实例
# [__init__] 初始化实例, value=42

s2 = Singleton(99)
# [__new__] 返回缓存的实例
# [__init__] 跳过重复初始化 (value=99 被忽略)

print(s1 is s2)          # True
print(s1.value)          # 42（不是99！）
```

**重要陷阱**：`__new__`返回缓存实例时，`type.__call__`**仍然会调用`__init__`**！因为`type_call`中`Py_TYPE(obj) == type`检查通过（返回的还是同一个类的实例），所以`tp_init`照常执行。必须在`__init__`中做保护。

**实验：追踪__new__与__init__的调用关系**

```python
class Tracked:
    def __new__(cls, *args, **kwargs):
        print(f"  __new__ called: cls={cls.__name__}, args={args}")
        instance = super().__new__(cls)
        print(f"  __new__ returned: id={id(instance):#x}")
        return instance

    def __init__(self, *args, **kwargs):
        print(f"  __init__ called: self.id={id(self):#x}, args={args}")

print("=== 创建第一个实例 ===")
t1 = Tracked('hello')
#   __new__ called: cls=Tracked, args=('hello',)
#   __new__ returned: id=0x7f...
#   __init__ called: self.id=0x7f..., args=('hello',)

print("\n=== __new__返回非本类实例时，__init__会被跳过 ===")
class Other:
    pass

class WeirdNew:
    def __new__(cls, *args, **kwargs):
        print(f"  __new__ 返回了 Other 类的实例！")
        return Other()  # 返回不同类型的实例

    def __init__(self, *args, **kwargs):
        print(f"  __init__ called （这条不会打印）")

w = WeirdNew()
#   __new__ 返回了 Other 类的实例！
# __init__ 被跳过！因为 type_call 检测到返回类型 != 调用类型

print(type(w))  # <class '__main__.Other'>
```

### 1.3 self与绑定方法

Python的方法不是什么特殊的东西——**方法就是函数 + 描述符绑定**。

**PyMethodObject结构（CPython 3.12之前）**：

```c
// CPython 3.11 Include/cpython/classobject.h
typedef struct {
    PyObject_HEAD
    PyObject *im_func;   // 底层函数对象
    PyObject *im_self;   // 绑定的实例（NULL表示未绑定）
    PyObject *im_weakreflist;
    PyObject *im_module;
} PyMethodObject;
```

> 注意：CPython 3.12+ 对方法对象做了大幅优化（vectorcall、内联方法等），但语义不变。

**绑定过程**：

```python
class Foo:
    def method(self, x):
        return self, x

f = Foo()

# 1. 属性查找：f.method → 触发描述符协议
#    Foo.method 是一个函数对象，函数实现了 __get__ 描述符协议
#    Foo.method.__get__(f, type(f)) → 返回绑定的方法对象

# 2. 绑定方法对象
bound = f.method
print(type(bound))      # <class 'method'>
print(bound.__self__)   # <Foo object at 0x...>  → 就是 f
print(bound.__func__)   # <function Foo.method at 0x...>  → 原始函数

# 3. 调用绑定方法
result = bound(42)
# 等价于：bound.__func__(bound.__self__, 42)
# 即：    Foo.method(f, 42)
print(result)           # (<Foo object>, 42)

# 4. 未绑定调用（直接从类获取函数）
# 在Python 3中，Foo.method 直接返回函数（不是未绑定方法）
raw = Foo.__dict__['method']  # 直接访问原始函数
print(type(raw))        # <class 'function'>
result2 = raw(f, 42)   # 必须手动传 self
print(result2)          # (<Foo object>, 42)
```

**字节码层面——方法调用的绑定机制**

```python
import dis

dis.dis(compile("f.method(42)", '<test>', 'exec'))
# 1           0 LOAD_NAME                0 (f)
#             2 LOAD_METHOD              1 (method)
#             4 LOAD_CONST               0 (42)
#             6 CALL_METHOD              1

# LOAD_METHOD 的语义（优化路径）:
#   1. 查找 type(f).__mro__ 中的 'method'
#   2. 如果找到的是函数 → 直接加载函数和实例，标记为"需要绑定"
#   3. CALL_METHOD 时: 如果标记了 → 自动插入 self 参数
#   4. 如果找到的不是函数(如已绑定的方法或其他可调用对象) → 正常调用
#
# 这避免了每次都创建 PyMethodObject 的开销！
# CPython 3.7+ 的优化：LOAD_METHOD + CALL_METHOD 替代了旧的 LOAD_ATTR + CALL_FUNCTION
```

**实验：手动模拟绑定过程**

```python
class Demo:
    def greet(self, name):
        return f"Hello, {name}! I am {id(self):#x}"

d = Demo()

# 方式1：正常调用
print(d.greet("Alice"))

# 方式2：手动描述符绑定
func = Demo.__dict__['greet']        # 获取原始函数
bound_method = func.__get__(d, Demo)  # 手动调用 __get__
print(bound_method("Bob"))            # 等价于 d.greet("Bob")

# 方式3：直接调用函数
print(func(d, "Charlie"))             # 手动传self

# 方式4：从类获取（Python 3中直接返回函数，非未绑定方法）
method_from_class = Demo.greet        # 注意：这里经过描述符，但unbound
# Demo.greet 本质上是 Demo.__dict__['greet'].__get__(None, Demo)
# 当 __get__ 的第一个参数是 None 时，返回函数本身
print(type(Demo.greet))               # <class 'function'>
print(Demo.greet(d, "David"))         # 可以这样调用

# 验证：__get__(None, type) 返回函数本身
raw_via_get = func.__get__(None, Demo)
print(raw_via_get is func)  # True！
```

## 二、继承与MRO——C3线性化的智慧

### 2.1 单继承——名字空间链

单继承下的属性查找遵循**MRO链**（Method Resolution Order）：

```python
class A:
    x = 1
    def foo(self): return "A.foo"

class B(A):
    y = 2
    def foo(self): return "B.foo"
    def bar(self): return "B.bar"

class C(B):
    z = 3
    def foo(self): return "C.foo"

c = C()

# 属性查找顺序: c.__dict__ → C.__dict__ → B.__dict__ → A.__dict__ → object.__dict__
# 即按 C.__mro__ 顺序查找

print(C.__mro__)
# (<class 'C'>, <class 'B'>, <class 'A'>, <class 'object'>)

print(c.x)  # 1  — 在A中找到
print(c.y)  # 2  — 在B中找到
print(c.z)  # 3  — 在C中找到

# 实例的 __dict__ 优先于类
c.x = 999
print(c.x)      # 999  — 实例 __dict__ 中找到
print(C.x)      # 未定义，但 A.x 仍为 1
print(A.x)      # 1
```

**CPython中的属性查找——_PyObject_GenericGetAttrWithDict（简化版）**：

```c
// CPython Objects/object.c
// 这是 object.__getattribute__ 的核心实现
PyObject *
_PyObject_GenericGetAttrWithDict(PyObject *obj, PyObject *name,
                                  PyObject **dict, int suppress)
{
    PyTypeObject *tp = Py_TYPE(obj);
    PyObject *descr = NULL;

    // 1. 在MRO中查找描述符（按MRO顺序搜索 tp_dict）
    descr = _PyType_Lookup(tp, name);  // 沿MRO链查找

    // 2. 检查是否是数据描述符（定义了 __get__ + __set__/__delete__）
    //    数据描述符优先于实例 __dict__
    if (descr != NULL) {
        descrgetfunc f = Py_TYPE(descr)->tp_descr_get;
        if (f != NULL && (Py_TYPE(descr)->tp_descr_set != NULL ||
                          descr == &(Py_TYPE(descr)->tp_dict))) {
            // 数据描述符 → 直接调用 __get__
            return f(descr, obj, (PyObject *)tp);
        }
    }

    // 3. 查找实例 __dict__
    if (dict != NULL && *dict != NULL) {
        PyObject *attr = PyDict_GetItem(*dict, name);
        if (attr != NULL) {
            return Py_NewRef(attr);
        }
    }

    // 4. 非数据描述符（只有 __get__，或无描述符协议）
    if (descr != NULL) {
        descrgetfunc f = Py_TYPE(descr)->tp_descr_get;
        if (f != NULL) {
            // 非数据描述符（如函数） → 调用 __get__ 返回绑定方法
            return f(descr, obj, (PyObject *)tp);
        }
        return Py_NewRef(descr);  // 普通类属性，直接返回
    }

    // 5. __getattr__ 钩子
    if (!suppress) {
        // 调用 __getattr__ 作为fallback
    }

    // 6. AttributeError
    PyErr_Format(PyExc_AttributeError,
                 "'%.50s' object has no attribute '%U'",
                 tp->tp_name, name);
    return NULL;
}
```

这个查找顺序揭示了**描述符协议的核心地位**：属性访问不是简单的dict查找，而是经过精心设计的优先级调度。

### 2.2 多继承与菱形问题

**菱形继承（Diamond Problem）**：

```
    A
   / \
  B   C
   \ /
    D
```

```python
class A:
    def who(self): return "A"

class B(A):
    def who(self): return "B"

class C(A):
    def who(self): return "C"

class D(B, C):
    pass

d = D()
print(d.who())  # "B" — 为什么？
print(D.__mro__)
# (<class 'D'>, <class 'B'>, <class 'C'>, <class 'A'>, <class 'object'>)
# 按MRO顺序，第一个定义who的是B
```

**C++如何处理菱形问题**：

C++默认不合并菱形顶点，`D`对象中包含两份`A`：

```cpp
// C++
class A { public: int x; };
class B : public A { };
class C : public A { };
class D : public B, public C { };

D d;
d.x = 1;     // 编译错误！二义性：是 B::A::x 还是 C::A::x？
d.B::x = 1;  // 必须显式指定
d.C::x = 2;  // 另一份A的x

// 解决方案：virtual继承
class B : virtual public A { };
class C : virtual public A { };
// 现在D中只有一份A，但virtual继承引入了vbase offset和运行时调整
```

Python的MRO自动解决了这个问题——C3线性化保证`A`只出现一次，且顺序一致。

**C3线性化算法**：

C3算法的核心思想：**单调性**——如果类在基类列表中出现在另一个类之前，那么在MRO中也必须保持这个顺序。

```
L[C] = C + merge(L[B1], L[B2], ..., [B1, B2, ...])
                                      ↑ 基类列表本身

merge 的规则：
1. 取第一个列表的头部（第一个元素）
2. 检查该头部是否出现在其他列表的尾部（除了第一个位置以外的部分）
3. 如果没有出现在任何尾部 → 好的头部，选它，从所有列表中删除它
4. 如果出现在某个尾部 → 坏的头部，跳过，看下一个列表的头部
5. 重复直到所有列表为空 → 完成
6. 如果所有列表的头部都是坏的 → 无法线性化，TypeError

好的头部 = 不在任何其他列表尾部中的元素
```

**手动计算菱形继承的MRO**：

```
L[A] = A + merge(L[object], [object])
     = A + merge([object], [object])
     = A + [object]
     = [A, object]

L[B] = B + merge(L[A], [A])
     = B + merge([A, object], [A])
     = B + A + merge([object], [])
     = [B, A, object]

L[C] = C + merge(L[A], [A])
     = [C, A, object]  （同理）

L[D] = D + merge(L[B], L[C], [B, C])
     = D + merge([B, A, object], [C, A, object], [B, C])

Step 1: B — 在其他列表尾部？不在（第三列表尾部是[C]，B不在其中）→ 选B
     = D + B + merge([A, object], [C, A, object], [C])

Step 2: A — 在其他列表尾部？在第二个列表的尾部[A, object]中（A是尾部元素？）
     不对！尾部是指除第一个元素以外的元素。
     第二列表 = [C, A, object]，尾部 = [A, object]，A在其中 → 坏头部
     看下一个列表的头部：C
     C — 在其他列表尾部？第一列表尾部=[object]，C不在 → 选C
     = D + B + C + merge([A, object], [A, object], [])

Step 3: A — 在其他列表尾部？第二列表已空。
     第一列表[A, object]尾部=[object]，A不在 → 选A
     = D + B + C + A + merge([object], [object], [])

Step 4: object — 选object
     = [D, B, C, A, object]

验证: D.__mro__ = (D, B, C, A, object) ✓
```

**C3失败案例**：

```python
# 不一致的继承顺序
class X:
    pass

class Y:
    pass

class A(X, Y):  # MRO: [A, X, Y, object]
    pass

class B(Y, X):  # MRO: [B, Y, X, object]  — 注意Y在X前！
    pass

class C(A, B):  # 试图合并
    pass
# TypeError: Cannot create a consistent method resolution
# order (MRO) for bases X, Y
#
# 原因：
# L[C] = C + merge([A, X, Y, object], [B, Y, X, object], [A, B])
# Step 1: A — 选A
# C + A + merge([X, Y, object], [B, Y, X, object], [B])
# Step 2: X — 在第二列表尾部[Y, X, object]中？X在尾部中 → 坏头部
#         B — 在第一列表尾部[Y, object]中？不在 → 选B
# C + A + B + merge([X, Y, object], [Y, X, object], [])
# Step 3: X — 在第二列表尾部[X, object]中 → 坏
#         Y — 在第一列表尾部[object]中？不在 → 选Y... 等等
#         第一列表现在是[X, Y, object]，Y是第二个元素
#         哦不对，merge每步只取第一个列表的头部，如果坏则看下一个列表
# C + A + B + merge([X, Y, object], [Y, X, object])
# 第一列表头部 X → 在第二列表尾部[X, object]中 → 坏
# 第二列表头部 Y → 在第一列表尾部[Y, object]中 → 坏
# 没有好头部 → TypeError!
```

这个例子精妙地展示了C3的**单调性保证**：`A`承诺`X`在`Y`前面，`B`承诺`Y`在`X`前面，两者矛盾，C3拒绝构建。

### 2.3 super()——协作式多继承

**最大的误解**：`super()`调用"父类方法"——错！`super()`调用**MRO中的下一个类**的方法。

```python
class A:
    def __init__(self):
        print("A.__init__")
        super().__init__()  # 这不是调用object.__init__——在MRO上下文中看

class B(A):
    def __init__(self):
        print("B.__init__")
        super().__init__()

class C(A):
    def __init__(self):
        print("C.__init__")
        super().__init__()

class D(B, C):
    def __init__(self):
        print("D.__init__")
        super().__init__()

# D 的 MRO: D → B → C → A → object
d = D()
# D.__init__
# B.__init__    ← super() in D calls B's __init__ (next in MRO after D)
# C.__init__    ← super() in B calls C's __init__ (next in MRO after B)
# A.__init__    ← super() in C calls A's __init__ (next in MRO after C)
#               ← super() in A calls object.__init__ (next after A)
```

**关键理解**：`super()`不是静态地调用"父类"，而是**动态地查找MRO中当前位置的下一个类**。

```
D 的 MRO: [D, B, C, A, object]

D.__init__ 中的 super() → 找 D 在 MRO 中的位置 → 下一个是 B → 调用 B.__init__
B.__init__ 中的 super() → 找 B 在 type(self).__mro__ 中的位置 → type(self) 是 D！
                          → D.__mro__ = [D, B, C, A, object]
                          → B 后面是 C → 调用 C.__init__
C.__init__ 中的 super() → 找 C 在 D.__mro__ 中的位置 → C 后面是 A → 调用 A.__init__
A.__init__ 中的 super() → 找 A 在 D.__mro__ 中的位置 → A 后面是 object → 调用 object.__init__
```

注意`super()`使用的是`type(self).__mro__`，即**实例实际类型的MRO**，而不是当前方法定义所在类的MRO。这就是为什么`B.__init__`中的`super()`调用的是`C`而不是`object`——因为`self`是`D`的实例。

**super()的两种调用形式**：

```python
# 1. 零参数形式（Python 3+，最常用）
super()  # 自动推断：__class__ + self

# 2. 两参数形式（显式指定）
super(Cls, self)  # 从 Cls 在 type(self).__mro__ 中的位置开始

# 零参数形式在字节码中的实现
import dis

class Example:
    def method(self):
        super().method()

dis.dis(Example.method)
# 注意字节码中的 __class__ 变量：
# 2           0 LOAD_GLOBAL              1 (super)
#             2 LOAD_FAST                1 (__class__)  ← 编译器自动注入
#             4 LOAD_FAST                0 (self)
#             6 CALL_FUNCTION            2
#             8 LOAD_METHOD              2 (method)
#            10 CALL_METHOD              0
#            12 RETURN_VALUE
```

**CPython中super()的实现**：

```c
// CPython Objects/superobject.c （简化版）
staticPyObject *
super_getattro(PyObject *self, PyObject *name)
{
    superobject *su = (superobject *)self;
    PyTypeObject *starttype;
    PyObject *mro;
    Py_ssize_t i;

    // 1. 确定"起始类型"：su->type（即super(Cls, self)中的Cls）
    starttype = su->type;
    if (starttype == NULL) {
        // 零参数super()：使用 __class__ cell variable
        starttype = su->obj_type; // 从实例推断
    }

    mro = Py_TYPE(su->obj)->tp_mro;  // 获取实例类型的MRO

    // 2. 在MRO中找到starttype的位置
    for (i = 0; i < PyTuple_GET_SIZE(mro); i++) {
        if (PyTuple_GET_ITEM(mro, i) == (PyObject *)starttype) {
            i++;  // 移到下一个位置！这就是"super"的含义
            break;
        }
    }

    // 3. 从下一个位置开始查找属性
    for (; i < PyTuple_GET_SIZE(mro); i++) {
        PyTypeObject *cls = (PyTypeObject *)PyTuple_GET_ITEM(mro, i);
        PyObject *res = PyObject_GenericGetAttr((PyObject *)cls, name);
        if (res != NULL) return res;
    }

    // 4. 未找到
    PyErr_SetObject(PyExc_AttributeError, name);
    return NULL;
}
```

**为什么super至关重要——协作式框架**

```python
# 插件/混入模式：每个类只做自己的事，通过super协作
class LogMixin:
    def save(self, data):
        print(f"[LOG] Saving: {data}")
        super().save(data)  # 向MRO下一个类委托

class ValidateMixin:
    def save(self, data):
        if not data:
            raise ValueError("数据不能为空")
        print(f"[Validate] 数据验证通过")
        super().save(data)

class Database:
    def save(self, data):
        print(f"[DB] 写入数据库: {data}")

# 组合1：日志 + 验证 + 数据库
class App1(LogMixin, ValidateMixin, Database):
    pass

# MRO: App1 → LogMixin → ValidateMixin → Database → object

app1 = App1()
app1.save("hello")
# [LOG] Saving: hello
# [Validate] 数据验证通过
# [DB] 写入数据库: hello

# 组合2：验证 + 日志 + 数据库（顺序不同）
class App2(ValidateMixin, LogMixin, Database):
    pass

# MRO: App2 → ValidateMixin → LogMixin → Database → object

app2 = App2("hello")
app2.save("hello")
# [Validate] 数据验证通过
# [LOG] Saving: hello
# [DB] 写入数据库: hello

# 通过改变继承顺序，改变了对数据的处理顺序！
# 这就是协作式多继承的威力——每个Mixin不知道也不关心其他Mixin，
# 只是通过super()将控制权传递给MRO中的下一个
```

**实验：追踪super调用链**

```python
class TraceSuper(type):
    def __new__(mcs, name, bases, namespace):
        # 包装所有方法，追踪super调用
        for key, val in namespace.items():
            if callable(val) and not isinstance(val, (staticmethod, classmethod)):
                namespace[key] = mcs._wrap(val, name, key)
        return super().__new__(mcs, name, bases, namespace)

    @staticmethod
    def _wrap(func, cls_name, method_name):
        import functools
        @functools.wraps(func)
        def wrapper(self, *args, **kwargs):
            print(f"  → {cls_name}.{method_name}")
            result = func(self, *args, **kwargs)
            print(f"  ← {cls_name}.{method_name} done")
            return result
        return wrapper

class Base(metaclass=TraceSuper):
    def process(self):
        print("    [Base] 核心处理")
        super().process()  # 如果没有下一个有process的类，会到object

# 等等，object没有process方法——如果要演示，需要在最上层加一个终结者
class Terminator:
    def process(self):
        print("    [Terminator] 处理完成")

class Stage1(Terminator):
    def process(self):
        print("    [Stage1] 前置处理")
        super().process()

class Stage2(Stage1):
    def process(self):
        print("    [Stage2] 中间处理")
        super().process()

class Stage3(Stage2):
    def process(self):
        print("    [Stage3] 最终处理")
        super().process()

# 不用metaclass版——手动trace更清晰
class A_T:
    name = "A"
    def process(self):
        print(f"  → {self.__class__.__name__}.process (from A)")
        super().process()
        print(f"  ← return from A.process")

class B_T(A_T):
    name = "B"
    def process(self):
        print(f"  → {self.__class__.__name__}.process (from B)")
        super().process()
        print(f"  ← return from B.process")

class C_T(A_T):
    name = "C"
    def process(self):
        print(f"  → {self.__class__.__name__}.process (from C)")
        super().process()
        print(f"  ← return from C.process")

class D_T(B_T, C_T):
    name = "D"
    def process(self):
        print(f"  → {self.__class__.__name__}.process (from D)")
        super().process()
        print(f"  ← return from D.process")

print(f"D_T.__mro__ = {D_T.__mro__}")
d = D_T()
d.process()
# 输出:
#   → D_T.process (from D)
#   → D_T.process (from B)
#   → D_T.process (from C)
#   → D_T.process (from A)
#   ← return from A.process
#   ← return from C.process
#   ← return from B.process
#   ← return from D.process
#
# 注意调用和返回的嵌套关系——完全遵循MRO链！
```

## 三、描述符协议——属性访问的真正引擎

### 3.1 描述符协议定义

描述符是Python OOP中最核心、最底层的协议之一。任何在**其类型**中定义了`__get__`、`__set__`或`__delete__`的对象都是描述符。

```python
# 描述符协议：任意对象，只要其类型定义了以下方法之一
class DescriptorProtocol:
    def __get__(self, obj, objtype=None):
        """obj.x → 调用此方法
        obj: 实例（类属性访问时为None）
        objtype: 实例的类型（即 type(obj)）
        返回: 属性值"""
        ...

    def __set__(self, obj, value):
        """obj.x = value → 调用此方法
        obj: 实例
        value: 要设置的值"""
        ...

    def __delete__(self, obj):
        """del obj.x → 调用此方法
        obj: 实例"""
        ...
```

**两种描述符**：

| 类型 | 定义的协议方法 | 实例__dict__的优先级 | 典型例子 |
|------|---------------|---------------------|---------|
| **数据描述符** | `__get__` + `__set__`（或`__delete__`） | **覆盖**实例`__dict__` | `property`, `slot` |
| **非数据描述符** | 仅`__get__` | 被**实例`__dict__`覆盖** | `function`, `classmethod`, `staticmethod` |

**属性查找的完整优先级（再回顾）**：

```
obj.x 的查找过程：

1. 在 type(obj).__mro__ 中查找 'x'
   找到了？→ 检查是否是数据描述符
     是数据描述符 → 调用 descriptor.__get__(obj, type(obj))  → 返回结果
     不是数据描述符 → 继续下一步

2. 在 obj.__dict__ 中查找 'x'
   找到了？→ 直接返回 obj.__dict__['x']

3. 回到MRO中找到的项
   是非数据描述符？→ 调用 descriptor.__get__(obj, type(obj)) → 返回结果
   是普通类属性？→ 直接返回

4. 调用 type(obj).__getattr__('x')（如果定义了）

5. 抛出 AttributeError
```

这个优先级设计精妙地解释了：
- 为什么实例可以覆盖方法（方法是非数据描述符，实例`__dict__`优先）
- 为什么`property`不能被实例属性覆盖（property是数据描述符，优先级最高）
- 为什么`__slots__`属性不受实例`__dict__`影响（slot是数据描述符）

**实验：验证数据描述符与非数据描述符的优先级**

```python
class DataDesc:
    """数据描述符：同时定义 __get__ 和 __set__"""
    def __get__(self, obj, objtype=None):
        return f"DataDesc.__get__ (obj={type(obj).__name__ if obj else 'None'})"

    def __set__(self, obj, value):
        print(f"DataDesc.__set__ called with value={value}")
        obj.__dict__['_data_desc_value'] = value  # 存到实例__dict__的另一个key

class NonDataDesc:
    """非数据描述符：仅定义 __get__"""
    def __get__(self, obj, objtype=None):
        return f"NonDataDesc.__get__ (obj={type(obj).__name__ if obj else 'None'})"

class Demo:
    data_desc = DataDesc()     # 数据描述符
    non_data_desc = NonDataDesc()  # 非数据描述符

d = Demo()

# 1. 数据描述符 vs 实例 __dict__
d.__dict__['data_desc'] = "I'm in instance __dict__"
print(d.data_desc)
# DataDesc.__get__ (obj=Demo)  ← 数据描述符赢了！

# 2. 非数据描述符 vs 实例 __dict__
d.__dict__['non_data_desc'] = "I'm in instance __dict__"
print(d.non_data_desc)
# I'm in instance __dict__  ← 实例 __dict__ 赢了！

# 3. 类级别访问（obj=None）
print(Demo.data_desc)
# DataDesc.__get__ (obj=None)

print(Demo.non_data_desc)
# NonDataDesc.__get__ (obj=None)

# 总结:
# 数据描述符: 总是优先于实例 __dict__ → 可控的属性访问
# 非数据描述符: 实例 __dict__ 优先 → 实例可以覆盖（方法就是这样）
```
