# Python核心基础（四）：控制流不只是if-else——条件/循环/模式匹配全解

## 引言

在 C 中，控制流是纯粹的运动：`if` 是条件跳转（`JZ`/`JNZ`），`for` 是 `init; compare; jump; increment` 的缩写，`switch` 是编译器优化后的跳转表或级联比较——一切最终都是 GOTO 的语法糖。在 Rust 中，`match` 是穷尽的、编译器强制的分支穷举，未覆盖的模式会在编译期报错，使非法状态不可表达。在 Go 中，没有 `while`，只有 `for`——一种唯一的循环关键字承担所有语义，语言的哲学是"少一种关键字，少一种心智负担"。

Python 做了三组足够激进的决定：

1. **真值测试（truthiness）替代显式布尔表达式**：`if xs:` 而非 `if len(xs) > 0:`，`if x:` 而非 `if x != None:`。Python 让 `__bool__()`/`__len__()` 协议决定对象的真假，消除了 C 中 `if (ptr)` 与 `if (ptr != NULL)` 的风格分裂，也避免了 Java 中 `if (list)` 编译报错、必须写 `if (!list.isEmpty())` 的啰嗦。

2. **for 是纯粹的迭代器消费者**：Python 删除了 C 风格的 `for(init; cond; incr)`，`for x in iterable` 背后是 `iter()` → `__iter__()` → `next()` 循环 → `StopIteration`。这意味着 for 循环能消费任何可迭代对象——列表、文件、生成器、无限序列——而不仅仅是整数索引的范围。代价是丧失了对索引变量的直接控制力和对循环步骤的精细调度。

3. **match/case 是结构化模式匹配，不是 switch**（Python 3.10+）：Python 没有引入 C/Java 的 switch（值分派 + fall-through），而是引入了结构化模式匹配——`case [x, y, *rest]:` 能解构列表，`case Point(x=0, y=0):` 能匹配类属性，`case {"type": "error", "code": code}:` 能解构字典。这使 match 成为数据解构的工具，而不仅仅是分派表。

这三组决定的统一逻辑是：**安全性优先于控制力**。真值测试消除空值检查的遗漏风险，迭代器协议消除越界访问的运行时错误，模式匹配消除 fall-through 的语义陷阱。Python 选择了可读性和安全性，放弃了 C 级别的跳转控制力。其代价是：你无法在 Python 中写出 `for (int i = 0, j = n-1; i < j; i++, j--)` 这样的双指针循环，也无法用 `goto` 实现异常处理的替代方案。

但理解控制流，不只是知道 if-else 怎么写、for 怎么用。它是读懂 Python 运行时行为的关键：为什么 `for/else` 的 else 在循环**正常结束**时执行？为什么 `and`/`or` 返回的是决定操作数而非 `True`/`False`？为什么 `range` 不是迭代器却能在 for 中工作？为什么推导式有独立的作用域？为什么 `match` 不需要 `break`？这些问题的答案都回溯到同一个根——**Python 将控制流建立在真值协议、迭代器协议、模式匹配协议之上，而非建立在跳转指令之上**。

本文将追踪 Python 控制流从**语法糖到字节码到 CPython 内部协议**的完整路径——你将亲眼看到 `POP_JUMP_IF_FALSE` 如何实现条件分支，`FOR_ITER` 如何驱动 for 循环，`MATCH_SUBJECT` 如何启动模式匹配，以及"一切控制流都是协议"这个论断在运行时究竟意味着什么。

### 控制流的四层模型

理解 Python 控制流需要区分四个层次，从上到下逐层展开：

| 层次 | 含义 | 示例 | 可见性 |
|:---|:---|:---|:---|
| **语法层** | 程序员写的控制结构 | `if/elif/else`, `for/in`, `while`, `match/case` | 直接面对 |
| **协议层** | 控制流依赖的对象协议 | `__bool__()`, `__iter__()`/`__next__()`, `__match_args__` | 隐式调用 |
| **字节码层** | CPython 虚拟机指令 | `POP_JUMP_IF_FALSE`, `FOR_ITER`, `MATCH_SUBJECT` | `dis.dis()` |
| **C 实现层** | 评估循环中的 switch-case | `ceval.c` 中的 `TARGET(POP_JUMP_IF_FALSE)` | 源码级 |

本文会在每个主题中追踪这四层，让你看到：**语法糖 → 协议调用 → 字节码发射 → C 评估循环**，每一步的翻译是如何完成的。

## 一、条件分支——真值测试的统一哲学

### 1.1 真值测试规则

#### 1.1.1 完整的真值表

Python 的 `if` 语句不要求条件是布尔值——任意对象都可以出现在 `if` 后面，解释器通过**真值测试（truth value testing）**将其转换为 `True` 或 `False`。以下对象在布尔上下文中为假（falsy）：

| 类型 | Falsy 值 | 为什么为假 | 协议返回值 |
|:---|:---|:---|:---|
| `bool` | `False` | 布尔类型的假值 | `__bool__()` → `False` |
| `NoneType` | `None` | 空值的唯一实例 | 默认 → `True`，但单例特殊处理 |
| `int` | `0` | 零即无 | `__bool__()` → `False`（`ob_digit` 为空） |
| `float` | `0.0` | 零即无 | `__bool__()` → `False` |
| `str` | `''` | 空序列 | `__len__()` → `0` |
| `tuple` | `()` | 空序列 | `__len__()` → `0` |
| `list` | `[]` | 空序列 | `__len__()` → `0` |
| `dict` | `{}` | 空映射 | `__len__()` → `0` |
| `set` | `set()` | 空集合 | `__len__()` → `0` |
| `frozenset` | `frozenset()` | 空集合 | `__len__()` → `0` |
| `range` | `range(0)` | 空范围 | `__len__()` → `0` |
| `bytes` | `b''` | 空字节串 | `__len__()` → `0` |
| `bytearray` | `bytearray()` | 空字节数组 | `__len__()` → `0` |
| 自定义类（无 `__bool__`/`__len__`） | — | 默认为真 | 默认 → `True` |

**核心规则**：除了 `False` 和 `None`，所有 falsy 值要么是数值零（`0`, `0.0`, `0j`），要么是空容器（`__len__() == 0`）。其他一切对象默认为 truthy。

```python
# 完整的 falsy 枚举
falsy_values = [False, None, 0, 0.0, 0j, '', b'', bytearray(), (), [], {}, set(), frozenset(), range(0)]

for v in falsy_values:
    assert not v, f"{v!r} should be falsy but is truthy"

# 典型 truthy（即使"看起来像假"）
truthy_surprises = [True, 1, -1, 0.1, ' ', b' ', (None,), [0], {0}, {False}, range(1)]

for v in truthy_surprises:
    assert v, f"{v!r} should be truthy but is falsy"

print("All truth value tests passed")
```

#### 1.1.2 真值协议的三级查找：`__bool__()` → `__len__()` → 默认 True

当 Python 在布尔上下文中求值一个对象时，CPython 的 `PyObject_IsTrue()` 函数按以下顺序查找：

```
PyObject_IsTrue(v):
    1. 如果 v 是 None → return 0 (False)
    2. 如果 v->ob_type->tp_as_number->nb_bool 存在 → 调用它返回 0/1
       (对应 Python 层 __bool__())
    3. 如果 v->ob_type->tp_as_sequence->sq_length 存在 → 调用它
       若返回 0 → False; 正数 → True; 负数 → ValueError
       (对应 Python 层 __len__())
    4. 默认返回 1 (True)
```

在 CPython 源码 `object.c` 中：

```c
int PyObject_IsTrue(PyObject *v) {
    if (v == Py_None) return 0;
    PyNumberMethods *nb = Py_TYPE(v)->tp_as_number;
    if (nb && nb->nb_bool) return (*nb->nb_bool)(v);
    PySequenceMethods *sq = Py_TYPE(v)->tp_as_sequence;
    if (sq && sq->sq_length) return PySequence_Check(v) ? PyObject_Size(v) : 1;
    return 1;
}
```

**`__bool__` 优先于 `__len__`**：如果两者都定义了，Python 只调用 `__bool__`。

实验 1：自定义 `__bool__` 和 `__len__` 的优先级

```python
class Ambiguous:
    """同时定义 __bool__ 和 __len__, 观察优先级"""
    def __bool__(self):
        print("  -> __bool__ called")
        return True      # bool 说 True

    def __len__(self):
        print("  -> __len__ called")
        return 0         # len 说 0 (falsy)

obj = Ambiguous()

print("bool(obj):", end=" ")
result = bool(obj)
print(f"= {result}")     # __bool__ only → True

print("if obj:", end=" ")
if obj:
    print("truthy")      # __bool__ only → truthy
else:
    print("falsy")

# 删掉 __bool__ 后, __len__ 才会被调用
del Ambiguous.__bool__

print("bool(obj) after del __bool__:", end=" ")
result = bool(obj)
print(f"= {result}")     # __len__ → 0 → False
```

输出：
```
bool(obj):  -> __bool__ called = True
if obj:  -> __bool__ called truthy
bool(obj) after del __bool__:  -> __len__ called = False
```

#### 1.1.3 Python 选择 truthiness 的设计理由

| 语言 | 条件语句写法 | 设计理念 |
|:---|:---|:---|
| C | `if (ptr != NULL)`, `if (len > 0)` | 显式比较，但常见漏洞：`if (ptr)` 忘记 `NULL` 检查 |
| Java | `if (list.size() > 0)` | 不允许对象隐式转布尔，必须显式方法调用 |
| Rust | `if !vec.is_empty()` | 不允许隐式转换，但方法名冗长 |
| Go | `if len(slice) > 0` | 不允许隐式转换，内置 `len()` 函数 |
| **Python** | `if lst:` / `if ptr is not None:` | **truthiness 允许简洁，`is not None` 保留空值安全性** |

Python 的折中：
- **优点**：`if items:` 比 `if len(items) > 0:` 简洁，且适用于任何容器
- **优点**：`if name:` 一步检查 `None` 和空字符串
- **风险**：`if x:` 当 `x = 0` 是合法值时会产生 bug——此时应写 `if x is not None:`
- **风险**：`if items:` 无法区分 `None` 和 `[]`——当两者语义不同时应显式检查

这就是 PEP 8 推荐 "与单例比较用 `is` / `is not`" 的原因——`if x is not None:` 既保留了 truthiness 的简洁（当 `x` 为 `None` 时为假，与 `if x:` 行为一致），又排除了 `0`/`[]`/`''` 等合法 falsy 值的误判。

### 1.2 短路求值——and/or 返回决定操作数

Python 的 `and` 和 `or` 不返回 `True`/`False`——它们返回**决定表达式值的那个操作数**。这是 Python 短路求值的核心特征，也是它区别于 C/Java 的关键点。

```
a and b:
    if not a: return a     # a 为 falsy → a 决定了结果为假, 直接返回 a
    else: return b         # a 为 truthy → b 决定结果, 返回 b

a or b:
    if a: return a         # a 为 truthy → a 决定了结果为真, 直接返回 a
    else: return b         # a 为 falsy → b 决定结果, 返回 b
```

| 表达式 | 结果 | 决定操作数 | 原因 |
|:---|:---|:---|:---|
| `3 and 5` | `5` | `5` | `3` truthy → 结果由 `5` 决定 |
| `0 and 5` | `0` | `0` | `0` falsy → 短路，结果由 `0` 决定 |
| `3 or 5` | `3` | `3` | `3` truthy → 短路，结果由 `3` 决定 |
| `0 or 5` | `5` | `5` | `0` falsy → 结果由 `5` 决定 |
| `[] or "default"` | `"default"` | `"default"` | `[]` falsy → 由 `"default"` 决定 |
| `"hi" or "default"` | `"hi"` | `"hi"` | `"hi"` truthy → 短路返回 |
| `None and 42` | `None` | `None` | `None` falsy → 短路返回 |

实验 2：and/or 返回值验证

```python
# and/or 返回的是决定操作数, 不是 True/False
print(3 and 5)           # 5
print(0 and 5)           # 0
print(3 or 5)            # 3
print(0 or 5)            # 5
print([] or "default")   # "default"
print([1] or "default")  # [1]
print(None and 42)       # None

# 实际用途: 默认值模式
def greet(name=None):
    name = name or "World"
    print(f"Hello, {name}!")

greet()          # Hello, World!
greet("Python")  # Hello, Python!
greet("")        # Hello, World! — 注意: 空字符串是 falsy, 被替换了!

# 更安全的写法: 用 is not None 避免误杀合法 falsy 值
def greet_safe(name=None):
    name = name if name is not None else "World"
    print(f"Hello, {name}!")

greet_safe("")   # Hello, ! — 空字符串得以保留
```

**与 C 的对比**：C 的 `&&`/`||` 返回 `int` 型的 `0`/`1`，不是操作数本身。Python 选择返回操作数是因为它让 `or` 能作为默认值运算符、让 `and` 能作为守卫运算符（`x and x.method()`），这是 Python "表达式应该有值"哲学的体现。

### 1.3 三元表达式——`x if condition else y`

Python 的条件表达式（常被误称为"三元运算符"）语法为：

```python
value = x if condition else y
```

注意它与 C/Java 的 `condition ? x : y` 的**语法顺序不同**——条件在中间，而非前面。Python 选择的理由是：阅读顺序与自然语言一致——"`x` 如果 `condition` 否则 `y`"，当条件为真时先读到结果 `x`。

实验 3：三元表达式是表达式，不是语句

```python
# 三元表达式可以出现在任何表达式上下文中
x = 5
result = "big" if x > 3 else "small"
print(result)                     # big

# 可以嵌套, 但不要过度
score = 85
grade = "A" if score >= 90 else "B" if score >= 80 else "C"
print(grade)                      # B

# 三元表达式 vs and/or 技巧
# 旧 Python (2.4 之前) 的默认值写法: condition and x or y
# 这有 bug: 当 x 为 falsy 时会错误返回 y
condition = True
x = 0                             # falsy!
print(condition and x or "fallback")  # "fallback" — 错误!
print(x if condition else "fallback")  # 0 — 正确!
```

### 1.4 if/elif/else 的字节码

Python 的条件分支在字节码层是**条件跳转 + 无条件跳转**的组合。让我们用 `dis.dis()` 逐步分析。

#### 1.4.1 基本 if 语句

实验 4：if 语句的字节码

```python
import dis

def if_simple(x):
    if x > 0:
        return "positive"

dis.dis(if_simple)
```

输出：
```
  2           0 LOAD_FAST                0 (x)
              2 LOAD_CONST               1 (0)
              4 COMPARE_OP              67 (>)
              8 POP_JUMP_IF_FALSE        6 (to 12)   ← 条件为假则跳到末尾

  3          10 LOAD_CONST               2 ('positive')
             12 RETURN_VALUE                         ← 正常结束（隐式 return None）
```

关键指令：
- **`COMPARE_OP`**：执行比较操作，将结果（`True`/`False`）压入栈
- **`POP_JUMP_IF_FALSE`**：弹出栈顶值，如果为假则跳转到指定偏移量；否则继续执行下一条指令

#### 1.4.2 if/else 语句

实验 5：if/else 的字节码——双路跳转

```python
def if_else(x):
    if x > 0:
        return "positive"
    else:
        return "non-positive"

dis.dis(if_else)
```

输出：
```
  2           0 LOAD_FAST                0 (x)
              2 LOAD_CONST               1 (0)
              4 COMPARE_OP              67 (>)
              8 POP_JUMP_IF_FALSE        6 (to 14)   ← 假→跳到 else 分支

  3          10 LOAD_CONST               2 ('positive')
             12 RETURN_VALUE

  5          14 LOAD_CONST               3 ('non-positive')  ← else 分支入口
             16 RETURN_VALUE
```

if/else 编译为：**条件为假跳到 else 入口 → if 分支返回 → else 分支返回**。注意 if 分支因 `return` 提前退出，不需要 `JUMP_FORWARD`；如果 if 分支不是 return，则会生成 `JUMP_FORWARD` 跳过 else 块。

#### 1.4.3 if/elif/else 语句

实验 6：if/elif/else 的链式跳转

```python
def if_elif_else(x):
    if x > 0:
        return "positive"
    elif x < 0:
        return "negative"
    else:
        return "zero"

dis.dis(if_elif_else)
```

输出（简化）：
```
  2     LOAD_FAST x
        LOAD_CONST 0
        COMPARE_OP >
        POP_JUMP_IF_FALSE → (elif)
  3     LOAD_CONST 'positive'
        RETURN_VALUE

  4     LOAD_FAST x                 ← elif 入口
        LOAD_CONST 0
        COMPARE_OP <
        POP_JUMP_IF_FALSE → (else)
  5     LOAD_CONST 'negative'
        RETURN_VALUE

  7     LOAD_CONST 'zero'           ← else 入口
        RETURN_VALUE
```

if/elif/else 被编译为**级联的条件跳转链**——每个条件为假时跳到下一个分支的入口，最后一个 else 无条件执行。这与 C 的 `if/else if/else` 编译结果结构一致，但 Python 的跳转指令是**基于真值测试的**（`POP_JUMP_IF_FALSE`），而非基于整数零判断（C 的 `JZ`）。

#### 1.4.4 比较操作符的字节码

Python 3.12 中 `COMPARE_OP` 的操作码表：

| 操作码 | 操作 | 返回值 |
|:---|:---|:---|
| 2 | `==` | `__eq__` |
| 3 | `!=` | `__ne__` |
| 4 | `<` | `__lt__` |
| 5 | `<=` | `__le__` |
| 6 | `>` | `__gt__` |
| 7 | `>=` | `__ge__` |
| 8 | `in` | `__contains__` 或迭代 |
| 9 | `not in` | `not __contains__` |
| 10 | `is` | 指针比较 (`id()` 相等) |
| 11 | `is not` | 指针比较不等 |

**`is` 和 `==` 的字节码差异**：`is` 使用 `COMPARE_OP(is)` 做指针比较（`id(a) == id(b)`），而 `==` 使用 `COMPARE_OP(==)` 调用 `__eq__` 方法。这是 `is` 和 `==` 语义不同的底层根源。

### 1.5 链式比较——Python 的独有特性

Python 允许链式比较：`a < b < c` 等价于 `a < b and b < c`，但 **`b` 只被求值一次**。

实验 7：链式比较的字节码与求值次数

```python
def chained(x, y, z):
    return x < y < z

dis.dis(chained)
```

输出：
```
  2     LOAD_FAST x
        LOAD_FAST y
        COMPARE_OP <           ← x < y
        COPY 1                  ← 复制比较结果（Python 3.12+的实现可能不同）
        POP_JUMP_IF_FALSE → (end)   ← 如果 x >= y, 短路跳到末尾
        LOAD_FAST y             ← y 再次加载（但不是重新求值——y 是局部变量）
        LOAD_FAST z
        COMPARE_OP <           ← y < z
        ...（最终得到 x < y and y < z 的结果）
```

实际上，链式比较的字节码在不同版本有差异，但关键语义是不变的：

```python
# 验证 b 只被求值一次
class Tracker:
    def __init__(self, name, value):
        self.name = name
        self.value = value
    def __repr__(self):
        return f"T({self.name}={self.value})"
    def __lt__(self, other):
        print(f"  comparing {self} < {other}")
        return self.value < other.value

a, b, c = Tracker('a', 1), Tracker('b', 2), Tracker('c', 3)

print("Chained: a < b < c")
result = a < b < c
print(f"  result = {result}")

print("\nExpanded: a < b and b < c")
a2, b2, c2 = Tracker('a', 1), Tracker('b', 2), Tracker('c', 3)
result2 = a2 < b2 and b2 < c2
print(f"  result = {result2}")
```

输出：
```
Chained: a < b < c
  comparing T(a=1) < T(b=2)
  comparing T(b=2) < T(c=3)       ← b 的 __lt__ 被调用了（作为右操作数）
  result = True

Expanded: a < b and b < c
  comparing T(a=1) < T(b=2)
  comparing T(b=2) < T(c=3)       ← 一样? 不完全一样...
  result = True
```

注意：在链式比较中，**中间值** `y` 的值只被计算一次并保存在栈上，这意味着如果 `y` 是有副作用的表达式（如函数调用），链式写法和展开写法的行为**不同**：

```python
def side_effect():
    print("evaluated!")
    return 2

# 链式: side_effect() 只调用一次（中间值缓存）
result = 1 < side_effect() < 3
# 输出: evaluated! (一次)

# 展开: side_effect() 调用两次
result = 1 < side_effect() and side_effect() < 3
# 输出: evaluated! (第一次)
#       evaluated! (第二次)
```

这正是 Python 选择独立实现链式比较而非简单展开的**关键原因**——保证中间表达式只求值一次，避免副作用的不确定性。

### 1.6 条件分支的设计闭环

| 设计选择 | 协议层支撑 | 字节码实现 | 安全性保障 | 代价 |
|:---|:---|:---|:---|:---|
| truthiness 替代显式比较 | `__bool__()` → `__len__()` 协议 | `POP_JUMP_IF_FALSE` 调用 `PyObject_IsTrue()` | 消除空值检查遗漏 | `0`/`[]`/`''` 可能被误判 |
| 短路求值返回操作数 | 真值协议决定短路点 | `JUMP_IF_TRUE_OR_POP`/`JUMP_IF_FALSE_OR_POP` | 可用作默认值/守卫运算符 | 混淆 `bool(x)` 和 `x` 本身 |
| 链式比较 | 三路比较协议 | `COMPARE_OP` + 条件跳转链 | 中间值只求值一次 | 无法自定义链式语义 |
| 三元表达式 | 条件 → 选择 | `POP_JUMP_IF_FALSE` + 两条路径 | 表达式上下文可用 | 嵌套可读性差 |

## 二、循环——迭代器驱动的控制流

### 2.1 for 循环——迭代器消费者

#### 2.1.1 迭代器协议：for 循环的根基

Python 的 `for x in iterable:` 不是 C 风格的 `for(init; cond; incr)`——它背后是**迭代器协议（Iterator Protocol）**：

```
for x in iterable:
    body

↓ 等价于 ↓

iterator = iter(iterable)       # 调用 __iter__() 获取迭代器
while True:
    try:
        x = next(iterator)      # 调用 __next__() 获取下一元素
    except StopIteration:       # 迭代器耗尽
        break
    body
```

**迭代器协议的两层**：

| 层次 | 方法 | 返回值 | 作用 |
|:---|:---|:---|:---|
| **可迭代对象（Iterable）** | `__iter__()` | 返回一个迭代器 | 提供"可以被遍历"的能力 |
| **迭代器（Iterator）** | `__next__()` | 返回下一元素 / 抛出 StopIteration | 提供"逐个取出元素"的能力 |
| **迭代器自身** | `__iter__()` | 返回 `self` | 迭代器也是可迭代对象（for 可以嵌套） |

实验 8：手动展开 for 循环

```python
# 用迭代器协议手动模拟 for 循环
lst = [1, 2, 3]

# === 标准写法 ===
for x in lst:
    print(x, end=" ")
print()   # 1 2 3

# === 手动展开 ===
it = iter(lst)              # lst.__iter__() → list_iterator 对象
while True:
    try:
        x = next(it)        # it.__next__() → 取下一元素
    except StopIteration:   # 迭代器耗尽 → 退出
        break
    print(x, end=" ")
print()   # 1 2 3

# === 验证: 迭代器是一次性消费品 ===
it2 = iter(lst)
print(list(it2))   # [1, 2, 3] — 消费完毕
print(list(it2))   # [] — 迭代器已耗尽, 再次迭代为空

# === 验证: 列表本身可以重复迭代 ===
print(list(lst))   # [1, 2, 3]
print(list(lst))   # [1, 2, 3] — lst 每次返回新迭代器
```

#### 2.1.2 for 循环的字节码

实验 9：for 循环的完整字节码

```python
import dis

def for_loop(items):
    total = 0
    for x in items:
        total += x
    return total

dis.dis(for_loop)
```

输出（Python 3.12 格式，简化）：
```
  2     0 RESUME                   0
        2 LOAD_CONST               0 (0)
        4 STORE_FAST               1 (total)

  3     6 LOAD_FAST                0 (items)
        8 GET_ITER                              ← iter(items), 获取迭代器
       10 FOR_ITER                6 (to 24)     ← 尝试 next(), 有值则继续, 耗尽则跳到 24
       12 STORE_FAST               2 (x)        ← x = next(iterator)

  4    14 LOAD_FAST                1 (total)
       16 LOAD_FAST                2 (x)
       18 BINARY_OP               13 (+=)       ← total += x
       22 STORE_FAST               1 (total)
       24 JUMP_BACKWARD            8 (to 10)    ← 跳回 FOR_ITER

  5    26 LOAD_FAST                1 (total)    ← 循环结束后继续
       28 RETURN_VALUE
```

关键指令解析：

| 字节码 | 作用 | C 层面 |
|:---|:---|:---|
| `GET_ITER` | `TOS = iter(TOS)` — 对栈顶可迭代对象调用 `__iter__()` | 调用 `PyObject_GetIter()` → `tp_iter` 槽位 |
| `FOR_ITER` | 如果栈顶迭代器有下一元素：`next()` 压入栈顶，继续；如果耗尽（`StopIteration`）：弹出迭代器，跳转到目标偏移 | 调用 `__next__()` → 捕获 `StopIteration` |
| `STORE_FAST` | 将栈顶值存入局部变量 | 直接写入栈帧的 `f_localsplus` 数组 |
| `JUMP_BACKWARD` | 无条件跳回循环头部 | 修改帧的 `f_lasti`（上次指令偏移） |

**FOR_ITER 的精妙之处**：它将 `next()` 调用 + `StopIteration` 捕获合并为单条指令。在 C 层面，`FOR_ITER` 直接调用迭代器的 `tp_iternext` 槽位（比通用的 `PyObject_CallMethod` 快得多），且 `StopIteration` 的捕获不需要走完整的异常处理路径（setjmp/longjmp），而是直接检查返回值是否为 NULL。

#### 2.1.3 for 不是 C 风格循环——设计理由

| 特性 | C 风格 for | Python for |
|:---|:---|:---|
| 循环变量 | 整数索引 `i` | 迭代产生的元素 `x` |
| 循环条件 | 表达式 `i < n` | 迭代器返回 `StopIteration` |
| 步进 | `i++` / `i += 2` | 由迭代器决定 |
| 适用范围 | 连续索引的数组/随机访问 | **任何可迭代对象** |
| 越界风险 | 有（`i` 可被误修改） | 无（迭代器自动终止） |
| 文件遍历 | 需要手动行计数 | `for line in file:` |
| 无限序列 | 不可能 | `for x in itertools.count():` |

Python 删除 C 风格 for 的收益：
1. **消除越界错误**：`for x in lst` 不可能访问 `lst[10]` 当 `lst` 只有 5 个元素
2. **统一遍历接口**：列表、字典、文件、生成器、数据库游标 全部用同一个 `for x in obj:` 遍历
3. **支持惰性序列**：生成器可以无限产生元素，C 风格 for 需要预知终止条件
4. **语义更清晰**：`for line in file:` 比 `for (int i = 0; i < line_count; i++) { line = file[i]; }` 更贴近意图

代价：
1. 无法直接获取索引（需 `enumerate()`）
2. 无法同时遍历两个序列的同位元素（需 `zip()`）
3. 无法在循环体中安全修改迭代变量来跳步（需 `itertools.islice` 等工具）

### 2.2 while 循环——条件驱动的重复

#### 2.2.1 while 的字节码

while 循环比 for 简单——它只依赖条件表达式的真值测试，不涉及迭代器协议。

实验 10：while 循环的字节码

```python
def while_loop(n):
    total = 0
    while n > 0:
        total += n
        n -= 1
    return total

dis.dis(while_loop)
```

输出（简化）：
```
  2     LOAD_CONST 0
        STORE_FAST total

  3     LOAD_FAST n               ← 条件求值开始
        LOAD_CONST 0
        COMPARE_OP >
        POP_JUMP_IF_FALSE → (end) ← 条件为假 → 跳出循环

  4     LOAD_FAST total
        LOAD_FAST n
        BINARY_OP +=
        STORE_FAST total

  5     LOAD_FAST n
        LOAD_CONST 1
        BINARY_OP -=
        STORE_FAST n
        JUMP_BACKWARD → (条件)    ← 跳回条件求值

  7     LOAD_FAST total
        RETURN_VALUE
```

while 循环的字节码结构是：**条件求值 → 条件跳转 → 循环体 → 无条件跳回**。与 for 不同，while 没有迭代器创建/销毁的开销，也没有 `FOR_ITER` 指令。

#### 2.2.2 while vs for——何时用哪个

| 场景 | 推荐 | 原因 |
|:---|:---|:---|
| 遍历序列/容器的元素 | `for` | 语义更清晰，不可能越界 |
| 已知迭代次数 | `for` + `range`/`enumerate` | 代码更紧凑 |
| 未知迭代次数（如等待用户输入、网络响应） | `while` | 条件驱动更自然 |
| 需要复杂的循环条件 | `while` | 条件可以是任意表达式 |
| 遍历文件/生成器 | `for` | 自动处理 `StopIteration` |
| 实现"至少执行一次"的循环 | `while True` + `break` | Python 没有 `do-while`（3.11+ 有 `while` + `if/break` 惯用法） |

### 2.3 break/continue/else——精确控制

#### 2.3.1 break——BREAK_LOOP

`break` 立即跳出**最内层**循环。在字节码层面，Python 3.12 之前使用 `BREAK_LOOP`，3.12+ 中 break 被编译为跳转到循环结束位置的 `JUMP_FORWARD`/`JUMP_BACKWARD`。

实验 11：break 的字节码

```python
def break_demo(nums):
    for x in nums:
        if x < 0:
            break
        print(x)
    print("done")

dis.dis(break_demo)
```

输出中，`break` 被编译为跳转到循环结束后第一条指令的跳转——不再有专门的 `BREAK_LOOP` 字节码，而是一个计算好偏移量的无条件跳转。

**break 只跳出最内层循环**——这是 Python 的硬约束，没有 `break 2` 或 `goto` 的等价写法。

#### 2.3.2 continue——跳到下一次迭代

`continue` 跳过当前迭代的剩余语句，回到循环的条件检查/下一次迭代。

实验 12：continue 在 for 和 while 中的行为

```python
# for 中的 continue: 跳回 FOR_ITER (取下一元素)
def continue_for(nums):
    for x in nums:
        if x < 0:
            continue        # 跳回 FOR_ITER
        print(x)

# while 中的 continue: 跳回条件求值
def continue_while(n):
    while n > 0:
        n -= 1
        if n % 3 == 0:
            continue        # 跳回 while n > 0
        print(n)

# 经典陷阱: while + continue + 计数器
def continue_bug():
    n = 5
    while n > 0:
        if n == 3:
            continue        # BUG! n 没有递减, 死循环
        n -= 1
        print(n)

# continue_bug()  ← 不要运行! 死循环!
```

**continue 的常见陷阱**：在 `while` 循环中，`continue` 跳回条件求值，如果计数器递增/递减语句在 `continue` 之后，就会被跳过，导致死循环。for 循环没有这个问题——`FOR_ITER` 自动推进迭代器。

#### 2.3.3 else 子句——循环的最被误解特性

Python 的 `for/else` 和 `while/else` 中，**else 子句在循环正常完成时执行（没有被 break 中断时）**。

这是 Python 最被误解的特性之一。Python 之父 Guido van Rossum 曾解释：else 的语义来自"循环 + break"的完整控制流——如果循环有 break（表示"在某种条件下提前退出"），else 就是没有触发那个条件的"否则"分支。

```
for x in iterable:
    if found(x):
        process(x)
        break           ← "如果找到了, 就处理并退出"
else:
    handle_not_found()  ← "否则(没有找到), 执行这个"
```

实验 13：for/else 的行为

```python
# 场景1: 没有 break → else 执行
print("=== 没有 break ===")
for i in range(3):
    print(i, end=" ")
else:
    print("\nelse executed")    # else executed

# 场景2: 有 break → else 不执行
print("\n=== 有 break ===")
for i in range(3):
    if i == 1:
        break
    print(i, end=" ")
else:
    print("\nelse executed")    # 不会执行!
print("(break happened)")

# 场景3: 空迭代 → else 执行
print("\n=== 空迭代 ===")
for i in []:
    print(i)
else:
    print("else on empty")     # else on empty

# 场景4: while/else
print("\n=== while/else ===")
n = 5
while n > 0:
    n -= 1
    if n == 0:
        break
else:
    print("while else")        # 不会执行
print(f"n = {n}")

# 实际用途: 搜索 + 未找到处理
def find_first_negative(nums):
    for x in nums:
        if x < 0:
            return x
    else:
        return None            # 没有 break → 没找到负数

print(find_first_negative([1, 2, 3]))    # None
print(find_first_negative([1, -2, 3]))   # -2
```

**else 什么时候不执行？**——仅当循环被 `break` 中断时。`continue` 不影响 else 的执行——else 只关心"有没有 break"。

#### 2.3.4 嵌套循环中的 break——只退出一层

Python 的 `break` 只退出最内层循环。要退出多层循环，有三种惯用法：

实验 14：多层 break 的方案

```python
# 方案1: 使用标志变量
def multi_break_flag(matrix, target):
    found = False
    for i, row in enumerate(matrix):
        for j, val in enumerate(row):
            if val == target:
                print(f"Found at ({i}, {j})")
                found = True
                break          # 只退出内层
        if found:
            break              # 退出外层

# 方案2: 使用 else + 条件（更 Pythonic）
def multi_break_else(matrix, target):
    for i, row in enumerate(matrix):
        for j, val in enumerate(row):
            if val == target:
                print(f"Found at ({i}, {j})")
                break
        else:
            continue           # 内层没 break → 继续外层
        break                  # 内层 break 了 → 退出外层

# 方案3: 使用异常（最灵活, 但最不常用）
class Found(Exception):
    pass

def multi_break_exception(matrix, target):
    try:
        for i, row in enumerate(matrix):
            for j, val in enumerate(row):
                if val == target:
                    raise Found(i, j)
    except Found as e:
        print(f"Found at {e.args}")

# 方案3b: 使用生成器（最 Pythonic）
def multi_break_generator(matrix, target):
    for i, j, val in ((i, j, v) for i, row in enumerate(matrix) for j, v in enumerate(row)):
        if val == target:
            return (i, j)
    return None

# 方案3c: 使用 itertoolstakewhile / product
from itertools import product
def multi_break_product(matrix, target):
    for i, j in product(range(len(matrix)), range(len(matrix[0]))):
        if matrix[i][j] == target:
            return (i, j)
    return None

matrix = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
multi_break_else(matrix, 5)   # Found at (1, 1)
```

**方案2（for/else + continue + break）是最 Pythonic 的多层 break 写法**——它巧妙利用了 else 子句的语义："内层正常结束"意味着"没找到目标"，这时 `continue` 继续外层；"内层 break"意味着"找到了目标"，这时跳过 else，执行外层 `break`。

### 2.4 range——不是迭代器，是惰性序列

`range` 是 Python 中最常被误解的对象之一。很多人认为 `range` 返回一个迭代器——它**不是**。

#### 2.4.1 range 是序列，不是迭代器

| 属性 | 迭代器（如 `iter([1,2,3])`） | `range` 对象 |
|:---|:---|:---|
| 可重复迭代？ | 否（一次性消费） | **是**（每次 `iter()` 返回新迭代器） |
| `__contains__` | 无（需遍历） | **有**（O(1) 数学计算） |
| `__len__` | 无 | **有**（预计算） |
| `__getitem__` | 无 | **有**（支持索引访问） |
| `__reversed__` | 无 | **有**（支持 `reversed()`） |
| 可拼接/切片 | 否 | 3.12+ 支持 `range` 切片（部分实现） |

实验 15：range 不是迭代器

```python
r = range(5)

# 关键证据1: range 可以重复迭代
print(list(r))   # [0, 1, 2, 3, 4]
print(list(r))   # [0, 1, 2, 3, 4] — 迭代器第二次应为 []!
print(list(iter([1,2,3])))   # [1, 2, 3]
print(list(iter([1,2,3])))   # [1, 2, 3] — 列表本身也是可重复迭代

# 区别: 迭代器 vs 可迭代对象
it = iter(r)
print(type(it))  # <class 'range_iterator'> — 这才是迭代器
print(list(it))  # [0, 1, 2, 3, 4]
print(list(it))  # [] — 迭代器耗尽了

# 关键证据2: range 有 __contains__ (O(1))
import time
start = time.time()
result = 10**9 in range(10**10)     # O(1) — 数学检查, 不遍历!
elapsed = time.time() - start
print(f"10**9 in range(10**10) = {result}, elapsed = {elapsed:.6f}s")
# result = True, elapsed ≈ 0.000001s

start = time.time()
result = 10**9 in list(range(10**7))    # O(n) — 线性遍历!
elapsed = time.time() - start
print(f"10**9 in list(range(10**7)) = {result}, elapsed = {elapsed:.4f}s")

# 关键证据3: range 有 __len__ 和 __getitem__
print(len(range(10, 20, 3)))   # 4 — 预计算: ceil((20-10)/3) = 4
print(range(10, 20, 3)[2])    # 16 — start + 2*step = 10 + 6 = 16
print(range(10, 20, 3)[-1])   # 19 — 倒数第一个
```

#### 2.4.2 range 的 `__contains__` 如何实现 O(1) 检查

range 的 `__contains__` 不遍历元素——它做数学判断：

```python
# range(start, stop, step).__contains__(x) 的等价逻辑:
def range_contains(start, stop, step, x):
    if step > 0:
        if not (start <= x < stop):
            return False
    else:
        if not (stop < x <= start):
            return False
    # 检查 (x - start) 是否能被 step 整除
    return (x - start) % step == 0
```

所以 `10**9 in range(10**10)` 只需要做：`0 <= 10**9 < 10**10` → True，`(10**9 - 0) % 1 == 0` → True。两步算术，与 range 大小无关。

#### 2.4.3 range 的内部结构

CPython 中 `range` 对象的 C 结构体：

```c
typedef struct {
    PyObject_HEAD                   // ob_refcnt + ob_type (16B)
    PyObject *start;                // 起始值 (PyLongObject*)
    PyObject *stop;                 // 终止值
    PyObject *step;                 // 步长
    PyObject *length;               // 预计算的长度 (ceil((stop-start)/step))
    // ... (hash 缓存等)
} rangeobject;
```

**关键设计**：`length` 在创建时预计算，存储为 `PyLongObject*`（支持任意大整数）。这意味着 `len(range(10**100))` 不会溢出也不会遍历，直接返回已存储的值。

#### 2.4.4 为什么 Python 3 用 range 替代 xrange

Python 2 有 `range()`（返回 `list`）和 `xrange()`（返回惰性对象）。Python 3 将 `xrange()` 重命名为 `range()`，删除了 `list` 版本。

| Python 2 `range()` | Python 2 `xrange()` | Python 3 `range()` |
|:---|:---|:---|
| 返回 `list` | 返回惰性对象 | 返回惰性序列 |
| 内存 O(n) | 内存 O(1) | 内存 O(1) |
| 支持 `__contains__`（O(n)遍历） | 无 `__contains__` | 支持 `__contains__`（O(1)数学） |
| 支持 `__getitem__` | 无 `__getitem__` | 支持 `__getitem__` |
| 支持切片、拼接 | 不支持 | 3.12+ 部分支持 |

Python 3 的 `range` = Python 2 `xrange` 的惰性 + 完整序列协议。这是一个"零缺点"的设计升级——`range` 既不预分配内存（惰性），又支持所有序列操作（O(1) `__contains__`、`__len__`、`__getitem__`），使得 `range(10**10)` 安全可用。

### 2.5 循环的设计闭环

| 设计选择 | 协议层支撑 | 字节码实现 | 安全性保障 | 代价 |
|:---|:---|:---|:---|:---|
| for 消除 C 风格循环 | `__iter__()`/`__next__()` 协议 | `GET_ITER` + `FOR_ITER` + `JUMP_BACKWARD` | 消除越界错误 | 无直接索引控制 |
| while 条件驱动 | 真值协议（`__bool__`/`__len__`） | `LOAD` + `COMPARE_OP` + `POP_JUMP_IF_FALSE` | 条件清晰显式 | continue 可能跳过计数器 |
| else 子句 | 循环中断标记 | `else` 块 > `JUMP_FORWARD`(break时) | 搜索+未找到模式简洁 | 语义反直觉 |
| break 只退一层 | 字节码跳转范围限于当前循环 | 跳转到当前循环的结束偏移 | 避免意外跳出 | 多层退出需额外机制 |
| range 惰性序列 | 序列协议（`__len__`+`__getitem__`+`__contains__`） | 不涉及（range 是数据对象） | 大范围安全，O(1) 成员检查 | 无法拼接/切片（3.12 前） |

## 三、模式匹配——结构化解构（Python 3.10+）

### 3.1 match/case 语法——不只是 switch

Python 3.10 引入的 `match/case` 是**结构化模式匹配（Structural Pattern Matching）**，不是 C/Java 的 `switch/case`。两者的本质区别：

| 特性 | C/Java `switch` | Python `match/case` |
|:---|:---|:---|
| 匹配基础 | **值**相等（整数、字符串、枚举） | **结构**匹配（值、序列、映射、类） |
| fall-through | **默认 fall-through**（需手动 `break`） | **无 fall-through**（每个 case 自带隐式 break） |
| 变量绑定 | 无 | **有**——`case [x, y]:` 将匹配值绑定到 `x`, `y` |
| 守卫条件 | 无 | **有**——`case x if x > 0:` |
| 穷尽检查 | 无（编译器不报错） | **部分**（解释器对常见遗漏发出警告） |
| 解构能力 | 无 | **有**——嵌套结构递归解构 |
| OR 模式 | 无（需连续 case + fall-through） | **有**——`case "a" \| "b":` |

### 3.1.1 字面模式——值匹配

最简单的模式，等价于 `if x == value`：

```python
def http_status(status):
    match status:
        case 200:
            return "OK"
        case 404:
            return "Not Found"
        case 500:
            return "Internal Server Error"
        case _:                     # _ 是通配符, 匹配一切
            return "Unknown"
```

### 3.1.2 变量捕获——解构绑定

case 中的**小写名字**是变量捕获，不是值比较：

```python
def greet(point):
    match point:
        case (0, 0):
            print("Origin")
        case (0, y):               # y 是变量捕获!
            print(f"Y-axis at y={y}")
        case (x, 0):
            print(f"X-axis at x={x}")
        case (x, y):               # x, y 都是变量捕获
            print(f"Point at ({x}, {y})")

greet((0, 5))    # Y-axis at y=5
greet((3, 4))   # Point at (3, 4)
```

**关键区别**：`case (0, 0):` 中的 `0` 是字面值（匹配相等），而 `case (0, y):` 中的 `y` 是变量（捕获值）。Python 通过大小写区分：小写 = 变量捕获，大写/带点的 = 常量值（`case MyEnum.A:`）。

### 3.1.3 OR 模式——多值合一

```python
def is_weekend(day):
    match day:
        case "Saturday" | "Sunday":
            return True
        case "Monday" | "Tuesday" | "Wednesday" | "Thursday" | "Friday":
            return False
        case _:
            raise ValueError(f"Unknown day: {day}")
```
