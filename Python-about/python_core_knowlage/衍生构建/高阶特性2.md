#### TypeVar 和 Generic——用户定义泛型

```python
from typing import TypeVar, Generic, List

T = TypeVar('T')  # 类型变量

class Stack(Generic[T]):

        self._items: List[T] = []

        self._items.append(item)

        return self._items.pop()

# 实例化时指定类型

str_stack.push("hello")
```

### 2.3 PEP 563——延迟注解求值

**问题:前向引用(Forward Reference)**:

```python
# 这会报错!Node 还未定义
def bad_example(node: Node) -> Node:
    return node

class Node:
    pass

# 传统解决方案:字符串注解
def good_example(node: 'Node') -> 'Node':
    return node
```

**PEP 563 解决方案:`from __future__ import annotations`**:

```python
from __future__ import annotations  # Python 3.7+

# 现在可以直接使用未定义的类型
def process(node: Node) -> Node:
    return node

class Node:
    value: int
    next: Node  # 自引用

# 但访问 __annotations__ 时得到的是字符串!
print(Node.__annotations__)
# {'value': 'int', 'next': 'Node'}  ← 字符串,不是类型对象
```

**解决:`typing.get_type_hints`**:

```python
import typing

# 解析字符串注解为真实类型

print(hints)  # {'value': <class 'int'>, 'next': <class '__main__.Node'>}
```

**PEP 649(Python 3.13 计划):惰性求值**:

```python
# Python 3.13 中,__annotations__ 是一个描述符
# 访问时才求值,无需 get_type_hints

# 实验模拟
class LazyAnnotations:
    """模拟 PEP 649 的惰性注解"""
    def __init__(self, raw_annotations, globals_ns):
        self._raw = raw_annotations
        self._globals = globals_ns
    
    def __getitem__(self, key):
        value = self._raw[key]
        if isinstance(value, str):
            # 惰性求值
            return eval(value, self._globals)
        return value
```

### 2.4 注解 vs 装饰器——设计差异

| 维度 | 注解(Annotations) | 装饰器(Decorators) |
|:---|:---|:---|
| **定义** | `def f(x: T):` | `@decorator def f():` |
| **执行时机** | 编译时解析,存储在 `__annotations__` | 定义时立即执行(`f = decorator(f)`) |
| **运行时影响** | 无(零开销,只是字典) | 可能完全改变函数行为 |
| **用途** | 文档、静态分析、IDE 提示、序列化 | 行为修改、注册、包装、元编程 |
| **可组合性** | 相加(多个注解存入同一字典) | 相乘/堆叠(多次包装) |
| **工具链依赖** | 需要 mypy/pyright 等外部工具 | Python 运行时原生执行 |

**注解 + 装饰器协同——运行时类型检查**:

```python
import functools
from typing import get_type_hints, Any

def validate_types(func):
    """装饰器:运行时验证类型注解"""
    hints = get_type_hints(func)
    
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        # 获取参数名
        param_names = func.__code__.co_varnames[:func.__code__.co_argcount]
        
        # 检查位置参数
        for name, value in zip(param_names, args):
            if name in hints:
                expected_type = hints[name]
                if not isinstance(value, expected_type):
                    raise TypeError(
                        f"参数 {name} 期望类型 {expected_type.__name__},"
                        f"实际类型 {type(value).__name__}"
                    )
        
        # 检查关键字参数
        for name, value in kwargs.items():
            if name in hints and name != 'return':
                expected_type = hints[name]
                if not isinstance(value, expected_type):
                    raise TypeError(
                        f"参数 {name} 期望类型 {expected_type.__name__},"
                        f"实际类型 {type(value).__name__}"
                    )
        
        # 调用函数
        result = func(*args, **kwargs)
        
        # 检查返回值
        if 'return' in hints:
            expected_type = hints['return']
            if not isinstance(result, expected_type):
                raise TypeError(
                    f"返回值期望类型 {expected_type.__name__},"
                    f"实际类型 {type(result).__name__}"
                )
        return result
    
    return wrapper

@validate_types
def divide(a: int, b: int) -> float:
    return a / b

# 测试
print(divide(10, 2))  # OK: 5.0
# print(divide("10", 2))  # TypeError: 参数 a 期望类型 int,实际类型 str
```

### 3.1 f-string 语法全面解析

### 3.2 f-string 的编译期实现——FORMAT_VALUE 字节码

f-string 不是运行时的字符串拼接,而是**编译为专门的字节码指令**。

**实验 4:对比 f-string、format()、% 的字节码**:

```python
import dis

# 三种格式化方式
code_fstring = compile('f"{x + y}"', '<string>', 'eval')
code_format = compile('"{x + y}".format(x=1, y=2)', '<string>', 'eval')
code_percent = compile('"%s" % (x + y,)', '<string>', 'eval')

print("=== f-string 字节码 ===")
dis.dis(code_fstring)

print("\n=== str.format() 字节码 ===")
dis.dis(code_format)

print("\n=== % 格式化字节码 ===")
dis.dis(code_percent)
```

**输出(简化)**:

```
=== f-string 字节码 ===
  1           0 LOAD_NAME                0 (x)
              2 LOAD_NAME                1 (y)
              4 BINARY_ADD
              6 FORMAT_VALUE             0    ← 专用指令!
              8 RETURN_VALUE

=== str.format() 字节码 ===
  1           0 LOAD_CONST               0 ('{x + y}')
              2 LOAD_METHOD              0 (format)
              4 LOAD_CONST               1 (1)
              6 LOAD_CONST               2 (2)
              8 BUILD_MAP                2
             10 CALL_METHOD              1
             12 RETURN_VALUE

=== % 格式化字节码 ===
  1           0 LOAD_CONST               0 ('%s')
              2 LOAD_NAME                0 (x)
              4 LOAD_NAME                1 (y)
              6 BINARY_ADD
              8 BUILD_TUPLE              1
             10 BINARY_MODULO
             12 RETURN_VALUE
```

**关键发现**:

1. **f-string 使用专用指令 `FORMAT_VALUE`**——一步完成求值+格式化+转换
2. **`str.format()` 需要方法调用**——`LOAD_METHOD` + `CALL_METHOD`
3. **`%` 格式化使用 `BINARY_MODULO`**——二元运算符

**FORMAT_VALUE 指令的操作数格式**:

```python
# FORMAT_VALUE 的操作数是一个标志字节
# 位 0-1: 转换标志 (0: 无, 1: !s, 2: !r, 3: !a)
# 位 2-7: 格式规范在常量池中的索引

import dis

# 无转换
code1 = compile('f"{x}"', '<string>', 'eval')
# FORMAT_VALUE 0

# !r 转换
code2 = compile('f"{x!r}"', '<string>', 'eval')
# FORMAT_VALUE 2  ← 转换标志 = 2 (repr)

# 带格式规范
code3 = compile('f"{x:.2f}"', '<string>', 'eval')
# FORMAT_VALUE 4  ← 格式规范索引 + 转换标志
```

**性能对比实验**:

```python

setup = "x = 3.14159; y = 2.71828"

# 三种格式化方式

print(f"format():  {t_format:.3f}s")
print(f"%:         {t_percent:.3f}s")

print(f"f-string 比 % 快 {t_percent / t_fstring:.2f} 倍")
```

**典型输出**:

```

%:         3.567s
```

### 3.3 格式规范详解

f-string 的格式规范与 `str.format()` 完全相同,遵循格式字符串迷你语言(Format String Mini-Language)。

**完整格式规范语法**:

```
[[fill]align][sign][#][0][width][grouping_option][.precision][type]

fill:        填充字符(默认空格)
align:       <(左对齐) | >(右对齐) | ^(居中) | =(符号后填充)
sign:        +(总是显示符号) | -(仅负数显示符号) | space(正数前加空格)
#:           备用形式(二进制、八进制、十六进制加前缀)
0:           用 0 填充(等价于 align='=' 和 fill='0')
width:       最小宽度
grouping:    ,(逗号) | _(下划线)
precision:   小数位数或字符串最大长度
type:        b/d/o/x/X/e/E/f/F/g/G/n/s/%
```

**示例大全**:

```python
import math

value = 1234.56789

# 对齐
print(f"|{value:<15}|")  # |1234.56789     |  左对齐
print(f"|{value:>15}|")  # |     1234.56789|  右对齐
print(f"|{value:^15}|")  # |  1234.56789  |  居中
print(f"|{value:*=15}|")  # |***1234.56789**|  自定义填充

# 符号
print(f"{value:+.2f}")  # +1234.57
print(f"{-value:+.2f}")  # -1234.57
print(f"{value: .2f}")  #  1234.57  (正数前空格)

# 千位分隔符
print(f"{value:,.2f}")  # 1,234.57
print(f"{value:_.2f}")  # 1_234.57

# 精度
print(f"{value:.2f}")  # 1234.57  (小数点后 2 位)
print(f"{value:.0f}")  # 1235  (四舍五入到整数)
print(f"{'hello':.3}")  # hel  (字符串截断)

# 科学计数法
print(f"{value:e}")  # 1.234568e+03
print(f"{value:.2e}")  # 1.23e+03
print(f"{value:E}")  # 1.234568E+03

# 通用格式(自动选择 f 或 e)
print(f"{value:g}")  # 1234.57  (大数字自动转换)
print(f"{0.000001:g}")  # 1e-06

# 百分比
print(f"{0.856:.2%}")  # 85.60%

# 进制
n = 42
print(f"{n:b}")  # 101010  (二进制)
print(f"{n:#b}")  # 0b101010  (带前缀)
print(f"{n:o}")  # 52  (八进制)
print(f"{n:#o}")  # 0o52
print(f"{n:x}")  # 2a  (十六进制)
print(f"{n:#x}")  # 0x2a
```

## 四、常见陷阱

### 陷阱 1:装饰器未使用 functools.wraps 导致函数身份丢失

**问题**:

```python
def bad_decorator(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@bad_decorator
def important_function(x):
    """这是重要的文档"""
    return x ** 2

# 问题:原始函数的信息丢失
print(important_function.__name__)  # "wrapper",不是 "important_function"
print(important_function.__doc__)   # None,不是 "这是重要的文档"

# 后果:
# 1. 调试时看到 wrapper 而非原函数名
# 2. pickle 序列化可能失败
# 3. 类型检查器丢失类型信息
# 4. help() 显示错误信息
```

**解决方案**:

```python
import functools

def good_decorator(func):
    @functools.wraps(func)  # ← 关键
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@good_decorator
def important_function(x):
    """这是重要的文档"""
    return x ** 2

print(important_function.__name__)  # "important_function" ✓
print(important_function.__doc__)   # "这是重要的文档" ✓
```

### 陷阱 2:类型注解 ≠ 运行时类型检查

**问题**:

```python
def add(a: int, b: int) -> int:
    """类型注解提示整数加法"""
    return a + b

# 运行时不强制类型!
result = add("hello", " world")  # 不报错,返回 "hello world"
```

### 题目 1:实现 `@retry` 装饰器工厂

**要求**:实现一个装饰器 `@retry(max_attempts, delay=1)`,在函数抛出异常时重试,达到最大次数后抛出最后一次异常。

**解答**:

```python
import functools
import time

def retry(max_attempts, delay=1):
    """重试装饰器
    
    Args:
        max_attempts: 最大尝试次数(包括第一次)
        delay: 每次重试之间的延迟(秒)
    """
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last_exception = None
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    last_exception = e
                    if attempt < max_attempts:
                        print(f"[{func.__name__}] 第 {attempt} 次失败,{delay}秒后重试...")
                        time.sleep(delay)
                    else:
                        print(f"[{func.__name__}] 达到最大重试次数 {max_attempts},放弃")
            raise last_exception
        return wrapper
    return decorator

# 测试
import random

@retry(3, delay=0.1)
def unstable_function():
    """模拟不稳定的函数"""
    if random.random() < 0.7:
        raise ValueError("随机失败!")
    return "成功"

try:
    result = unstable_function()
    print(f"最终结果: {result}")
except ValueError as e:
    print(f"最终失败: {e}")
```

### 题目 2:解释输出

**代码**:

```python
def trace(func):
    def wrapper(*args, **kwargs):
        print(f"Call {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@trace
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(3))
```

**问题**:输出是什么?为什么?

**答案**:

```
Call fib
Call fib
Call fib
Call fib
Call fib
Call fib
Call fib
3
```

**原因**:`fib` 在装饰后被重新绑定为 `wrapper`,所以**递归调用也经过装饰器**。每次递归都打印 "Call fib"。

**如果不想递归调用经过装饰器**:

```python
def trace_non_recursive(func):
    def wrapper(*args, **kwargs):
        print(f"Call {func.__name__}")
        return func(*args, **kwargs)  # 调用原始函数
    wrapper.__wrapped__ = func  # 保留原函数引用
    return wrapper

@trace_non_recursive
def fib(n):
    if n < 2:
        return n
    return fib.__wrapped__(n - 1) + fib.__wrapped__(n - 2)  # 显式调用原函数
```

### 题目 3:实现类型安全的装饰器工厂

**要求**:实现 `@validate_args`,自动验证参数类型和返回值类型。

**解答**:

```python
import functools
from typing import get_type_hints, Any

def validate_args(func):
    """验证参数和返回值类型的装饰器"""
    hints = get_type_hints(func)
    sig = functools.signature(func)
    
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        # 绑定参数
        bound = sig.bind(*args, **kwargs)
        bound.apply_defaults()
        
        # 验证参数类型
        for name, value in bound.arguments.items():
            if name in hints and name != 'return':
                expected = hints[name]
                if not isinstance(value, expected):
                    raise TypeError(
                        f"参数 '{name}' 期望类型 {expected.__name__},"
                        f"实际类型 {type(value).__name__}"
                    )
        
        # 调用函数
        result = func(*args, **kwargs)
        
        # 验证返回值类型
        if 'return' in hints:
            expected = hints['return']
            if not isinstance(result, expected):
                raise TypeError(
                    f"返回值期望类型 {expected.__name__},"
                    f"实际类型 {type(result).__name__}"
                )
        return result
    
    return wrapper

# 测试
@validate_args
def safe_divide(a: int, b: int) -> float:
    if b == 0:
        raise ValueError("除零错误")
    return a / b

print(safe_divide(10, 2))  # 5.0
# print(safe_divide("10", 2))  # TypeError: 参数 'a' 期望类型 int,实际类型 str
# print(safe_divide(10, 2.0))  # TypeError: 参数 'b' 期望类型 int,实际类型 float
```

## 六、Pythonic代码的解释力——15个疑惑统一回溯

| 疑惑 | 根因 | 回溯路径 |
|:---|:---|:---|
| **1. 为什么装饰器必须返回可调用对象?** | 装饰器是高阶函数变换 | `@d def f():` → `f = d(f)`,`f()` 必须能调用 → `d(f)` 必须可调用 |
| **2. 为什么 `@functools.wraps` 如此重要?** | 函数对象携带元数据(`__name__`、`__doc__`等) | 装饰器返回新函数 → 新函数是独立对象 → 元数据丢失 → `wraps` 复制原函数元数据到新函数 |
| **3. 为什么类型注解不影响性能?** | 注解只是 `__annotations__` 字典 | 编译时存入字典 → 运行时不读取 → 无额外开销 |
| **4. 为什么 `mypy` 是必需的?** | Python 运行时不强制类型 | 注解是契约,不是约束 → 需要外部工具 enforce → `mypy` 静态分析填补空白 |
| **5. 为什么 f-string 最快?** | 编译为 `FORMAT_VALUE` 字节码 | 编译期解析表达式 → 一条指令完成求值+格式化 → 无方法调用开销 |
| **6. 为什么 f-string 不能做模板?** | f-string 在定义时求值 | `{expr}` 编译为求值指令 → 表达式绑定到定义时作用域 → 无法延后求值 → 需要模板时用 `str.format()` |
| **7. 为什么 `@property` 是描述符而非装饰器?** | 属性访问需要拦截协议 | `obj.x` → `type(obj).__dict__['x'].__get__(obj)` → 描述符协议 → 装饰器无法拦截访问 |
| **8. 为什么堆叠装饰器自底向上应用?** | 语法定义如此 | `@a @b def f():` → `f = a(b(f))` → 先应用 `b`,再应用 `a` |
| **9. 为什么装饰器工厂需要三层嵌套?** | 参数化需要额外调用 | `@d(arg) def f()` → `d(arg)(f)` → 第一层接收参数,第二层接收函数,第三层是包装函数 |
| **10. 为什么 PEP 563 存储字符串注解?** | 解决前向引用 + 加速导入 | 编译时不求值类型名 → 存储字符串 → 访问时用 `get_type_hints` 解析 |
| **11. 为什么 `f"{x=}"` 如此方便调试?** | Debug 格式编译为特殊字符串 | `x=10` 编译为带表达式的字符串 → 打印时显示表达式和值 |
| **12. 为什么日志推荐 `%` 而非 f-string?** | 惰性求值 | `logging.info("%s", expr)` → 日志级别不够时不求值 → f-string 总是求值 |
| **13. 为什么 `@lru_cache` 能缓存任意函数?** | 字典存储参数→结果映射 | 装饰器内部缓存字典 → 参数作为键 → 结果作为值 → 上限 LRU 淘汰 |
| **14. 为什么 `Protocol` 不需要显式继承?** | 结构化类型(鸭子类型的编译期版本) | 类型检查看方法/属性签名 → 不看继承关系 → 隐式满足协议 |
| **15. 为什么装饰器能实现单例、注册、验证等多样功能?** | 装饰器是完全的函数变换 | `f = decorator(f)` → 返回值可以是任何对象 → 替换类、注册函数、包装验证 → 只受想象力限制 |

## 七、跨语言对比表——装饰器/注解/字符串插值的演进

| 语言 | 装饰器/注解机制 | 运行时影响 | 类型检查 | 字符串插值 | 设计哲学 |
|:---|:---|:---|:---|:---|:---|
| **Python** | **装饰器 = 高阶函数**,注解 = 元数据字典 | 装饰器:完全改变对象<br>注解:零影响 | 装饰器:无<br>注解:opt-in(mypy) | **f-string**(编译期优化) | 运行时元编程最大化,编译期类型安全 opt-in |
| **Java** | Annotation = 元数据(Retention Policy) | 零(除非反射读取) | 编译期(Annotation Processor) | 无(Java 21 预览:字符串模板) | 编译期处理优先,运行时零开销 |
| **Rust** | Attribute = AST变换,Macro = 过程宏 | 编译期完全展开 | 编译期强制 | `format!` 宏 | 零运行时开销,编译期安全保证 |
| **JavaScript** | Decorator 提案(Stage 3),注解无 | 装饰器:类/方法变换 | 无(有 Flow/TypeScript) | **模板字面量** `` `${expr}` `` | 动态语言,运行时灵活 |
| **C#** | Attribute = 元数据 + 反射 | 零(除非反射读取) | 无 | 字符串插值 `$"{expr}"` | .NET 生态,反射是核心能力 |
| **Go** | 无装饰器,无注解 | - | 无(泛型 1.18+) | 无(用 `fmt.Sprintf`) | 简单优先,避免元编程 |

**Python 的独特价值**:

1. **装饰器是运行时变换**——比 Java/C# 的元数据更强,比 Rust 的宏更灵活
2. **类型注解是渐进式类型**——可以零注解开始,逐步添加类型,不影响运行
3. **f-string 是性能+可读性的权衡**——编译期优化,运行时无解析开销

## 八、总结——Pythonic 的本质

**Pythonic 不是语法糖的堆砌,而是理解底层机制后做出的自然选择**。

- **装饰器**:理解 `@decorator` 是 `f = decorator(f)` 的高阶函数变换,你就能设计出灵活的装饰器工厂、类装饰器,避免 `functools.wraps` 陷阱。
  
- **类型注解**:理解 `__annotations__` 是一个字典、运行时零开销,你就能正确看待类型注解的边界——它不是约束,是契约,契约需要自愿遵守(mypy)或强制执行(pydantic)。

- **f-string**:理解 f-string 编译为 `FORMAT_VALUE` 字节码、编译期解析表达式、运行时零解析开销,你就能在性能敏感场景选择 f-string,在需要模板时选择 `str.format()`,在日志场景选择 `%` 惰性求值。

**Python 的三原则**:

1. **Simple is better than complex**——装饰器只是高阶函数,注解只是字典,f-string 只是编译期优化的插值,机制本身极其简单
2. **Explicit is better than implicit**——装饰器必须显式返回对象,类型注解不是隐式约束,f-string 的 `{}` 显式标记求值位置
3. **Practicality beats purity**——类型注解 opt-in(纯静态类型系统 impractical),f-string 无模板(纯 AST 宏 impractical)

理解机制 → 做出自然选择 → 写出 Pythonic 代码,这条路径的核心是"理解"而非"记忆"。下一个疑惑出现时,你有能力回溯到根因,自己推导答案。
