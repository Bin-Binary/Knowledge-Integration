### 4.2 PyByteArrayObject——可变的字节序列

`bytearray` 是 `bytes` 的可变版本，支持原地修改。它的内存布局与 `bytes` 有本质区别——数据区不再内联，而是使用独立分配的缓冲区：

```c
// CPython Include/bytearrayobject.h
typedef struct {
    PyObject_VAR_HEAD             // 24B
    Py_ssize_t ob_alloc;          // 8B — 已分配的缓冲区大小(≥ob_size)
    char *ob_bytes;               // 8B — 指向数据缓冲区的指针
    char *ob_start;               // 8B — 指向缓冲区中的起始位置(用于切片)
    Py_hash_t ob_shash;           // 8B — 缓存哈希 (-1表示不可哈希,因为可变)
} PyByteArrayObject;
```

```
PyByteArrayObject 内存布局:

ba = bytearray(b'hello'):
┌───────────────────────────────────────────────────┐
│ ob_refcnt = 1                        (8 字节)     │
│ ob_type   → <class 'bytearray'>      (8 字节)     │
│ ob_size   = 5                        (8 字节)     │ ← 当前字节数
│ ob_alloc  = 5 (或更大)               (8 字节)     │ ← 已分配容量
│ ob_bytes  ─────────────────────────────────╂──→ 独立缓冲区
│ ob_start  ─────────── (通常=ob_bytes)      │     ┌──────────────────────┐
│ ob_shash  = -1 (不缓存)              (8 字节)│     │h│e│l│l│o│ │(预留)    │
└───────────────────────────────────────────┘     └──────────────────────┘
总结构体大小: 56B + 缓冲区 → sys.getsizeof(bytearray(b'hello'))
```

### 4.3 buffer 协议——memoryview 与零拷贝

`bytes` 和 `bytearray` 都实现了 Python 的 **buffer 协议**——一个 C 层面的内存共享接口，允许不同对象零拷贝地共享同一块内存。

```
buffer 协议的抽象:
┌──────────────┐         ┌──────────────┐
│ bytes object │         │ bytearray    │
│ (数据所有者)  │         │ (数据所有者)  │
└──────┬───────┘         └──────┬───────┘
       │ buf.ptr                │ buf.ptr
       ↓                        ↓
┌──────────────────────────────────────┐
│           原始内存缓冲区              │
│  [H][e][l][l][o][\0]                │
└──────────────────────────────────────┘
       ↑
       │ 通过 buffer 协议共享
┌──────┴───────┐
│ memoryview   │  ← 不拷贝数据, 直接指向原始缓冲区
│ (视图/引用)   │
└──────────────┘
```

**实验 21：memoryview 的零拷贝特性**

### 4.4 bytes vs str——何时用哪个

```
使用 bytes 的场景:                           使用 str 的场景:
┌──────────────────────────┐         ┌──────────────────────────┐

│ 图像/音频原始数据          │         │ JSON 文本                 │

│ 结构体封装 (struct.pack)  │         │ 日志消息                  │
└──────────────────────────┘         └──────────────────────────┘

规则: 处理"含义"(文本)用 str, 处理"表示"(字节)用 bytes
      在边界处显式 编码/解码, 不要隐式混用
```

```python

# 文本文件 → str

    text = f.read()           # 返回 str

# sock.send(b'GET / HTTP/1.0\r\n\r\n')
# response = sock.recv(4096)  # 返回 bytes

```

```
    → str 处理文本, bytes 处理二进制 (分工)
      → bytes 不可变 (与 str 对称, 内联存储, 可哈希)
        → bytearray 可变 (需要原地修改二进制数据的场景)

```

## 五、bool 与 None

### 5.1 bool——int 的子类, True/False 的单例

§1.6 已详述 bool 继承 int 的机制。此处补充几个更深层的行为：

**bool 的 PyTypeObject 槽位**：

`bool` 作为 `int` 的子类，继承了 `int` 的几乎所有槽位，但**覆盖了 `tp_repr` 和 `tp_str`**——使 `repr(True)` 返回 `'True'` 而非 `'1'`，`repr(False)` 返回 `'False'` 而非 `'0'`。

```python
# repr 的差异: bool 覆盖了 tp_repr
print(repr(True))      # 'True'   ← bool.__repr__
print(repr(1))         # '1'      ← int.__repr__
print(str(True))       # 'True'
print(str(1))          # '1'

# 但是 format 没有覆盖!
print(f"{True}")       # 'True'
print(f"{True:d}")     # '1'      ← 按 int 格式化, 返回 '1'!
print(f"{True:05d}")   # '00001'
```

**实验 22：bool 单例的全局性**

```python
b = 2 > 1

print(f"2>1 is True: {b is True}")     # True
print(f"a is b: {a is b}")             # True — 都是同一个 True 对象!

# bool() 构造总是返回单例

print(f"bool('') is False: {f is False}")      # True

import sys

```

### 5.2 None——全进程唯一的空值单例

`None` 是 Python 中最轻的对象——它只是一个裸 `PyObject`，没有任何有效载荷：

```c
// CPython Include/object.h
// PyNoneObject 就是 PyObject 本身!
static PyTypeObject _PyNone_Type = {
    PyVarObject_HEAD_INIT(&PyType_Type, 0)
    "NoneType",                     // tp_name
    ...
};

// 全局单例
PyObject _Py_NoneStruct = {
    _PyObject_EXTRA_INIT
    1,                              // ob_refcnt: 永远 > 0
    &_PyNone_Type                   // ob_type
};

#define Py_None (&_Py_NoneStruct)   // 所有 None 引用都指向这同一个对象
```

```
PyNoneObject (None) 的内存布局:

┌───────────────────────────────────────────────────┐
│ ob_refcnt = ∞ (实际上是一个很大的数)    (8 字节)    │ ← 全局常量,永不被回收
│ ob_type   → <class 'NoneType'>         (8 字节)    │
└───────────────────────────────────────────────────┘
总大小: 16 字节  ← sys.getsizeof(None) 验证
```

**实验 23：None 的单例性验证**

```python
import sys

# 所有 None 都是同一个对象
a = None
b = None
c = eval("None")

print(f"None is None: {a is b}")                # True
print(f"eval('None') is None: {c is None}")     # True
print(f"id(None) = {id(None)}")                 # 固定地址

# None 的引用计数极高 (被到处引用)
print(f"sys.getrefcount(None) = {sys.getrefcount(None)}")
# 模块级和内置名字空间都持有 None 引用, 计数通常数百或更多

# None 只有 16 字节
print(f"sys.getsizeof(None) = {sys.getsizeof(None)}")   # 16

# None 的类型
print(f"type(None) = {type(None)}")                     # <class 'NoneType'>

# None 不是 0, 不是 False, 不是空字符串
print(f"None == False: {None == False}")       # False
print(f"None == 0: {None == 0}")               # False
print(f"None == '': {None == ''}")             # False
print(f"bool(None): {bool(None)}")             # False — 但 None ≠ False!

# 正确的 None 判断方式
x = None
print(f"x is None: {x is None}")              # True — 官方推荐
print(f"x == None: {x == None}")              # True — 也能工作, 但慢
# is None 是 O(1) 指针比较, == None 需要调用 __eq__ 方法
```

**为什么推荐 `x is None` 而非 `x == None`？**

1. **性能**：`is` 是指针比较（一条 CPU 指令），`==` 需要调用 `__eq__` 方法（需要 `ob_type` 分派）
2. **安全**：自定义类可以覆盖 `__eq__` 使 `x == None` 返回非预期值，但 `is` 不可覆盖
3. **确定性**：`is None` 的结果只取决于对象身份，不受任何用户代码影响

### 5.3 真值测试（Truth Value Testing）——__bool__() → __len__() → True

Python 的 `if`、`while`、`and`、`or`、`not` 以及 `bool()` 不直接检查对象是否等于 `True`/`False`，而是走一套**三级回退**的真值测试协议：

```
bool(obj) 的查找链:
  1. type(obj)->tp_bool (即 __bool__(self))    ← 优先级最高
     ├── 存在 → 调用, 返回 True/False
     └── 不存在 ↓
  2. type(obj)->sq_length/mp_length (即 __len__(self))
     ├── 存在 → len(obj) == 0 则 False, > 0 则 True
     └── 不存在 ↓
  3. 默认返回 True                              ← 任何对象至少为 True
```

**完整真值规则表**：

| 类型 | 值 | bool() 结果 | 规则来源 |
|:---|:---|:---|:---|
| `int` | `0` | `False` | `int.__bool__`: 0 → False |
| `int` | 非0 | `True` | `int.__bool__`: 非0 → True |
| `float` | `0.0` | `False` | `float.__bool__`: 0.0 → False |
| `float` | `0.3` | `True` | `float.__bool__`: |
| `float` | `NaN` | `True` | — `NaN` 在布尔上下文中是真!|
| `float` | `inf` | `True` | — |
| `str` | `""` | `False` | `str.__len__`: 0 → False |
| `str` | 非0长度 | `True` | `str.__len__`: >0 → True |
| `bytes` | `b""` | `False` | `bytes.__len__`: 0 → False |
| `bytes` | 非0长度 | `True` | — |
| `list` | `[]` | `False` | `list.__len__`: 0 → False |
| `list` | 非0长度 | `True` | — |
| `dict` | `{}` | `False` | `dict.__len__`: 0 → False |
| `tuple` | `()` | `False` | `tuple.__len__`: 0 → False |
| `set` | `set()` | `False` | `set.__len__`: 0 → False |
| `None` | `None` | `False` | `NoneType.__bool__`: 返回 False |
| `bool` | `False` | `False` | `False` 的值就是 0 |
| `bool` | `True` | `True` | `True` 的值就是 1 |
| 自定义类 | (默认) | `True` | 无 `__bool__`/`__len__`, 默认 True |

**实验 24：真值测试的细节**

```python

nan = float('nan')
print(f"bool(float('nan')): {bool(nan)}")       # True!
print(f"NaN != NaN: {nan != nan}")              # True
print(f"NaN is not 0.0: {nan != 0.0}")         # True
# bool(NaN) = True, 因为 NaN 不是 0.0, float.__bool__ 只对 0.0 返回 False

# 自定义类的真值控制
class AlwaysFalse:
    def __bool__(self):
        return False
    def __len__(self):
        return 100    # __bool__ 优先, __len__ 被忽略

af = AlwaysFalse()
print(f"bool(AlwaysFalse()): {bool(af)}")       # False — __bool__ 优先

class LenFalse:
    def __len__(self):
        return 0

lf = LenFalse()
print(f"bool(LenFalse()): {bool(lf)}")          # False — 无__bool__, 走__len__

class DefaultTrue:
    pass

dt = DefaultTrue()
print(f"bool(DefaultTrue()): {bool(dt)}")       # True — 默认

# None 的真值
print(f"bool(None): {bool(None)}")              # False
# 但 None ≠ False!
print(f"None == False: {None == False}"))       # False
print(f"None is False: {None is False}")        # False

# 常见错误: 用 == 检查 None
def dangerous(x):
    if x == None:       # 错误! 应该用 is None
        return "空值"
    return "非空"

class Sneaky:
    def __eq__(self, other):
        return True       # 与任何对象相等, 包括 None

print(dangerous(Sneaky()))   # "空值" — 误判!
# 而 x is None 不会被 __eq__ 影响
```

**设计闭环——bool/None 的因果链**：

```
"一切皆 PyObject" (根因)
  → bool 也是 PyObject, 继承 int 的 nb_add 等槽位 (因)
    → True + 1 == 2 (效果: 算术兼容)
      → 但 bool 必须 type-distinguish from int (约束: 序列化/类型检查需要)
        → True is not 1, ob_type 指向 bool (设计: 独立单例)
          → isinstance(True, int) True, isinstance(1, bool) False (不对称结果)
  → None 也是 PyObject, 但无有效载荷 (因: 表示"无值")
    → 仅 16 字节, 最轻对象 (效果)
    → 全局单例, is None 判断 (设计: 确定性)
    → bool(None) = False 但 None ≠ False (区分: "空值"≠"假值")
```

## 六、类型间的转换协议

### 6.1 显式转换——tp_call 的统一入口

Python 的显式类型转换（`int()`、`float()`、`str()`、`bool()`）本质上都是**调用类型对象的 `tp_call` 槽位**——每个类型对象（`int`、`float`、`str`、`bool`）都是可调用的，`tp_call` 指向各类型的 `__new__` + `__init__` 链。

```
int("42") 的工作流程:
  1. int 是一个类型对象 (ob_type → type)
  2. type 的 tp_call 被 invoke
  3. tp_call 调用 int.__new__(int, "42")  → 创建新 PyLongObject
  4. tp_call 调用 int.__init__(new_obj, "42") → 初始化
  5. 返回新对象

float("3.14") 的工作流程:
  1. float 的 tp_call 被 invoke
  2. float.__new__(float, "3.14") → 创建 PyFloatObject
  3. float.__init__ 通常无操作 (float 不可变, 所有初始化在 __new__ 中完成)
  4. 返回新对象

str(42) 的工作流程:
  1. str 的 tp_call 被 invoke
  2. str.__new__(str, 42)
  3. 内部调用 42.__str__() (即 int.__str__) 获取字符串表示
  4. 创建 PyUnicodeObject
  5. 返回新对象
```

**实验 25：转换函数的底层机制**

```python

# str() 的完整转换能力
print(str(42))              # "42"
print(str(3.14))            # "3.14"
print(str(True))            # "True"
print(str(None))            # "None"
print(str(b'hello'))        # "b'hello'" — bytes 的 repr, 不是内容!
print(str(b'hello', 'utf-8'))  # "hello" — 指定编码才能解码

# bool() 的完整转换能力
print(bool(0))              # False
print(bool(1))              # True
print(bool(0.0))            # False
print(bool(0.1))            # True
print(bool(""))             # False
print(bool("hello"))        # True
print(bool([]))             # False
print(bool([0]))            # True
print(bool(None))           # False
```

### 6.2 隐式转换——Python 的强类型拒绝

与 JavaScript 和 C 的隐式转换不同，Python **极少做隐式类型转换**：

```python
# JavaScript: "3" + 4 → "34" (字符串拼接)
# Python:
print("3" + 4)    # TypeError: can only concatenate str (not "int") to str

# JavaScript: "3" - 1 → 2 (隐式转数字)
# Python:
print("3" - 1)    # TypeError: unsupported operand type(s) for -: 'str' and 'int'

# JavaScript: "3" == 3 → true (隐式转换后比较)
# Python:
print("3" == 3)   # False — 不同类型, 值比较直接返回 False

# C: int + float → float (隐式提升)
# Python 也有, 但仅限数值类型之间:
print(1 + 0.5)    # 1.5 — int + float → float (nb_add 中的隐式提升)
print(type(1 + 0.5))  # <class 'float'>

# Python 唯一允许的隐式转换: 数值塔内的提升
# int + float → float
# int + complex → complex
# float + complex → complex
print(type(1 + 2j))    # <class 'complex'>
print(type(1.0 + 2j))  # <class 'complex'>
```

### 6.3 数值塔——int → float → complex 的隐式提升

Python 定义了一个**数值塔（numeric tower）**，塔中较高层的类型可以在运算中隐式提升较低层：

```
数值塔 (由低到高):
  bool → int → float → complex
   │      │      │       │
   │      │      │       └─ 复数, 最高层
   │      │      └─ 浮点数, 15位精度
   │      └─ 任意精度整数
   └─ 整数的子类, 只有 True/False

隐式提升规则:
  bool + int     → int     (bool 提升为 int)
  int + float    → float   (int 提升为 float)
  float + complex → complex(float 提升为 complex)
  int + complex  → complex (int 提升为 complex)
```

```python
# 验证数值塔的提升
print(type(True + 1))          # <class 'int'>    — bool提升为int
print(type(True + 1.0))        # <class 'float'>  — bool→int→float
print(type(1 + 1.0))           # <class 'float'>  — int提升为float
print(type(1 + 1j))            # <class 'complex'> — int提升为complex
print(type(1.0 + 1j))          # <class 'complex'> — float提升为complex

# 但反向不会降级
print(type(3.0))               # <class 'float'>
print(type(int(3.0)))          # <class 'int'>    — 需要显式转换

# bool(0.0) 的推导链
# 0.0 → float.__bool__ → 0.0 == 0.0 → True → False
print(bool(0.0))               # False
print(bool(0.0001))            # True
```

### 6.4 转换的边界情况

```python
# int() 的边界
print(int(float('inf')))      # OverflowError: cannot convert float infinity to integer
print(int(float('nan')))      # ValueError: cannot convert float NaN to integer
print(int("0x", 16))          # ValueError: invalid literal for int() with base 16: '0x'
print(int(""))                # ValueError: empty string

# float() 的边界
print(float("hello"))         # ValueError: could not convert string to float: 'hello'
print(float(b'3.14'))         # 3.14 — bytes 可以! (先decode为str)
print(float(b'\xff'))         # ValueError — 非UTF-8且不是有效数字

# str() 的边界
print(str(b'\xff'))           # "b'\\xff'" — 不是内容! 而是repr!
print(str(b'\xff', 'latin-1'))  # 'ÿ' — 需指定编码才解码

# bool() 的边界
print(bool("False"))          # True! — 非空字符串都是True, 包括"False"!
print(bool("0"))              # True! — 非空字符串!
print(bool(0.0))              # False — 0.0 是 falsy
print(bool(-0.0))             # False — -0.0 也是 0, 也是 falsy
print(bool(0j))               # False — 0+0j 是 falsy
print(bool(0.0000001))        # True — 非0浮点数是 truthy

# bytes → str 必须显式指定编码
b = b'\xe4\xbd\xa0\xe5\xa5\xbd'  # UTF-8 编码的 "你好"
try:
    str(b)        # 不是解码! 返回 repr: "b'\\xe4\\xbd\\xa0\\xe5\\xa5\\xbd'"
except:
    pass
print(str(b, 'utf-8'))  # "你好" — 这才是解码
```

**实验 26：bool("0") 是 True 的典型陷阱**

```python
# 最常见的 bool 陷阱: 字符串 "0" 是 Truthy
x = "0"
if x:                     # 程序员以为: x 是 "0" 所以是 False
    print("进入分支")      # 实际: 非空字符串 → True → 进入分支!

# 正确写法
y = "0"
if int(y) == 0:           # 显式转换为 int 再判断
    print("y 是零")

# 或更明确
if y == "0":              # 直接比较值
    print("y 等于 '0'")
```

**设计闭环——转换协议的因果链**：

```
"强类型"原则 (根因: ob_type 严格, 无隐式跨类型)
  → "3" + 4 → TypeError (效果: 拒绝隐式转换)
    → 程序员必须显式写 int("3") + 4 (设计: 显式优于隐式)
      → 但数值塔内允许有限隐式提升 (例外: 1 + 0.5 → 1.5)
        → 原因: 纯数值运算的语义无歧义, 隐式安全 (正当理由)
          → int + float → float (精度安全的方向)
          → 但 str + int 语义有歧义 ("3" + 4 = "34"还是7?) → 拒绝
```

## 七、常见陷阱

### 陷阱 1：浮点数等价比较

```python
# 错误: 用 == 比较浮点数
def calc_total(prices):
    total = sum(prices)
    if total == 100.0:        # 可能让 0.1+0.2+...+1.0 等于 100 的判断失败
        return "满百优惠"
    return "无优惠"

# 正确: 使用 math.isclose 或允许容差
import math

def calc_total_safe(prices):
    total = sum(prices)
    if math.isclose(total, 100.0, rel_tol=1e-9):
        return "满百优惠"
    return "无优惠"

# 或者用整数分来避免浮点问题 (金融场景)
def calc_total_cents(prices_cents):
    total_cents = sum(prices_cents)  # 整数运算, 无精度问题
    if total_cents == 10000:          # 100.00 元 = 10000 分
        return "满百优惠"
    return "无优惠"
```

**根因**：IEEE 754 无法精确表示大多数十进制小数，累积舍入误差使 `==` 不可靠。回溯到 `float` 的 `ob_fval`——8 字节 double 只有 52 位尾数，十进制分数如 0.1 无限循环，截断产生误差。

### 陷阱 2：bool("0") 是 True

```python
# 错误: 以为空字符串以外的 "0"/"False" 是 falsy
def process_config(value):
    if value:                # value="0" → True!
        enable_flag = True   # 本意: value 为 "0" 时不启用
    else:
        enable_flag = False

# 正确: 明确转换
def process_config_safe(value):
    enable_flag = value not in ("0", "false", "False", "")
    # 或: enable_flag = bool(int(value))  (如果确定value是数字字符串)
```

**根因**：`str` 类型的真值由 `__len__` 决定——`len("0") == 1 > 0` → `True`。字符串的真值只看长度，不看内容。回溯到 `PyTypeObject` 的 `sq_length` 槽位——`str` 没有实现 `tp_bool`（`__bool__`），只实现了 `sq_length`（`__len__`），真值测试走的是 `__len__` 回退路径。

### 陷阱 3：小整数池导致 is 比较的假阳性

```python
# 错误: 用 is 比较两个整数
def check_admin(user_id):
    if user_id is 1:         # 小整数池内, 恰好工作
        return True
    return False

# 当 user_id 超过 256 时可能失败
check_admin(1)    # True (命中缓存)
check_admin(257)  # 可能 True(同一代码块常量折叠) 或 False(新对象) — 不确定!

# 正确: 值比较用 ==
def check_admin_safe(user_id):
    if user_id == 1:         # 可靠的值比较
        return True
    return False
```

**根因**：小整数池 [-5, 256] 是 CPython 的实现细节，`is` 比较的是对象地址（`id()`），而非值。在池内的整数共享同一 `PyObject`，`is` 恰好工作；池外的整数每次创建新对象，`is` 失败。这不是 Python 的 bug，而是 `is` 被误用——`is` 只应用于 `None`、`True`、`False` 等单例判断。

### 陷阱 4：bytes 和 str 的隐式转换混淆

```python
# Python 2: str + unicode 会隐式解码/编码
# Python 3: str + bytes → TypeError, 不再隐式转换

# 错误: 混用 str 和 bytes
def write_header(f, name):
    header = b"Name: " + name    # name 是 str → TypeError!
    f.write(header)

# 正确: 统一类型
def write_header_fix(f, name):
    header = "Name: " + name      # 统一为 str
    f.write(header.encode('utf-8'))  # 写入时转为 bytes

# 或者全部使用 bytes
def write_header_bytes(f, name):
    header = b"Name: " + name.encode('utf-8')
    f.write(header)
```

**根因**：PEP 3137 的 str/bytes 分裂使两者不能隐式运算——这是 Python 3 相比 Python 2 的一个**破坏性改进**，消除了隐蔽的编码 bug。回溯到对象模型：`str` 的 `sq_concat`（`nb_add`）在发现右操作数的 `ob_type` 不是 `str` 时返回 `PyNotImplemented`，不会像 Python 2 那样尝试隐式解码。

### 陷阱 5：整数与浮点数的混合运算精度丢失

```python
# 大整数 + float → 精度丢失
big = 2**53 + 1       # int, 9007199254740993
float_big = float(big) # float, 9007199254740992.0 — 丢失了 +1!

print(f"2**53+1 = {big}")
print(f"float(2**53+1) = {float_big}")
print(f"2**53+1 == float(2**53+1): {big == float_big}")  # False!

# 混合运算
result = big + 0.0     # int + float → float, 丢失精度
print(f"2**53+1 + 0.0 = {result}")    # 9007199254740992.0

# int(float_n) 可能不等于原始 int
original = 2**53 + 1
after_round_trip = int(float(original))
print(f"原始: {original}, 经过float: {after_round_trip}")
print(f"相等: {original == after_round_trip}")  # False!
```

**根因**：`float` 的 52 位尾数只能精确表示 ≤ 2^53 的整数。超过此范围的整数在转换为 float 时会丢失低位精度——数值塔的隐式提升方向（int → float）在此处是**有损的**，这是 Python 唯一一个"安全的隐式转换"实际不安全的情况。

**题目 1**：以下代码输出什么？请从 `PyLongObject` 的 `ob_digit` 角度解释。

```python
import sys
a = 2**30 - 1
b = 2**30
print(sys.getsizeof(a))
print(sys.getsizeof(b))
print(a + 1 == b)
```

**题目 2**：以下代码中，哪几行输出 `True`？请解释 `True is 1` 为何是 `False`，而 `True == 1` 为何是 `True`。

```python
print(True == 1)
print(True is 1)
print(isinstance(True, int))
print(isinstance(True, bool))
print(isinstance(1, bool))
print(type(True) is type(1))
```

**题目 3**：以下代码输出什么？请从 IEEE 754 二进制表示角度解释为什么。

```python
a = 0.1 + 0.2
b = 0.3
print(a == b)
print(a)
print(float('nan') == float('nan'))
print(float('nan') != float('nan'))
```

---

<details>
<summary>参考答案</summary>

**题目 1**：
- `sys.getsizeof(a)` 输出 `28`——`2**30 - 1` 的 bit_length 为 30，恰好可以用 1 个 30-bit digit 表示，因此 `ob_digit` 数组长度为 1，总大小 = 24（头部）+ 4（1个digit）= 28 字节。
- `sys.getsizeof(b)` 输出 `32`——`2**30` 需要 2 个 digit（`ob_digit[0]=0, ob_digit[1]=1`），总大小 = 24 + 4×2 = 32 字节。跨越 30-bit 边界时增大。
- `a + 1 == b` 输出 `True`——虽然 `a` 和 `b` 的 `ob_digit` 结构不同，`a + 1` 的 `long_add` 实现正确处理了 `0x3FFFFFFF + 1 = 2**30` 的跨 digit 进位，结果与 `b` 的值相等。

**题目 2**：
- `True == 1` → `True`：`==` 走 `__eq__` 值比较，`bool` 继承 `int` 的 `tp_richcompare`，`True` 的 `ob_digit[0]` 值为 1，与 `1` 的 `ob_digit[0]` 相等。但注意比较时还会检查类型，bool 和 int 的 `__eq__` 实现了跨类型值比较。
- `True is 1` → `False`：`is` 比较对象地址（`id()`），`True` 的 `ob_type` 指向 `bool`，`1` 的 `ob_type` 指向 `int`，它们是不同的 `PyObject` 实例。
- `isinstance(True, int)` → `True`：`bool` 是 `int` 的子类（`MRO = (bool, int, object)`），沿 MRO 能找到 `int`。
- `isinstance(True, bool)` → `True`：`True` 的 `ob_type` 直接指向 `bool`。
- `isinstance(1, bool)` → `False`：`1` 的 `ob_type` 指向 `int`，`int` 不在 `bool` 的子类树中。
- `type(True) is type(1)` → `False`：`type(True)` = `bool`，`type(1)` = `int`，`bool is int` 为 `False`（`bool` 是 `int` 的子类，但不是 `int` 本身）。

**题目 3**：
- `a == b` → `False`：0.1 和 0.2 在 IEEE 754 中都是无限循环二进制分数，截断存储后的实际值分别为 0.10000000000000000555... 和 0.20000000000000001110...，相加结果为 0.30000000000000004440...，而 0.3 的实际存储为 0.29999999999999998889...，两者相差约 5.55e-17。
- `a` 输出 `0.30000000000000004`——Python 的 `repr()` 显示 17 位有效数字（`sys.float_info.dig + 2`），足以区分相邻的 float。
- `float('nan') == float('nan')` → `False`——IEEE 754 规定 NaN 与任何值（包括自身）比较都返回 False，这是 NaN 的定义性特征。
- `float('nan') != float('nan')` → `True`——`!=` 是 `==` 的逻辑反，因为 `==` 为 False 所以 `!=` 为 True。正确的 NaN 检测应使用 `math.isnan()`。

</details>

理解基本类型在 `PyObject`/`PyTypeObject` 层面的实现，不只是一堆底层知识——它提供了一个**统一的解释框架**，让表面上各自独立的疑惑都能回溯到同一个根因体系。

**这 27 个疑惑的统一解释框架**：

```
PyObject 头部 (ob_refcnt + ob_type)
  ├── ob_refcnt → 管理对象生死 → 小整数池/驻留的安全基础 (True, None的单例性)
  └── ob_type → 指向 PyTypeObject → 决定对象能力和行为
       ├── tp_basicsize → 决定 sizeof (int=28, float=24, None=16)
       ├── tp_hash → 决定可哈希性 (bytes:有, bytearray:无)
       ├── nb_add → 决定 + 的行为 (int:数值加, str:拼接, 拒绝混合)
       ├── sq_ass_item → 决定可变性 (str/bytes:NULL=不可变, bytearray:有=可变)
       ├── sq_length → 决定 len() 和真值回退
       ├── tp_bool → 决定真值测试的优先路径
       └── tp_call → 决定类型转换的入口 (int("42"), float("3.14"))
```

每一个表层行为——`0.1 + 0.2 ≠ 0.3`、`True is not 1`、`bool("0")` 为 True、`bytes` 可哈希而 `bytearray` 不行——都回溯到 `PyTypeObject` 的槽位矩阵和 `PyObject` 的内存布局。理解了基本类型的 C 层实现，Python 的表面行为就不再需要逐个记忆——它们是从少数几个设计决策推出的必然结论。

**与《对象模型》的衔接**：
