### 2.6 float 比较的正确姿势——math.isclose

直接用 `==` 比较 float 是不安全的，因为舍入误差可能让数学上相等的值在二进制表示上微差。

```python
import math

# 错误: 用 ==
a = 0.1 + 0.2
b = 0.3
print(f"0.1+0.2 == 0.3: {a == b}")                # False

# 正确: 用 math.isclose
print(f"math.isclose(0.1+0.2, 0.3): {math.isclose(a, b)}")  # True

# isclose 的默认参数: rel_tol=1e-9, abs_tol=0.0
# 判断条件: |a-b| ≤ max(rel_tol * max(|a|, |b|), abs_tol)

# 接近零时的特殊情况
x = 1e-10
y = 0.0
print(f"math.isclose(1e-10, 0.0): {math.isclose(x, y)}")     # False!
# 相对容差 1e-9 × max(1e-10, 0) = 1e-19, 而 |1e-10| > 1e-19

print(f"math.isclose(1e-10, 0.0, abs_tol=1e-9): "
      f"{math.isclose(x, y, abs_tol=1e-9)}")      # True

# 大数比较
print(f"math.isclose(1e20, 1e20+1): "
      f"{math.isclose(1e20, 1e20 + 1)}")          # True — 差1对1e20微不足道
print(f"1e20 == 1e20 + 1: {1e20 == 1e20 + 1}")    # True! float 本身就分辨不了
```

### 2.7 为什么 Python 选择了 float64（double）

Python 没有提供 `float32`（单精度）作为默认浮点类型。这不是遗漏，而是**精度优先**的设计选择：

- **float32**: 7 位有效数字，内存 4 字节
- **float64**: 15-17 位有效数字，内存 8 字节

Python 的哲学是**正确性优先于效率**——7 位精度太容易在日常使用中出现可见的精度损失（如货币计算、科学计数法），而 float64 的 15 位精度覆盖了绝大部分应用场景。如果确实需要 float32（如 GPU 计算、大规模数值存储），Python 通过 `numpy.float32` 提供，但这是一个需要显式选择的优化，而非默认行为。

```python
import numpy as np

a = np.float32(0.1)
b = np.float64(0.1)
print(f"float32(0.1) = {a}")       # 0.10000000149011612
print(f"float64(0.1) = {b}")       # 0.1 (打印截断, 实际也有误差)
print(f"float32 精度: ~7位")
print(f"float64 精度: ~15位")
```

**设计闭环——float 的完整因果链**：

```
Python 选择 float64 (因: 精度优先)
  → 15 位十进制精度 (效果)
    → 日常计算精度足够, 但 0.1 等十进制分数仍无法精确表示 (代价)
      → 0.1 + 0.2 ≠ 0.3 (直接后果)
        → 需要 math.isclose 而非 == 比较 (补丁)
          → float 加法不满足结合律 (更深层代价)
            → 数值算法需要专门设计以降低累积误差 (下游影响)
```

### 3.1 PyUnicodeObject——PEP 393 的灵活编码

Python 3 的字符串是本文最复杂的类型——它不仅在对象模型层面有 `PyVarObject` + 内联数据的结构，还在 Unicode 层面实现了 PEP 393 的**灵活字符串表示**（Flexible String Representation），根据字符范围自动选择最省内存的编码层级。

```c
// CPython Objects/unicodeobject.c (PEP 393 简化)
typedef struct {
    PyASCIIObject base;           // 变长头部
    // ... 后面紧跟字符数据区
} PyUnicodeObject;

// ASCII 字符串 (所有字符 < 128):
typedef struct {
    PyObject_VAR_HEAD             // ob_refcnt(8) + ob_type(8) + ob_size(8) = 24B
    unsigned int state:30;        // ASCII/紧凑/内联/ready 标志
    unsigned int interned:2;      // 驻留状态
    wchar_t *wstr;                // 宽字符缓存 (可能为NULL)
} PyASCIIObject;                  // + 字符数据 (1B/char, ASCII)
// 总头部: 24 + 4(state+interned) + 8(wstr) = 36B
// 但实际 CPython 实现: 24(ob_size之后是hash+state等)

// 更精确的 PyASCIIObject:
typedef struct {
    PyObject_VAR_HEAD             // 24B
    Py_hash_t hash;               // 8B — 缓存哈希
    struct {
        unsigned int interned:2;
        unsigned int kind:3;      // 0=ASCII, 1=UCS1, 2=UCS2, 4=UCS4
        unsigned int compact:1;   // 1=数据内联
        unsigned int ascii:1;     // 1=纯ASCII
        unsigned int ready:1;     // 1=规范化完成
        unsigned int :24;         // 保留
    } state;                      // 4B
    wchar_t *wstr;                // 8B — 宽字符缓存
} PyASCIIObject;                  // 36B 头部 + 内联数据
```

PEP 393 的核心设计：**根据字符串中最大字符的码点，选择最省内存的编码层级**：

```
PyUnicodeObject 的三种数据编码:

1. kind=1 (UCS1/Latin-1): 每字符 1 字节, 码点范围 U+0000-U+00FF
   适用: 纯 ASCII + 西欧字符

2. kind=2 (UCS2): 每字符 2 字节, 码点范围 U+0000-U+FFFF
   适用: BMP(基本多文种平面)字符, 包括大部分中文/日文/韩文

3. kind=4 (UCS4): 每字符 4 字节, 码点范围 U+0000-U+10FFFF
   适用: 补充字符(emoji, 罕见汉字, 古文字等)

ASCII 特殊优化:
   当所有字符 < 128 时, kind=0 (ASCII模式)
   此时仍按 1B/char 存储, 但 state.ascii=1
   hash 算法使用 ASCII 优化路径
```

```
ASCII "hi" (kind=0, 1B/char):

│ ob_size   = 2                   (8B)     │ ← 字节数(也是字符数)

┌──────────────────────────────────────────┐

│ ob_size   = 2                   (8B)     │ ← 字符数(不是字节数!)
│ hash      = ...                 (8B)     │

│ (对齐)                          (4B)     │
│ wstr      = NULL                (8B)     │
│ 你(2B or 4B) │ 好(2B or 4B) │ '\0'(2B) │ ← 按 kind 决定字符宽度
└──────────────────────────────────────────┘
```

**实验 16：使用 ctypes 读取 PyUnicodeObject 头部**

```python
import ctypes
import sys

class PyUnicodeObject(ctypes.Structure):
    _fields_ = [
        ("ob_refcnt", ctypes.c_ssize_t),
        ("ob_type", ctypes.c_void_p),
        ("ob_size", ctypes.c_ssize_t),
        ("hash", ctypes.c_ssize_t),
        ("state", ctypes.c_uint32),
        ("interned_and_padding", ctypes.c_uint32),
        ("wstr", ctypes.c_void_p),
    ]

def analyze_str(s):
    addr = id(s)
    obj = PyUnicodeObject.from_address(addr)
    state = obj.state
    kind = (state >> 2) & 0x7       # kind 字段的偏移位置
    ascii_flag = (state >> 6) & 1
    compact = (state >> 5) & 1
    ready = (state >> 7) & 1
    print(f"'{s}': ob_size={obj.ob_size}, hash={obj.hash}, "
          f"kind={kind}, ascii={ascii_flag}, compact={compact}, ready={ready}, "
          f"sizeof={sys.getsizeof(s)}")

analyze_str("hello")     # kind=1(ASCII优化), ascii=1
analyze_str("café")      # kind=1(Latin-1)
analyze_str("你好")      # kind=2 或 kind=4
analyze_str("🎉")        # kind=4
```

### 3.2 字符串驻留（intern）——编译期与运行时

字符串驻留是 Python 对不可变字符串的缓存优化：**值相同的字符串共享同一个 `PyObject`**，节省内存并加速 `==`/`is` 比较。

**编译期自动驻留**：

CPython 编译器在编译时会对**标识符和字面量**做驻留：
- 所有标识符（变量名、函数名、属性名）自动驻留
- 只含 ASCII 字母、数字、下划线的字面量自动驻留
- 不是所有字面量都会自动驻留！含有空格或特殊字符的不一定

```python
# 编译期驻留: 相同字面量是同一对象
a = "hello_world"
b = "hello_world"
print(f"编译期驻留: {a is b}")          # True (很可能)

# 运行时构造: 可能不驻留
a = "hello world"                       # 含空格
b = "hello world"
print(f"含空格: {a is b}")              # 不确定, 取决于实现

# 拼接: 运行时产生的新字符串通常不驻留
a = "hel" + "lo"                        # 编译期折叠 → "hello"
b = "hello"
print(f"编译期拼接: {a is b}")          # True (编译器优化)

prefix = "hel"
c = prefix + "lo"                       # 运行时拼接
d = "hello"
print(f"运行时拼接: {c is d}")          # False (不在同一intern表)
```

**显式驻留: `sys.intern()`**

```python
import sys

s1 = "hello world!"
s2 = "hello world!"
print(f"驻留前: s1 is s2 = {s1 is s2}")    # 不确定

s1 = sys.intern("hello world!")
s2 = sys.intern("hello world!")
print(f"驻留后: s1 is s2 = {s1 is s2}")    # True! 一定为True

# intern 的工作原理:
# 1. 查全局 intern 表 (dict: str → interned_str)
# 2. 存在 → 返回表中的对象 + INCREF
# 3. 不存在 → 将当前 str 加入表 + INCREF
# 所以相同值调用 sys.intern() 一定返回同一对象

# intern 的性能收益:
# 1. 节省内存: N 个相同字符串只占 1 份
# 2. 加速比较: interned 字符串用 is 代替 ==, O(1) vs O(n)
# 3. dict key 查找加速: hash 已缓存, is 比较快路径

# 什么时候应该手动 intern?
# - 大量重复字符串 (如日志中的标签、配置键名)
# - 字典键的高频查找场景
# - XML/HTML 解析中的标签名
```

### 3.3 str 的不可变性——内联数据的物理约束

在《对象模型》§1.1 中，我们已分析了 PEP 393 的内联存储决定了 `str` 必须不可变。此处从基本类型的角度补充一个关键点：**str 的 `ob_type` 指向的 `PyTypeObject` 中，`sq_ass_item` 槽位为 NULL**，在 C 层面直接拒绝索引赋值。

```
str 的 PyTypeObject (部分槽位):
┌────────────────────────────────────────────────────┐
│ tp_name     = "str"                                │
│ tp_basicsize = 49 (ASCII) / 更大 (非ASCII)         │
│ tp_hash     = unicode_hash         ← 有哈希!       │
│ tp_as_sequence:                                    │
│   sq_concat    = unicode_concat     ← "a" + "b"    │
│   sq_repeat    = unicode_repeat     ← "a" * 3      │
│   sq_item      = unicodegetitem     ← s[0]         │
│   sq_ass_item  = NULL               ← s[0]="H" ✗   │
│ tp_as_number:                                      │
│   nb_add       = NULL               ← "a" + 1 ✗    │
│   nb_multiply  = NULL                               │
│ tp_richcompare = unicode_richcompare ← ==, <, >   │
└────────────────────────────────────────────────────┘
```

```python
s = "hello"
try:
    s[0] = "H"
except TypeError as e:
    print(f"s[0]='H' → {e}")   # 'str' object does not support item assignment
    # C 层面: sq_ass_item 为 NULL, 走 PyErr_Format 报错

# "修改"字符串的唯一方式: 创建新对象
s2 = "H" + s[1:]    # 新建 str, s 不变
print(s2)            # "Hello"
print(s)             # "hello"
```

### 3.4 Python 3 的 str/bytes 分裂——PEP 3137

Python 2 中 `str` 等同于字节串（bytes），`unicode` 才是文本字符串。这导致了大量隐式编码转换和混乱的 type error。Python 3 通过 PEP 3137 彻底分裂了两者：

```
Python 2:                        Python 3:
  str  = bytes (字节序列)          str  = Unicode 文本 (码点序列)
  unicode = 文本 (码点序列)        bytes = 字节序列 (0-255)
                                   bytearray = 可变字节序列
```

**核心理念**：**文本与字节是两个完全不同的语义领域，不应该隐式混淆**。

- `str` 处理**文本**——你知道它的含义（人类语言），你知道它的编码方式（内部是 Unicode 码点），你不需要关心它在磁盘或网络上的字节表示
- `bytes` 处理**二进制数据**——你只知道它是字节序列，不知道也不应该假设它"是什么文本"

**编码/解码边界**——两者之间的唯一桥梁：

```
文本世界(str)                    二进制世界(bytes)
  Unicode码点                      0x00-0xFF 字节
 人类可读的文本                    磁盘/网络/协议的原始数据
       │                                │
       │ str.encode('utf-8')            │ bytes.decode('utf-8')
       │ ─────────────────→             │ ←─────────────────
       │                                │
       │ str→bytes: 编码 (必须指定)      │ bytes→str: 解码 (必须指定)
       │ 无编码 → TypeError              │ 无解码 → TypeError
```

```python
# str → bytes: 编码
text = "你好"
encoded = text.encode('utf-8')
print(f"str: {text}, type: {type(text)}")         # str
print(f"bytes: {encoded}, type: {type(encoded)}") # bytes b'\xe4\xbd\xa0\xe5\xa5\xbd'

# bytes → str: 解码
decoded = encoded.decode('utf-8')
print(f"decoded: {decoded}, type: {type(decoded)}")  # str

# Python 3 的强类型: str ≠ bytes
try:
    "hello" + b"world"
except TypeError as e:
    print(f"str + bytes: {e}")   # can't concat str to bytes

try:
    "hello" == b"hello"
except Exception as e:
    print(f"str == bytes: {e}")
print(f"'hello' == b'hello': {'hello' == b'hello'}")  # False!  != TypeError
```

### 3.5 编码错误处理

```python
# 编码: str → bytes 时, 某些字符在目标编码中不存在
text = "café"
try:
    encoded = text.encode('ascii')   # é 不在 ASCII 中
except UnicodeEncodeError as e:
    print(f"encode error: {e}")

# 错误处理策略
print(text.encode('ascii', errors='ignore'))    # b'caf' — 丢弃无法编码的
print(text.encode('ascii', errors='replace'))   # b'caf?' — 用?替换
print(text.encode('ascii', errors='xmlcharrefreplace'))  # b'caf&#233;'
print(text.encode('ascii', errors='backslashreplace'))   # b'caf\\xe9'

# 解码: bytes → str 时, 某些字节序列非法
bad_bytes = b'\xff\xff'
try:
    decoded = bad_bytes.decode('utf-8')
except UnicodeDecodeError as e:
    print(f"decode error: {e}")

print(bad_bytes.decode('utf-8', errors='ignore'))    # '' — 丢弃非法字节
print(bad_bytes.decode('utf-8', errors='replace'))   # '��' — 用U+FFFD替换
print(bad_bytes.decode('latin-1'))                    # 'ÿÿ' — latin-1永不失败!
```

### 3.6 字符串方法——C 层面的极致优化

Python 的字符串方法（`.split()`, `.join()`, `.find()`, `.replace()` 等）在 CPython 中都是 C 实现的，性能远超纯 Python 等价代码：

```python
# .join() vs + 拼接的性能差异
import timeit

n = 1000
items = [str(i) for i in range(n)]

t_join = timeit.timeit('"|".join(items)', 
                        setup='items = [str(i) for i in range(1000)]',
                        number=10000)
t_plus = timeit.timeit('s = ""; for item in items: s += item',
                        setup='items = [str(i) for i in range(1000)]',
                        number=1000)  # 减少次数,因为太慢

print(f"join(): {t_join:.4f}s")
print(f"+=:     {t_plus:.4f}s")
# join() 快一个数量级!

# 原因:
# join() 预先计算总长度, 一次分配内存, 逐个拷贝 → O(n)
# += 每次创建新 str 对象, 拷贝旧内容 + 新内容 → O(n^2)
# (CPython 对 += 有优化,但不如 join 高效)
```

**实验 18：字符串方法的槽位映射**

```python
# str 的关键方法在 PyTypeObject 中的对应:
# s + t     → tp_as_sequence->sq_concat  = unicode_concat
# s * n     → tp_as_sequence->sq_repeat  = unicode_repeat
# s[i]      → tp_as_sequence->sq_item    = unicodegetitem
# s == t    → tp_richcompare             = unicode_richcompare
# s in t    → tp_as_sequence->sq_contains = unicode_contains
# len(s)    → tp_as_sequence->sq_length  (通过ob_size直接返回)
# hash(s)   → tp_hash                    = unicode_hash
# s[i:j]    → tp_as_sequence->sq_slice   (或 mp_subscript)

# 验证: len(s) 直接返回 ob_size, O(1)
import sys
s_short = "a"
s_long = "a" * 1000000
print(f"len(short): {sys.getsizeof(s_short)}B")
print(f"len(long):  {sys.getsizeof(s_long)}B")
# ob_size 记录字符数, 无论多长, len() 都是 O(1)
```

**设计闭环——str 的完整因果链**：

```
PEP 393 内联存储 (因: 省内存)
  → 数据区固定在结构体尾部 (效果)
    → str 必须不可变 (约束: 长度/编码无法原地改变)
      → sq_ass_item = NULL (制度化: C层拒绝写操作)
      → 可做哈希 → 可做 dict key (收益)
      → 可做常量折叠/驻留 (收益)
      → 可做 hash 缓存 (收益)
    → PEP 3137 分裂 str/bytes (设计: 文本vs二进制的语义分离)
      → 编码/解码是跨越边界的唯一桥梁 (约束: 必须显式指定编码)
        → 不再出现隐式编码转换的混乱 (收益, 相比Python2)
```

## 四、bytes 与 bytearray

### 4.1 PyBytesObject——不可变的字节序列

`bytes` 是 Python 3 中表示**不可变字节序列**的类型，对应 C 中的 `unsigned char[]`。它的内存布局与 `str` 类似——头部 + 内联数据：

```c
// CPython Include/bytesobject.h
typedef struct {
    PyObject_VAR_HEAD             // ob_refcnt(8) + ob_type(8) + ob_size(8) = 24B
    Py_hash_t ob_shash;           // 8B — 缓存的哈希值
    char ob_sval[1];              // 变长: ob_size字节的实际数据 + 1字节null终止符
} PyBytesObject;
```

```
PyBytesObject 内存布局 (64位系统):

b'hello' (5 字节):
┌───────────────────────────────────────────────────┐
│ ob_refcnt = 1                        (8 字节)     │
│ ob_type   → <class 'bytes'>          (8 字节)     │
│ ob_size   = 5                        (8 字节)     │ ← 字节数
│ ob_shash  = -1 (未计算)              (8 字节)     │ ← -1 表示尚未计算哈希
│ 'h'(0x68)│'e'(0x65)│'l'(0x6C)│'l'(0x6C)│'o'(0x6F)│'\0'│
└───────────────────────────────────────────────────┘
总大小: 24 + 8 + 5 + 1(null) = 38... 实际 sys.getsizeof(b'hello') = 38 或有对齐

b'' (空):
┌───────────────────────────────────────────────────┐
│ ob_refcnt = 1                        (8 字节)     │
│ ob_type   → <class 'bytes'>          (8 字节)     │
│ ob_size   = 0                        (8 字节)     │
│ ob_shash  = 0                        (8 字节)     │ ← 空bytes的hash=0
│ '\0'                                  (1 字节)     │ ← 仍有null终止符!
└───────────────────────────────────────────────────┘
总大小: 33 — sys.getsizeof(b'')
```
