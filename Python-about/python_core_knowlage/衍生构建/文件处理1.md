# Python核心基础（十）：Python的文件世界——文本/二进制I/O与标准流

## 引言

在 C 中，文件是 `FILE*`——`fopen` 返回一个不透明指针，`fread`/`fwrite` 对原始字节操作，没有编码意识的任何概念，程序员必须在应用层自己处理从字节到字符的转换。在 Java 中，I/O 被劈成两棵继承树——`Reader`/`Writer`（文本，16位 char）与 `InputStream`/`OutputStream`（二进制，byte），Decorator 模式层层包装：`new BufferedReader(new InputStreamReader(new FileInputStream("file.txt"), "UTF-8"))`。在 Go 中，`io.Reader`/`io.Writer` 是朴素接口——任何类型只要实现 `Read(p []byte)` 和 `Write(p []byte)` 就能接入 I/O 生态，但 encoding 层需要手动组合。在 Rust 中，`std::fs::File` 是零抽象原始句柄——`BufReader::new(file)` 添加缓冲，`io::copy` 实现拷贝，Result 类型让每个 I/O 调用都伴随 `?` 运算符。

Python 做了一个足够优雅的决定：**`open()` 返回一个层层叠加的 I/O 栈，同一套 API 表面（`read`/`write`/`readline`）在所有模式下工作，编码、缓冲、换行转换被封装在层与层之间**。

```python
f = open("file.txt", "r", encoding="utf-8")    # 3 层：FileIO → BufferedReader → TextIOWrapper
type(f)  # <class '_io.TextIOWrapper'>

f = open("file.txt", "rb")                      # 2 层：FileIO → BufferedReader
type(f)  # <class '_io.BufferedReader'>

f = open("file.txt", "r", buffering=0)          # 1 层：FileIO (仅二进制模式允许)
type(f)  # <class '_io.FileIO'>
```

这是**抽象层次的自由落体**：从应用视角看，`f.read()` 返回 `str` 或 `bytes`，简单统一；从实现视角看，数据流经三层——原始文件描述符（系统调用）→ 缓冲区（减少 syscall）→ 编解码器（字节与字符转换）。但这种简单有代价：编码错误时，新手不知道错误来自哪一层；性能敏感场景下，3 层抽象的 overhead 不能忽略；跨平台时，默认编码的差异让同一份代码在不同系统上行为不同。

理解文件 I/O，不只是知道 `"r"` 读取、`"w"` 写入、`with` 自动关闭这些语法。它是读懂 Python I/O 全链路的起点：为什么 `open("file.txt", "r")` 返回 `TextIOWrapper`？为什么 `sys.stdout.buffer` 存在？为什么 `readline()` 比 `read()` 慢？为什么 `encoding` 参数默认值在不同平台不同？这些问题的答案都回溯到同一个根——`io` 模块的层叠架构与 CPython `PyFileObject` 的内部实现。

本文将追踪一次 `open()` 从**路径解析、模式解析、层级构建到返回对象**的完整过程，用可运行的代码逐步揭开 `_PyIO_open` 内部结构、`FileIO`/`BufferedReader`/`TextIOWrapper` 的协作机制、`sys.stdin`/`stdout`/`stderr` 的初始化过程——你将亲眼看到 `"r"` 如何映射为 `O_RDONLY`，3KB 的缓冲区如何减少 90% 的系统调用，UTF-8 编解码器如何与缓冲层交互，以及为什么文件必须关闭但 `with` 不是唯一的答案。

## 一、open()——三层层叠的I/O架构

### 1.1 I/O分层模型：从系统调用到字符串的旅程

Python 的 `open()` 返回值从来不是单一的"文件对象"——它是一个**层层叠加的葱头式架构**，每一层负责一个维度的抽象，数据从磁盘流向应用（或反向）时经过每一层的处理。

#### Layer 1：Binary I/O（FileIO）——原始系统调用层

```python
import io

# Layer 1: FileIO — 直接对接操作系统文件描述符
f_raw = io.FileIO("example.txt", mode='r')
print(type(f_raw))          # <class '_io.FileIO'>
print(f_raw.fileno())       # 文件描述符（如 3、4、5 ...）

# FileIO 的 read() 返回 bytes，无缓冲，每次读取都是一次系统调用
data = f_raw.read(10)       # 底层调用: read(fd, 10) — 一次 syscall
print(type(data))           # <class 'bytes'>
print(f_raw.mode)           # 'r' (实际是 'rb' 的简写)
f_raw.close()
```

`FileIO` 是对 POSIX `open()`/`read()`/`write()`/`close()` 的薄封装：

```
CPython 内部结构（简化版）:
struct _PyIO_FileIOObject {
    PyObject_HEAD
    int fd;                  // 文件描述符（int fd = open(path, flags, mode)）
    PyObject *name;          // 文件路径
    char *mode;              // 模式字符串
    int seekable;           // 是否可 seek（-1=未知，0=不可，1=可）
    int closefd;            // close() 时是否关闭 fd（false 时只是放弃所有权）
};
```

`FileIO.read(n)` 直接调用 C 的 `read(fd, buffer, n)`，**无任何缓冲**：每次调用都是一次完整的系统调用开销（用户态→内核态→用户态的上下文切换）。对于频繁的小块读取（如逐行解析），这是性能灾难。

#### Layer 2：Buffered I/O（BufferedReader/BufferedWriter）——缓冲层

```python
import io

# Layer 2: BufferedReader — 在 FileIO 之上添加缓冲
f_raw = io.FileIO("example.txt", mode='r')
f_buffered = io.BufferedReader(f_raw, buffer_size=8192)  # 8KB 缓冲区

print(type(f_buffered))     # <class '_io.BufferedReader'>
print(f_buffered.raw)       # 底层的 FileIO 对象

# 现在的小块读取会利用缓冲区，大幅减少 syscall 次数
data1 = f_buffered.read(100)   # 第 1 次：read(fd, 8192) → 返回前 100 字节，剩余 8092 缓存
data2 = f_buffered.read(100)   # 第 2 次：从缓冲区取 100 字节，无 syscall
data3 = f_buffered.read(100)   # ... 无 syscall
# ... 直到缓冲区耗尽
data40 = f_buffered.read(100)  # 缓冲区耗尽，触发第 2 次 syscall: read(fd, 8192)

f_buffered.close()
```

`BufferedReader` 的核心是**预读缓冲策略**（read-ahead buffering）：

```
CPython 内部结构（简化版）:
struct _PyIO_BufferedObject {
    PyObject_HEAD
    PyObject *raw;          // 底层的 raw I/O 对象（FileIO）
    char *buffer;           // 缓冲区指针
    Py_ssize_t buffer_size; // 缓冲区大小（默认 8KB）
    Py_ssize_t read_pos;    // 当前读取位置（缓冲区内）
    Py_ssize_t read_end;    // 缓冲区有效数据末尾
    int writable;           // 是否可写
};
```

读取流程：
1. 应用调用 `buffered.read(n)`
2. 若缓冲区有足够数据（`read_end - read_pos >= n`）：直接从缓冲区复制，返回
3. 若缓冲区不足：
   - 先返回缓冲区剩余数据
   - 调用 `raw.read(buffer_size)` 填充缓冲区（一次系统调用）
   - 继续从新缓冲区复制，直到凑够 n 字节或文件结束

**关键洞察**：`BufferedReader` 让 8192 次小读取只触发 1 次系统调用（假设 buffer_size=8192，每次读取 1 字节）。

#### Layer 3：Text I/O（TextIOWrapper）——编解码层

```python
import io

# Layer 3: TextIOWrapper — 在 BufferedReader 之上添加编码转换
f_raw = io.FileIO("example.txt", mode='r')
f_buffered = io.BufferedReader(f_raw)
f_text = io.TextIOWrapper(f_buffered, encoding='utf-8', newline=None)

print(type(f_text))         # <class '_io.TextIOWrapper'>
print(f_text.buffer)        # 底层的 BufferedReader
print(f_text.encoding)      # 'utf-8'
print(f_text.errors)        # 'strict'

# TextIOWrapper 的 read() 返回 str，不是 bytes
content = f_text.read(10)   # 读取 10 个字符（不是字节！）
print(type(content))        # <class 'str'>

line = f_text.readline()    # 读取一行（按 \n 分割，自动处理 \r\n 和 \r）
print(repr(line))           # '第一行内容\n'

f_text.close()
```

`TextIOWrapper` 的核心是**字节与字符的边界**与**换行符统一处理**：

```
CPython 内部结构（简化版）:
struct _PyIO_TextIOWrapperObject {
    PyObject_HEAD
    PyObject *buffer;        // 底层的 buffered I/O 对象
    PyObject *encoding;      // 编码名（如 'utf-8'）
    PyObject *errors;        // 错误处理策略（'strict', 'ignore', 'replace' ...）
    PyObject *decoder;       // 增量解码器（IncrementalDecoder）
    char *pending;           // 待解码的字节缓冲区
    int line_buffering;      // 是否行缓冲（遇到 \n 自动 flush）
    int write_through;       // 写入时是否绕过缓冲
};
```

读取流程：
1. 应用调用 `text.read(n)` 请求 n 个**字符**
2. TextIOWrapper 调用 decoder.decode()，从 buffer 层读取**字节**
3. UTF-8 等变长编码中，字符可能占用 1~4 字节，decoder 维护状态处理"半字符"问题
4. 若 `newline=None`，('\r\n' | '\r' | '\n') 全部统一转换为 '\n'
5. 返回解码后的 `str` 对象

**关键洞察**：TextIOWrapper 的 `read(n)` 读取的是 n 个**Unicode 字符**，不是 n 字节。对于 UTF-8 编码的中文文件，`read(1)` 可能消耗 1~3 字节。

#### 完整的层层叠加：open() 返回的秘密

```python
import io

def analyze_file_object(f, name):
    """递归分析文件对象的层级结构"""
    print(f"\n=== {name} ===")
    print(f"Type: {type(f)}")
    
    if hasattr(f, 'buffer'):
        analyze_file_object(f.buffer, f"{name} → .buffer")
    elif hasattr(f, 'raw'):
        analyze_file_object(f.raw, f"{name} → .raw")

# 先创建测试文件
with open("test.txt", "w", encoding="utf-8") as f:
    f.write("测试内容")

# 场景 1: 文本读取模式（默认）
with open("test.txt", "r", encoding="utf-8") as f:
    analyze_file_object(f, 'open("test.txt", "r")')

# 场景 2: 二进制读取模式
with open("test.txt", "rb") as f:
    analyze_file_object(f, 'open("test.txt", "rb")')

# 场景 3: 无缓冲二进制模式
with open("test.txt", "rb", buffering=0) as f:
    analyze_file_object(f, 'open("test.txt", "rb", buffering=0)')

import os
os.remove("test.txt")
```

### 1.2 文件模式全解

`open(file, mode)` 的 `mode` 参数是一个字符串，由多个字符组合而成，每个字符控制一个维度的行为。

#### 模式字符解析表

| 模式字符 | 语义 | 文件存在时 | 文件不存在时 | 读 | 写 | 创建 | 截断 | 追加 |
|---------|------|-----------|-------------|----|----|-----|------|-----|
| `r` | 只读 | 打开 | **FileNotFoundError** | ✓ | ✗ | ✗ | ✗ | ✗ |
| `w` | 只写 | **截断为0字节** | 创建 | ✗ | ✓ | ✓ | ✓ | ✗ |
| `a` | 追加 | 打开 | 创建 | ✗ | ✓ | ✓ | ✗ | ✓ |
| `x` | 独占创建 | **FileExistsError** | 创建 | ✗ | ✓ | ✓ | ✗ | ✗ |
| `r+` | 读写 | 打开 | **FileNotFoundError** | ✓ | ✓ | ✗ | ✗ | ✗ |
| `w+` | 读写 | **截断为0字节** | 创建 | ✓ | ✓ | ✓ | ✓ | ✗ |
| `a+` | 读写追加 | 打开 | 创建 | ✓ | ✓ | ✓ | ✗ | ✓ |

#### 基础模式详解

```python
import os

# === 'r' — 只读模式 ===
# 最常用, 最安全
with open("existing.txt", "r") as f:
    content = f.read()
# 文件必须存在, 否则 FileNotFoundError

# === 'w' — 只写模式 ===
# 危险: 截断现有文件!
with open("file.txt", "w") as f:
    f.write("new content")
# 如果 file.txt 已有内容, 现在全部丢失!
# 这是"清空后写入", 不是"覆盖写入"

# === 'a' — 追加模式 ===
with open("log.txt", "a") as f:
    f.write("new log entry\n")
# 写入位置总在文件末尾, seek() 无效

# === 'x' — 独占创建模式 (Python 3.3+) ===
try:
    with open("file.txt", "x") as f:
        f.write("content")
except FileExistsError:
    print("文件已存在, 拒绝覆盖")
# 适合需要确保不覆盖现有文件的场景
```

#### 组合模式：`+` 号的魔法

```python
# 'r+' — 读写, 不截断, 文件必须存在
with open("data.txt", "r+") as f:
    content = f.read()
    f.seek(0)
    f.write("OVERWRITE")
# 文件必须有内容, 从开头覆盖, 不改变其他部分

# 'w+' — 读写, 截断后创建
with open("data.txt", "w+") as f:
    f.write("new data")
    f.seek(0)
    content = f.read()  # 可以立即读回刚写的内容
# 文件先被清空, 然后可以读写

# 'a+' — 读写追加
with open("data.txt", "a+") as f:
    f.write("appended")
    f.seek(0)
    content = f.read()  # 可以读取整个文件
# 写入总是在末尾, 但可以 seek 到任意位置读取
```

#### 二进制模式：`b` 与文本模式 `t`

```python
# 'b' — 二进制模式
with open("image.png", "rb") as f:
    data = f.read()      # 返回 bytes
with open("output.bin", "wb") as f:
    f.write(b"\x89PNG")  # 接受 bytes

# 't' — 文本模式 (默认, 显式指定)
with open("text.txt", "rt") as f:
    content = f.read()   # 返回 str

# 模式组合
"rb"   # 二进制只读
"wb"   # 二进制只写
"r+b"  # 二进制读写 (无截断)
"w+b"  # 二进制读写 (截断)
```

#### CPython 内部：模式解析

```
open() 的 mode 参数在 CPython 中被解析为 POSIX flags:

mode     →  POSIX flags
'r'      →  O_RDONLY
'w'      →  O_WRONLY | O_CREAT | O_TRUNC
'a'      →  O_WRONLY | O_CREAT | O_APPEND
'x'      →  O_WRONLY | O_CREAT | O_EXCL
'r+'     →  O_RDWR
'w+'     →  O_RDWR | O_CREAT | O_TRUNC
'a+'     →  O_RDWR | O_CREAT | O_APPEND

'b'      →  不影响 POSIX flags, 仅决定返回类型 (bytes vs str)
't'      →  不影响 POSIX flags, 默认行为
```

## 二、文本I/O——编码的边界

### 2.1 TextIOWrapper的内部机制

`TextIOWrapper` 的核心职责是**在字节流与字符流之间建立可逆映射**。

#### encoding参数：默认值的跨平台陷阱

```python
import locale
import sys

print(f"locale.getpreferredencoding() = {locale.getpreferredencoding()}")
# Linux/Mac: 'UTF-8'
# Windows: 'cp936' (GBK)

# 这意味着同一份代码不同平台行为不同!

# Linux:
with open("data.txt", "w") as f:  # encoding='UTF-8'
    f.write("中文")

# Windows:
with open("data.txt", "w") as f:  # encoding='cp936'
    f.write("中文")

# 两种文件编码不同, 互读会乱码或报错!
```

**最佳实践**：**永远显式指定 encoding 参数**，除非是二进制模式。

```python
# ✅ 正确写法
with open("data.txt", "w", encoding="utf-8") as f:
    f.write("中文")

with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
```

#### errors参数：编解码错误处理策略

```python
import io

# 准备一个损坏的 UTF-8 序列
bad_data = b"Valid:ASCIIChar \x80 Invalid"

# 策略 1: 'strict' (默认) — 抛异常
try:
    wrapper = io.TextIOWrapper(io.BytesIO(bad_data), encoding='utf-8', errors='strict')
    wrapper.read()
except UnicodeDecodeError as e:
    print(f"strict: 抛出异常 at byte {e.start}")
    # UnicodeDecodeError: 'utf-8' codec can't decode byte 0x80

# 策略 2: 'ignore' — 跳过非法字节
wrapper = io.TextIOWrapper(io.BytesIO(bad_data), encoding='utf-8', errors='ignore')
print(f"ignore: {repr(wrapper.read())}")
# 'Valid:ASCIIChar  Invalid'  ← \x80 被丢弃

# 策略 3: 'replace' — 用 U+FFFD (�) 替换
wrapper = io.TextIOWrapper(io.BytesIO(bad_data), encoding='utf-8', errors='replace')
print(f"replace: {repr(wrapper.read())}")
# 'Valid:ASCIIChar � Invalid'  ← \x80 变为 �

# 策略 4: 'backslashreplace' — 用转义序列表示
wrapper = io.TextIOWrapper(io.BytesIO(bad_data), encoding='utf-8', errors='backslashreplace')
print(f"backslashreplace: {repr(wrapper.read())}")
# 'Valid:ASCIIChar \\x80 Invalid'  ← 适合调试

# 策略 5: 'surrogateescape' — 无损往返 (Python 3 独有)
wrapper = io.TextIOWrapper(io.BytesIO(bad_data), encoding='utf-8', errors='surrogateescape')
result = wrapper.read()
print(f"surrogateescape: {repr(result)}")
# 'Valid:ASCIIChar \udc80 Invalid'
# \x80 被映射到 surrogate U+DC80

# 关键: 可以无损还原
original_bytes = result.encode('utf-8', errors='surrogateescape')
print(f"还原: {original_bytes}")
# b'Valid:ASCIIChar \x80 Invalid'  ← 完美!
```

#### newline参数：换行符跨平台处理

```python
import io

# Windows 文件内容: b"line1\r\nline2"
win_content = b"line1\r\nline2\r\nline3"

# newline=None (默认): 通用换行符模式
# 读取时: \r\n, \r, \n 全部转换为 \n
wrapper = io.TextIOWrapper(io.BytesIO(win_content), encoding='utf-8', newline=None)
lines = wrapper.readlines()
print(lines)  # ['line1\n', 'line2\n', 'line3\n']
# 无论来源平台, 统一为 \n

# newline='': 不转换
wrapper = io.TextIOWrapper(io.BytesIO(win_content), encoding='utf-8', newline='')
content = wrapper.read()
print(repr(content))  # 'line1\r\nline2\r\nline3'
# 原样保留

# newline='\n': 只识别 \n
# newline='\r': 只识别 \r
# newline='\r\n': 只识别 \r\n

# 写入时的行为
output = io.BytesIO()
wrapper = io.TextIOWrapper(output, encoding='utf-8', newline=None)
wrapper.write("line1\nline2\n")
wrapper.flush()
print(output.getvalue())
# Windows: b'line1\r\nline2\r\n'
# Linux:   b'line1\nline2\n'
# \n 被转换为 os.linesep
```

### 2.2 编解码深度：从字节到字符

#### UTF-8 编码的变长特性

```python
# UTF-8 编码规则:
# U+0000..U+007F   → 0xxxxxxx                     (1 字节)
# U+0080..U+07FF   → 110xxxxx 10xxxxxx            (2 字节)
# U+0800..U+FFFF   → 1110xxxx 10xxxxxx 10xxxxxx   (3 字节)
# U+10000..U+10FFFF → 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx (4 字节)

# 这导致 TextIOWrapper.read(n) 需要小心处理
# 因为 n 个字符可能对应 1~4*n 字节

text = "Hello世界🌍"  # 5 ASCII + 2 中文 + 1 emoji
encoded = text.encode('utf-8')
print(f"字符数: {len(text)}")     # 8
print(f"字节数: {len(encoded)}")  # 5 + 3*2 + 4 = 15

# TextIOWrapper 内部的增量解码器处理"半字符"问题
import io
stream = io.BytesIO(encoded)
wrapper = io.TextIOWrapper(stream, encoding='utf-8')

# 如果底层缓冲区边界刚好在字符中间:
# 假设缓冲区大小 = 7 字节 (刚好切断"世"的第 3 字节)
# 解码器会:
# 1. 解码前 5 字节 "Hello"
# 2. 发现 "世" 的第 1、2 字节, 但没有第 3 字节
# 3. 将前 2 字节存入 pending 缓冲区, 等待更多数据
# 4. 下次读取时, 合并 pending + 新数据, 继续解码
```

#### BOM (Byte Order Mark) 处理

```python
# BOM 是文件开头的特殊标记:
# UTF-8 BOM:    EF BB BF
# UTF-16 LE:    FF FE
# UTF-16 BE:    FE FF

# Python 默认不写入 BOM
with open("file.txt", "w", encoding="utf-8") as f:
    f.write("Hello")
# 文件开头: 48 65 6C 6C 6F (无 BOM)

# 如果需要 BOM
with open("file.txt", "w", encoding="utf-8-sig") as f:
    f.write("Hello")
# 文件开头: EF BB BF 48 65 6C 6C 6F

# 读取时自动跳过 BOM
with open("file.txt", "r", encoding="utf-8-sig") as f:
    content = f.read()
print(content)  # "Hello" (BOM 被自动跳过)

# 注意: "utf-8-sig" 仅在文件开头检测 BOM, 不在中间检测
```

### 2.3 常见编码问题诊断

#### 场景 1：Windows 文件在 Linux 上读取

```python
# Windows 上创建的中文文件 (GBK 编码)
# 在 Linux 上用 UTF-8 读取 → UnicodeDecodeError

# 解决方案 1: 指定正确编码
with open("win_file.txt", "r", encoding="gbk") as f:
    content = f.read()

# 解决方案 2: 探测编码
def detect_encoding(file_path):
    """简单编码探测 (生产环境请用 chardet)"""
    import codecs
    encodings = ['utf-8', 'gbk', 'gb18030', 'latin-1']
    for enc in encodings:
        try:
            with open(file_path, "r", encoding=enc) as f:
                f.read()
            return enc
        except UnicodeDecodeError:
            continue
    return 'utf-8'  # fallback

detected = detect_encoding("unknown.txt")
with open("unknown.txt", "r", encoding=detected) as f:
    content = f.read()
```

## 三、二进制I/O——原始数据的通道

### 3.1 BufferedReader/BufferedWriter的缓冲策略

缓冲层的核心价值：**将多次小系统调用合并为少量大系统调用**，从而将用户态↔内核态切换开销摊薄。

#### 缓冲区大小参数详解

```python
import io

# buffering 参数的四种情况:
# -1 (默认): 使用 io.DEFAULT_BUFFER_SIZE (通常 8KB)
#  0: 无缓冲 (仅二进制模式允许)
#  1: 行缓冲 (仅文本模式允许)
# >1: 指定缓冲区大小

print(f"DEFAULT_BUFFER_SIZE = {io.DEFAULT_BUFFER_SIZE}")  # 通常 8192

# 场景 1: 文本模式, buffering = -1 (默认)
with open("file.txt", "r", encoding="utf-8") as f:
    # 内部结构: FileIO → BufferedReader(8KB) → TextIOWrapper
    print(f.buffer.raw)  # <_io.FileIO ...>

# 场景 2: 文本模式, buffering = 1 (行缓冲)
with open("file.txt", "w", encoding="utf-8", buffering=1) as f:
    # 每遇到 \n 自动 flush()
    f.write("line1\n")   # 立即 flush 到磁盘
    f.write("line2")     # 还在缓冲区, 未 flush
    # 行缓冲适用于交互式输出 (如终端日志)

# 场景 3: 二进制模式, buffering = 0 (无缓冲)
with open("file.bin", "rb", buffering=0) as f:
    # 内部结构: FileIO (无任何缓冲层)
    # 每次 read() 都是直接的系统调用
    type(f)  # <class '_io.FileIO'>

# 场景 4: 二进制模式, buffering = 65536 (64KB 缓冲)
with open("file.bin", "rb", buffering=65536) as f:
    # 适合大文件顺序读取
    pass
```

#### BufferedReader 的读取策略

```python
import io
import os

# 创建测试文件
with open("test_buf.txt", "wb") as f:
    f.write(b"A" * 10000)

# 手动构建层级结构以观察缓冲行为
f_raw = io.FileIO("test_buf.txt", "r")
f_buf = io.BufferedReader(f_raw, buffer_size=4096)  # 4KB 缓冲区

print(f"文件大小: {os.path.getsize('test_buf.txt')} bytes")
print(f"缓冲区大小: 4096 bytes")

# 第 1 次 read(1000): 触发 1 次 syscall, 读取 4096 字节到缓冲区
data1 = f_buf.read(1000)
print(f"read(1000): 获取 {len(data1)} 字节, syscall 1 次")

# 第 2 次 read(1000): 从缓冲区取, 无 syscall
data2 = f_buf.read(1000)
print(f"read(1000): 获取 {len(data2)} 字节, syscall 0 次")

# ... 继续读取缓冲区中的数据
data3 = f_buf.read(1000)
data4 = f_buf.read(1000)  # 缓冲区刚好用完 (4 × 1000 = 4000)

# 第 5 次: 缓冲区已空, 触发第 2 次 syscall
data5 = f_buf.read(1000)
print(f"read(1000): 触发 syscall 填充缓冲区")

f_buf.close()
os.remove("test_buf.txt")
```

**性能对比：缓冲 vs 无缓冲**

```python
import io
import time
import os

# 创建 10MB 测试文件
TEST_FILE = "perf_test.bin"
TOTAL_SIZE = 10 * 1024 * 1024  # 10 MB

with open(TEST_FILE, "wb") as f:
    f.write(b"X" * TOTAL_SIZE)

# 测试 1: 无缓冲
start = time.perf_counter()
with io.FileIO(TEST_FILE, "r") as f:
    while f.read(100):  # 每次读 100 字节
        pass
no_buf_time = time.perf_counter() - start

# 测试 2: 8KB 缓冲 (默认)
start = time.perf_counter()
with open(TEST_FILE, "rb") as f:
    while f.read(100):
        pass
buf_time = time.perf_counter() - start

print(f"无缓冲: {no_buf_time:.3f} 秒")
print(f"8KB缓冲: {buf_time:.3f} 秒")
print(f"性能提升: {no_buf_time/buf_time:.1f}x")
# 典型结果: 无缓冲 ~2.5x 慢于 8KB 缓冲

os.remove(TEST_FILE)
```

#### BufferedWriter 的写入策略

```python
import io

# BufferedWriter 的写入流程:
# 1. 数据写入内存缓冲区 (不立即 syscall)
# 2. 缓冲区满时, 调用底层 FileIO.write() 一次性写入
# 3. 文件关闭时, flush 剩余缓冲数据

f_buf.write(b" ")          # 在缓冲区
f_buf.write(b"World")      # 在缓冲区

# 此时文件仍然为 0 字节!
import os
print(f"文件大小: {os.path.getsize('write_test.txt')}")  # 0

f_buf.flush()              # 手动 flush → 触发 syscall
```

### 3.2 结构化二进制数据：struct与array

处理二进制文件时，`struct`、`array` 和 `memoryview` 是三个核心工具。

#### struct 模块：打包/解包二进制记录

```python
import struct

# 格式字符串语法:
# 字节序: < (little-endian) | > (big-endian) | @ (native) | = (native std)
# 类型: b/B (char/uchar) h/H (short/ushort) i/I (int/uint) q/Q (long long)
#       f (float) d (double) s (bytes) p (Pascal string) P (pointer)
# 数字: 重复计数，如 10s = 10 字节 bytes

# 示例: 网络数据包头部
# 格式: <
# 無作用, 小端序, 因为结构化数据是由 struct 转换的
# 格式不需要有 ":" , 直接小端组合
HEADER_FMT = "<IHHII"  # magic(4) + version(2) + flags(2) + seq(4) + length(4)

header_size = struct.calcsize(HEADER_FMT)
print(f"头部大小: {header_size} 字节")  # 16

# 打包
magic = 0x12345678
version = 1
flags = 0x0080
seq = 42
length = 1024

packed = struct.pack(HEADER_FMT, magic, version, flags, seq, length)
print(f"打包后: {packed.hex()}")
# 78 56 34 12 | 01 00 | 80 00 | 2a 00 00 00 | 00 04 00 00  (小端序)

# 解包
values = struct.unpack(HEADER_FMT, packed)
print(f"解包: magic={values[0]:08x}, version={values[1]}, length={values[4]}")

# unpack_from: 从偏移量解析, 不需要切分 bytes
data = b"PREFIX" + packed + b"SUFFIX"
values = struct.unpack_from(HEADER_FMT, data, offset=6)  # offset=6 跳过 PREFIX
print(f"unpack_from: {values}")

# pack_into: 打包到现有 buffer
import array
buf = array.array('b', [0] * 16)  # 16 字节 buffer
struct.pack_into(HEADER_FMT, buf, 0, magic, version, flags, seq, length)

# 混合字符串字段
RECORD_FMT = "<I10sf"  # id(4) + name(10字节bytes) + score(4字节float)
record = struct.pack(RECORD_FMT, 1001, b"Alice\x00\x00\x00\x00\x00", 95.5)
id_, name, score = struct.unpack(RECORD_FMT, record)
print(f"ID: {id_}, Name: {name.rstrip(b'\\x00').decode()}, Score: {score}")
```

#### array 模块：类型化数组

```python
import array

# array.array(typecode, initializer)
# typecode: 'b' (signed char) 'B' (unsigned char)
#           'h'/'H' (short) 'i'/'I' (int) 'f' (float) 'd' (double)

# 创建整数数组 (比 list[int] 更省内存)
arr = array.array('I', [1, 2, 3, 4, 5])  # unsigned int
print(f"每个元素 {arr.itemsize} 字节, 共 {len(arr)} 个")

# 从二进制文件读取
with open("data.bin", "wb") as f:
    arr.tofile(f)  # 直接写入二进制

with open("data.bin", "rb") as f:
    arr2 = array.array('I')
    arr2.fromfile(f, 5)  # 读取 5 个元素
print(arr2)

# 切片和修改
arr[0] = 100
arr.append(6)
print(arr.tolist())
```

#### memoryview：零拷贝内存视图

```python
import struct

# memoryview 核心: 不复制数据, 提供内存的"视图"
data = bytearray(b"ABCDEFGHIJ")  # 可变字节序列

# 创建 memoryview
mv = memoryview(data)

# 切片: 返回新 memoryview, 不复制数据!
sub_mv = mv[2:6]  # 视图指向 data[2:6]
print(bytes(sub_mv))  # b'CDEF'

# 修改视图影响原数据
sub_mv[0] = ord('X')
print(data)  # bytearray(b'ABXEFHIJ') — data 被修改了!

# 与 struct 结合: 零拷贝解析大型二进制文件
header = mv[:16]  # 前 16 字节的视图
# struct.unpack_from 可以直接在 memoryview 上工作
values = struct.unpack_from("<IIII", header)

# 性能对比: 切片 vs memoryview
import time

large_bytes = b"X" * 10_000_000

# 切片: 创建新 bytes 对象 (复制数据)
start = time.perf_counter()
chunk = large_bytes[1000:2000]  # 复制 1000 字节
elapsed_slice = time.perf_counter() - start

# memoryview: 不复制
start = time.perf_counter()
mv = memoryview(large_bytes)
chunk_mv = mv[1000:2000]
bytes_view = bytes(chunk_mv)  # 这里有转换, 但视图创建是 O(1)
elapsed_mv = time.perf_counter() - start

print(f"切片耗时: {elapsed_slice:.9f}")
print(f"memoryview 耗时: {elapsed_mv:.9f}")
```

## 四、标准流——程序与世界的三个通道

### 4.1 stdin/stdout/stderr的层级结构

每个 Python 进程启动时，操作系统预先打开三个文件描述符：

| 文件描述符 | 名称 | Python 对象 | 用途 |
|:----------|:-----|:------------|:-----|
| 0 | stdin | `sys.stdin` | 标准输入 |
| 1 | stdout | `sys.stdout` | 标准输出 |
| 2 | stderr | `sys.stderr` | 标准错误 |

```python
import sys

# sys.stdin 的层级结构
print(type(sys.stdin))         # <class '_io.TextIOWrapper'>
print(type(sys.stdin.buffer))  # <class '_io.BufferedReader'>
print(type(sys.stdin.buffer.raw))  # <class '_io.FileIO'>

# 验证文件描述符
print(sys.stdin.buffer.fileno())   # 0
print(sys.stdout.buffer.fileno())  # 1
print(sys.stderr.buffer.fileno())  # 2

# stdin 用于读取用户输入
name = sys.stdin.readline().rstrip('\n')  # 等同于 input()

# stdout 用于输出
sys.stdout.write("Hello\n")  # 等同于 print("Hello")

# stderr 用于错误输出 (即使 stdout 重定向, stderr 仍显示在终端)
sys.stderr.write("Error message\n")
```

#### stdout vs stderr 的关键差异

```python
import sys

# stdout: 行缓冲 (终端) 或全缓冲 (管道/文件)
# stderr: 无缓冲 (总是立即输出)

# 演示差异
print("This goes to stdout", file=sys.stdout)
print("This goes to stderr", file=sys.stderr)

# 为什么 stderr 无缓冲?
# 因为错误消息需要立即可见, 不应该被缓冲延迟
# 即使程序崩溃, stderr 的内容也已输出到终端

# 混合输出的顺序
import time
sys.stdout.write("stdout: step 1\n")
sys.stderr.write("stderr: step 1\n")  # 立即显示
time.sleep(0.1)
sys.stdout.write("stdout: step 2\n")  # 如果有缓冲可能稍后显示
sys.stderr.write("stderr: step 2\n")
```
