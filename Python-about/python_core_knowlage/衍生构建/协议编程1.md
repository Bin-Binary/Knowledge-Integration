# Python核心基础（十四）：Python中的"协议"编程——从迭代器到上下文管理器

## 引言：编程范式中的"契约精神"

在静态类型语言的世界里，接口是显式的、强制性的：
- **Java**：你实现一个 `Interface`，编译器强制检查所有方法是否实现
- **Go**：接口是隐式满足的，但类型系统仍然在编译期验证
- **Rust**：你显式实现一个 `Trait`，编译器确保行为完整

而在Python的世界里，我们有一种更灵活、更Pythonic的机制——**协议（Protocol）**。

协议不是语言强制的规定，而是一种约定俗成的"契约"：**如果你的对象定义了一组特定的方法名，Python就会把它当作某种特定类型的对象来对待，赋予它相应的能力**。这正是鸭子类型（Duck Typing）的核心哲学——"如果它走起来像鸭子，叫声像鸭子，那么它就是鸭子"。

但协议的重要性远不止于此。协议是Python整个对象模型的基石：
- **迭代器协议**让任何对象都能被`for`循环遍历
- **容器协议**让对象支持`len()`、`in`、索引访问
- **上下文管理器协议**让对象能安全地管理资源
- **描述符协议**让属性访问变得可控和可定制

本文将系统性地梳理Python中的所有核心协议，揭示它们背后的工作机制， 并展示如何利用协议编写出更Pythonic、更灵活、更强大的代码。我们将把读者在"容器篇"（三）、"迭代器篇"（六）、"OOP篇"（七）、"异常篇"（九）中学习的知识，统一到"协议"这个更高层次的抽象框架中。

## 一、协议的本质——鸭子类型的制度化

### 1.1 什么是协议？

**协议（Protocol）是一组方法名称的集合，如果一个类型定义了这些方法，Python的内置功能就会自动识别并支持该类型的特定行为。**

这里的关键词是"自动识别"——Python不会在编译时强制你实现某个协议，而是在运行时检测你的对象是否有相应的方法，如果有，就开启对应的内置能力。

让我们看一个最简单的例子——迭代器协议：

```python
# 示例1：迭代器协议的演示
class Countdown:
    """一个简单的倒计时器，演示迭代器协议"""
    
    def __init__(self, start):
        self.current = start
    
    def __iter__(self):
        """迭代器协议第一部分：返回self"""
        return self
    
    def __next__(self):
        """迭代器协议第二部分：返回下一个值或抛出StopIteration"""
        if self.current <= 0:
            raise StopIteration
        self.current -= 1
        return self.current + 1

# 使用协议赋能的对象
countdown = Countdown(5)
for num in countdown:
    print(num)  # 输出: 5 4 3 2 1
```

请注意，我们**从未显式声明**`Countdown`实现了某个"Iterable接口"。但仅仅因为定义了`__iter__`和`__next__`方法，Python就自动识别它为迭代器，允许它被`for`循环使用。这就是协议的力量。

### 1.2 协议 vs 接口：形式化的程度

让我们对比不同语言的"行为契约"机制：

| 语言 | 机制名称 | 形式化程度 | 检查时机 | 灵活性 |
|------|---------|-----------|---------|--------|
| Java | Interface | 显式、强制 | 编译期 | 低（必须显式声明） |
| Go | Interface | 隐式满足 | 编译期 | 中（自动推断但静态） |
| Rust | Trait | 显式实现 | 编译期 | 中（trait bound有约束） |
| **Python** | **Protocol** | **非强制约定** | **运行期** | **极高（鸭子类型）** |

Python协议的独特优势：

```python
# 示例2：协议的灵活性——不完整实现也有价值
class PartialContainer:
    """只实现部分容器协议，依然能获得部分能力"""
    
    def __len__(self):
        return 42
    
    # 没有实现__contains__，但in操作依然可用！
    # Python会自动降级使用__getitem__遍历

obj = PartialContainer()
print(len(obj))  # 输出: 42 — __len__协议生效
print(1 in obj)  # AttributeError: 'PartialContainer' object is not iterable
# 但如果我们实现了__getitem__，即使不实现__contains__，in也能工作！
```

**协议允许部分实现，语言会在能力允许的范围内提供最大支持。**

### 1.3 协议的底层实现：类型槽（Type Slots）

在CPython实现中，协议不是抽象概念，而是实实在在的C结构体字段——**类型槽（Type Slots）**。

每个Python对象的类型信息存储在`ob_type`指针指向的`PyTypeObject`结构体中：

```c
// CPython源码中的PyTypeObject结构（简化版）
typedef struct _typeobject {
    PyObject_VAR_HEAD
    const char *tp_name;
    Py_ssize_t tp_basicsize;
    
    // 类型槽：每个槽对应一个协议或特殊行为
    destructor tp_dealloc;
    printfunc tp_print;
    getattrfunc tp_getattr;
    setattrfunc tp_setattr;
    Py_ssize_t tp_hashoffset;
    
    // 迭代器协议槽
    getiterfunc tp_iter;        // 对应__iter__
    iternextfunc tp_iternext;   // 对应__next__
    
    // 可调用协议槽
    ternaryfunc tp_call;        // 对应__call__
    
    // 哈希协议槽
    hashfunc tp_hash;           // 对应__hash__
    
    // 描述符协议槽
    descrgetfunc tp_descr_get;  // 对应__get__
    descrsetfunc tp_descr_set;  // 对应__set__
    
    // 容器协议槽
    lenfunc tp_len;             // 对应__len__
    ssizeargfunc tp_getitem;    // 对应__getitem__
    ssizeobjargproc tp_setitem; // 对应__setitem__
    
    // 上下文管理器协议槽
    unaryfunc tp_enter;         // 对应__enter__
    unaryfunc tp_exit;          // 对应__exit__
    
    // 更多槽...
} PyTypeObject;
```

当你定义一个Python类并实现`__iter__`方法时，CPython会自动将`tp_iter`槽指向你的`__iter__`方法。当`for`循环开始时，解释器会检查`tp_iter`是否非空，如果非空就调用它。

**协议的本质就是：Python方法定义 → 槽位赋值 → 解释器特殊行为激活。**

让我们验证这一点：

```python
# 示例3：验证槽位机制
import sys

class WithIter:
    def __iter__(self):
        return iter([])

class WithoutIter:
    pass

# 检查类型对象
with_iter_type = type(WithIter())
without_iter_type = type(WithoutIter())

# 在Python层面，我们无法直接访问C槽位，但可以通过抽象基类检测
from collections.abc import Iterable

print(isinstance(WithIter(), Iterable))     # True
print(isinstance(WithoutIter(), Iterable))  # False
```

### 1.4 Abstract Base Classes（ABC）：协议的正式化检测

虽然协议是非强制的，但Python提供了`collections.abc`模块来**形式化检测**一个对象是否满足某个协议：

```python
# 示例4：ABC协议检测
from collections.abc import (
    Iterable, Iterator, Container, Sized, 
    Callable, Hashable, Mapping, Sequence
)

# 一个自定义容器类
class MyList:
    def __init__(self, items):
        self._items = list(items)
    
    def __len__(self):
        return len(self._items)
    
    def __getitem__(self, index):
        return self._items[index]
    
    def __contains__(self, item):
        return item in self._items

mylist = MyList([1, 2, 3])

# ABC检测：虚拟子类（Virtual Subclass）
print(isinstance(mylist, Sized))      # True  — 有__len__
print(isinstance(mylist, Container))  # True  — 有__contains__
print(isinstance(mylist, Iterable))   # True  — 有__getitem__可迭代
print(isinstance(mylist, Sequence))   # True  — 满足序列协议
print(isinstance(mylist, Mapping))    # False — 不是映射
```

**ABC的工作原理：`__subclasshook__`**

ABC能检测协议的关键是`__subclasshook__`类方法。让我们看一个简化实现：

```python
# 示例5：自定义ABC的subclasshook
from abc import ABCMeta, abstractmethod

class MyIterable(metaclass=ABCMeta):
    """自定义Iterable抽象基类"""
    
    __slots__ = ()
    
    @abstractmethod
    def __iter__(self):
        raise NotImplementedError
    
    @classmethod
    def __subclasshook__(cls, C):
        """核心：鸭子类型检测逻辑"""
        if cls is MyIterable:
            # 检查是否有__iter__方法
            if any("__iter__" in B.__dict__ for B in C.__mro__):
                return True  # 是虚拟子类
        return NotImplemented  # 让其他ABC来判断

# 测试
class MyRange:
    def __iter__(self):
        return iter(range(10))

print(isinstance(MyRange(), MyIterable))  # True
```

**ABC不检查继承关系，只检查方法是否存在——这正是协议思想的制度化。**

### 1.5 为什么选择协议而非继承？

协议相比传统继承的优势：

```python
# 示例6：协议 vs 继承——谁更灵活？

# 方案A：继承（需要显式继承，多重继承复杂）
class MyContainerA(list):
    def first(self):
        return self[0] if self else None

# 方案B：协议（无继承负担，更纯净）
class MyContainerB:
    def __init__(self, items):
        self._items = items
    
    def __len__(self):
        return len(self._items)
    
    def __getitem__(self, index):
        return self._items[index]
    
    def first(self):
        return self._items[0] if self._items else None

# 两者功能相同，但B没有继承包袱
from collections.abc import Sequence

print(isinstance(MyContainerA([1,2,3]), Sequence))  # True
print(isinstance(MyContainerB([1,2,3]), Sequence))  # True（协议支持）
```

**协议的优势总结**：
1. **最小承诺**：只实现需要的方法，不背负整个父类
2. **组合灵活**：可以自由组合多个协议，无多重继承冲突
3. **类型无关**：任何类都可以实现协议，不破坏现有继承链
4. **运行时检测**：ABC提供验证，不强制编译期约束

## 二、迭代器协议——最基础的协议

*本节关联文章：《Python核心基础（六）：迭代与生成器——Python之流的哲学》*

### 2.1 迭代器协议的完整定义

迭代器协议是最早、最基础的Python协议，它定义了如何让对象被`for`循环遍历。

**正式定义**：
- **迭代器对象**必须实现：
  - `__iter__()`：返回迭代器对象本身
  - `__next__()`：返回下一个元素，无元素时抛出`StopIteration`
- **可迭代对象**只需实现：
  - `__iter__()`：返回一个迭代器对象

区别在于：**可迭代对象是容器，迭代器是游标**。

```python
# 示例7：可迭代对象 vs 迭代器
class MyIterable:
    """可迭代对象：容器，可以被多次迭代"""
    def __init__(self, data):
        self.data = data
    
    def __iter__(self):
        """每次返回一个新的迭代器"""
        return MyIterator(self.data)

class MyIterator:
    """迭代器：游标，一次性消费"""
    def __init__(self, data):
        self.data = data
        self.index = 0
    
    def __iter__(self):
        """迭代器的__iter__返回self"""
        return self
    
    def __next__(self):
        """返回下一个元素或抛出StopIteration"""
        if self.index >= len(self.data):
            raise StopIteration
        value = self.data[self.index]
        self.index += 1
        return value

# 使用演示
iterable = MyIterable([1, 2, 3])
for x in iterable:  # 第一次迭代
    print(x)  # 输出: 1 2 3

for x in iterable:  # 第二次迭代——可以重新开始
    print(x)  # 输出: 1 2 3

iterator = iter(iterable)
for x in iterator:  # 迭代器一次性消费
    print(x)  # 输出: 1 2 3

for x in iterator:  # 再次迭代——已耗尽
    print(x)  # 无输出
```

### 2.2 for循环的协议调用链

当我们写`for item in obj:`时，Python解释器执行了以下步骤：

```python
# 示例8：for循环的等价实现
def for_loop_equivalent(iterable, func):
    """手动实现for循环的底层逻辑"""
    
    # 步骤1：调用iter()获取迭代器
    iterator = iter(iterable)  # 实际调用: iterable.__iter__()
    
    # 步骤2：循环调用next()
    while True:
        try:
            # 步骤3：获取下一个元素
            item = next(iterator)  # 实际调用: iterator.__next__()
            
            # 步骤4：执行循环体
            func(item)
            
        except StopIteration:
            # 步骤5：捕获StopIteration，结束循环
            break

# 测试
for_loop_equivalent([1, 2, 3], print)  # 输出: 1 2 3
```

**调用链可视化**：
```
for item in obj:
    ↓
iter(obj)  → obj.__iter__()  → 返回iterator对象
    ↓
next(iterator) → iterator.__next__() → 返回item1
    ↓
循环体执行(item1)
    ↓
next(iterator) → iterator.__next__() → 返回item2
    ↓
循环体执行(item2)
    ↓
...
    ↓
next(iterator) → iterator.__next__() → 抛出StopIteration
    ↓
捕获异常，循环结束
```

### 2.3 迭代器协议的实际应用：自定义数据结构

让我们实现一个实现迭代器协议的自定义数据结构——环形缓冲区：

```python
# 示例9：环形缓冲区——实战迭代器协议
class CircularBuffer:
    """环形缓冲区：固定大小，新数据覆盖旧数据"""
    
    def __init__(self, capacity):
        self.capacity = capacity
        self.buffer = [None] * capacity
        self.head = 0  # 写入位置
        self.size = 0  # 当前大小
    
    def append(self, item):
        """添加元素"""
        self.buffer[self.head] = item
        self.head = (self.head + 1) % self.capacity
        self.size = min(self.size + 1, self.capacity)
    
    def __len__(self):
        """容器协议：支持len()"""
        return self.size
    
    def __iter__(self):
        """迭代器协议：支持for循环"""
        return CircularBufferIterator(self)
    
    def __repr__(self):
        return f"CircularBuffer({list(self)})"

class CircularBufferIterator:
    """环形缓冲区的迭代器"""
    
    def __init__(self, buffer):
        self.buffer = buffer
        self.index = 0
        self.count = 0
    
    def __iter__(self):
        return self
    
    def __next__(self):
        if self.count >= self.buffer.size:
            raise StopIteration
        
        # 计算实际读取位置（从最旧的数据开始）
        if self.buffer.size < self.buffer.capacity:
            actual_index = self.index
        else:
            oldest = self.buffer.head
            actual_index = (oldest + self.index) % self.buffer.capacity
        
        value = self.buffer.buffer[actual_index]
        self.index = (self.index + 1) % self.buffer.capacity
        self.count += 1
        return value

# 使用演示
buffer = CircularBuffer(5)
for i in range(10):
    buffer.append(i)

print(buffer)  # CircularBuffer([5, 6, 7, 8, 9])
print(len(buffer))  # 5

for item in buffer:
    print(item, end=' ')  # 输出: 5 6 7 8 9
```

### 2.5 迭代器协议的陷阱

**陷阱1：迭代器耗尽**

```python
# 示例11：迭代器耗尽陷阱
numbers = [1, 2, 3]
iterator = iter(numbers)

print(list(iterator))  # [1, 2, 3]
print(list(iterator))  # [] —— 已耗尽！

# 解决方案：始终从可迭代对象创建迭代器
def safe_iteration(iterable):
    """推荐模式：每次从原始可迭代对象创建新迭代器"""
    return list(iterable)

print(safe_iteration(numbers))  # [1, 2, 3]
print(safe_iteration(numbers))  # [1, 2, 3]
```

**陷阱2：在迭代时修改容器**

```python
# 示例12：迭代时修改陷阱
items = [1, 2, 3, 4, 5]
for item in items:
    if item == 3:
        items.remove(item)  # 危险！导致跳过元素
    print(item, end=' ')  # 输出: 1 2 3 5（跳过了4）

# 解决方案：迭代副本
items = [1, 2, 3, 4, 5]
for item in items[:]:  # 迭代副本
    if item == 3:
        items.remove(item)
print(items)  # [1, 2, 4, 5]
```

## 三、容器协议——in/len/getitem的统一

*本节关联文章：《Python核心基础（三）：容器——Python的容器哲学》*

### 3.1 容器协议家族

容器协议不是单一协议，而是多个相关协议的组合：

| 协议名 | 方法 | 赋予的能力 | ABC类 |
|-------|------|----------|------|
| Sized | `__len__` | `len(obj)` | `collections.abc.Sized` |
| Container | `__contains__` | `item in obj` | `collections.abc.Container` |
| Iterable | `__iter__` | `for x in obj` | `collections.abc.Iterable` |
| Sequence | `__getitem__` + `__len__` | 索引访问、切片 | `collections.abc.Sequence` |
| Mapping | `__getitem__` + `__iter__` | 键值访问 | `collections.abc.Mapping` |

这些协议可以独立实现，也可以组合使用。

### 3.2 `__len__`协议：Sized

```python
# 示例13：__len__协议
class UnlimitedSequence:
    """理论上无限的序列"""
    
    def __getitem__(self, index):
        return index * 2
    
    # 不实现__len__——无限序列

unlimited = UnlimitedSequence()
print(unlimited[100])  # 200

# len(unlimited)  # TypeError: object of type has no len()

# 但我们可以用切片
print(unlimited[0:5])  # 报错：索引访问需要__len__支持切片
```

**Python如何调用`__len__`**：

```python
# 示例14：len()的协议调用
class MySized:
    def __len__(self):
        print("__len__被调用")
        return 42

obj = MySized()
length = len(obj)  # 输出: __len__被调用
print(length)  # 42
```

**底层优化**：对于内置类型（list, dict, str），`len()`直接读取C结构体的长度字段，不调用Python方法，速度极快。

### 3.3 `__contains__`协议：Container

当你写`item in obj`时，Python按以下优先级处理：

```python
# 示例15：in操作符的查找策略
class ContainsDemo:
    """演示in操作符的三种策略"""
    
    def __init__(self, items):
        self.items = items
    
    def __contains__(self, item):
        """策略1：如果定义了__contains__，直接使用"""
        print(f"__contains__({item})被调用")
        return item in self.items
    
    def __iter__(self):
        """策略2：如果没有__contains__，遍历__iter__"""
        print("__iter__被调用")
        return iter(self.items)
    
    def __getitem__(self, index):
        """策略3：如果没有__iter__，索引遍历__getitem__"""
        print(f"__getitem__({index})被调用")
        return self.items[index]

# 测试
obj = ContainsDemo([1, 2, 3])
print(2 in obj)  # __contains__(2)被调用 → True

# 如果注释掉__contains__，会调用__iter__
# 如果注释掉__iter__，会调用__getitem__
```

**优先级**：`__contains__` > `__iter__` > `__getitem__`（索引0, 1, 2...）

### 3.4 `__getitem__`协议：序列访问

`__getitem__`是最强大的容器协议，一旦实现，自动获得多项能力：

```python
# 示例16：__getitem__的自动赋能
class SimpleSequence:
    """仅实现__getitem__，获得多项能力"""
    
    def __init__(self, items):
        self.items = items
    
    def __len__(self):
        return len(self.items)
    
    def __getitem__(self, index):
        """神奇的__getitem__"""
        return self.items[index]

seq = SimpleSequence(['a', 'b', 'c', 'd'])

# 能力1：索引访问
print(seq[0])   # a
print(seq[-1])  # d

# 能力2：切片（Python自动构建slice对象）
print(seq[1:3])  # ['b', 'c']

# 能力3：迭代
for item in seq:
    print(item, end=' ')  # a b c d
print()

# 能力4：in操作（自动遍历）
print('b' in seq)  # True

# 能力5：反向迭代
print(list(reversed(seq)))  # ['d', 'c', 'b', 'a']
```

## 四、可调用协议——函数对象的一切

### 4.1 `__call__`协议：让对象像函数一样调用

任何实现了`__call__`方法的对象都可以像函数一样被调用：

```python
# 示例21：__call__协议基础
class Adder:
    """加法器：状态保持的函数"""
    
    def __init__(self, increment):
        self.increment = increment
    
    def __call__(self, value):
        """调用协议"""
        return value + self.increment

add5 = Adder(5)
print(add5(10))  # 15 — 像"函数"一样调用

# 验证Callable协议
from collections.abc import Callable
print(isinstance(add5, Callable))  # True
```

**调用过程**：`obj(args)` → `obj.__call__(args)` → C层`tp_call`槽触发

### 4.2 可调用对象 vs 函数

```python
# 示例22：可调用对象是"有状态的函数"
import math

class SmoothedValue:
    """滑动平均：状态累积的可调用对象"""
    
    def __init__(self, window_size=10):
        self.window_size = window_size
        self.values = []
    
    def __call__(self, new_value):
        """添加新值并返回滑动平均"""
        self.values.append(new_value)
        if len(self.values) > self.window_size:
            self.values.pop(0)
        return sum(self.values) / len(self.values)

averager = SmoothedValue(window_size=3)
print(averager(10))  # 10.0
print(averager(20))  # 15.0
print(averager(30))  # 20.0
print(averager(40))  # 30.0
```

**可调用对象的优势**：
- 闭包功能：封装数据和行为
- 状态保持：跨越多次调用
- 配置灵活：通过`__init__`参数化行为

### 4.3 装饰器：基于`__call__`的元编程

装饰器本质上就是一个可调用对象，它接受一个函数并返回一个新函数：

```python
# 示例23：装饰器的__call__实现
import functools
import time

class Timer:
    """计时装饰器类"""
    
    def __init__(self, func=None, *, precision=2):
        self.func = func
        self.precision = precision
        functools.update_wrapper(self, func) if func else None
    
    def __call__(self, *args, **kwargs):
        """装饰器调用协议"""
        if self.func is None:
            # @Timer(precision=3) 用法：返回装饰器本身
            self.func = args[0]
            return self
        
        # 被装饰函数的调用
        start = time.perf_counter()
        result = self.func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{self.func.__name__} 耗时: {elapsed:.{self.precision}f}秒")
        return result

# 使用装饰器
@Timer
def slow_function():
    time.sleep(0.1)
    return "完成"

@Timer(precision=4)  # 参数化装饰器
def very_slow_function():
    time.sleep(0.2)
    return "完成"

slow_function()          # slow_function 耗时: 0.10秒
very_slow_function()     # very_slow_function 耗时: 0.2000秒
```

### 4.4 工厂模式：可调用对象的设计应用

```python
# 示例24：可调用工厂
class PersonFactory:
    """人员工厂：可调用的对象工厂"""
    
    def __init__(self, default_age=18):
        self.default_age = default_age
    
    def __call__(self, name, age=None, **kwargs):
        """创建Person对象"""
        age = age if age is not None else self.default_age
        return type('Person', (), {
            'name': name,
            'age': age,
            **kwargs
        })()

# 使用工厂
factory = PersonFactory(default_age=25)
p1 = factory("Alice")
p2 = factory("Bob", age=30, city="Beijing")

print(p1.name, p1.age)  # Alice 25
print(p2.name, p2.age, p2.city)  # Bob 30 Beijing
```

## 五、哈希协议——dict key的通行证

### 5.1 哈希协议的定义

对象要作为字典的key或放入set，必须满足哈希协议：

**协约定义**：
- 实现`__hash__()`方法，返回一个整数
- 实现`__eq__()`方法，用于比较相等性
- **关键契约**：`a == b` ⟹ `hash(a) == hash(b)`（相等对象必须哈希值相同）

```python
# 示例25：哈希协议基础
class Point:
    """二维点：可哈希"""
    
    def __init__(self, x, y):
        self.x = x
        self.y = y
    
    def __eq__(self, other):
        """相等比较"""
        if not isinstance(other, Point):
            return NotImplemented
        return self.x == other.x and self.y == other.y
    
    def __hash__(self):
        """哈希值：基于坐标"""
        return hash((self.x, self.y))
    
    def __repr__(self):
        return f"Point({self.x}, {self.y})"

# 作为字典key和集合元素
p1, p2 = Point(1, 2), Point(1, 2)
p3 = Point(3, 4)

print(p1 == p2)  # True
print(hash(p1) == hash(p2))  # True（契约满足）

d = {p1: "A", p3: "B"}
print(d[p2])  # "A" — p2是不同的对象，但与p1相等且哈希相同

s = {p1, p2, p3}
print(len(s))  # 2 — p1和p2合并为一个
```

### 5.2 为什么可变对象不可哈希？

核心原因：**可变性会破坏哈希契约**。

```python
# 示例26：可变对象哈希的危险（反例）
class MutablePoint:
    """可变点：不应该可哈希"""
    
    def __init__(self, x, y):
        self.x = x
        self.y = y
    
    def __eq__(self, other):
        return self.x == other.x and self.y == other.y
    
    def __hash__(self):
        return hash((self.x, self.y))

# 危险演示
p = MutablePoint(1, 2)
d = {p: "value"}
print(d[p])  # "value"

p.x = 5  # 修改对象
# d[p]  # KeyError! 哈希值变了，找不到了
```

**Python的保护机制**：默认情况下，可变对象不可哈希

```python
# 示例27：默认哈希行为
class DefaultClass:
    pass

obj = DefaultClass()
print(hash(obj))  # 默认基于id的哈希

class WithEq:
    def __eq__(self, other):
        return True

obj2 = WithEq()
# hash(obj2)  # TypeError: unhashable type（定义了__eq__后默认不可哈希）
```

**最佳实践**：

```python
from dataclasses import dataclass

@dataclass(frozen=True)  # frozen=True使其不可变且可哈希
class ImmutablePoint:
    x: float
    y: float

p1 = ImmutablePoint(1, 2)
p2 = ImmutablePoint(1, 2)
d = {p1: "A"}
print(d[p2])  # "A"
```

# 示例28：自定义哈希策略
class CaseInsensitiveString:
    """不区分大小写的字符串"""
    
    def __init__(self, s):
        self.value = s
    
    def __eq__(self, other):
        if not isinstance(other, CaseInsensitiveString):
            return NotImplemented
        return self.value.lower() == other.value.lower()
    
    def __hash__(self):
        # 哈希基于小写形式
        return hash(self.value.lower())
    
    def __repr__(self):
        return self.value

s1 = CaseInsensitiveString("Hello")
s2 = CaseInsensitiveString("HELLO")

print(s1 == s2)  # True
print(hash(s1) == hash(s2))  # True

d = {s1: "greeting"}
