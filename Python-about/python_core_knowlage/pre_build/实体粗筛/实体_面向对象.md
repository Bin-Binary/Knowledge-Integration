╔═══════════════════════════════════════════════════════════╗
║  【类型系统】类定义与实例化                                ║
║  编号: E018 | 来源: 提取清单C070+C071+C072                ║
╚═══════════════════════════════════════════════════════════╝

【定义】 class语句创建新的类型对象(type的实例), 执行类体代码将定义收集到类__dict__中; 调用类(__init__)创建该类型的实例对象。

【结构】"它长什么样？"
- 类的元结构: type(name, bases, namespace) 是class的底层API
- 类对象(PyTypeObject子结构): {tp_name, tp_bases(tuple), tp_dict(dict), tp_call, tp_new, tp_init}
- 实例对象: {ob_refcnt, ob_type→类, __dict__(若定义了__slots__则无)}
- __slots__: 用紧凑C数组替代__dict__, 节省内存但限制动态属性
- class体: 运行时执行, 局部名字空间收集为类的__dict__

【时序】"它按什么顺序动？"
- 类创建:
  1. 编译器生成 __build_class__ 字节码
  2. 调用元类__prepare__ → 创建名字空间
  3. 执行类体代码 → 填充名字空间
  4. 调用元类__new__ → 创建类对象
  5. 调用元类__init__ → 初始化类
- 实例创建(cls()):
  1. cls.__call__ → cls.__new__(cls) → 创建空实例(PyObject_New)
  2. instance.__init__(args) → 初始化实例状态
  3. 返回实例
- self: 实例方法的第一个参数, 由描述符协议自动绑定(instance.method → 绑定方法对象)
- 方法查找: instance.method → 在type(instance).__dict__中查找 → 若找到且是descriptor → 调用__get__绑定self

【实体】"它的最小数据单元？"
- 类__dict__: 存储方法/类变量/描述符
- 实例__dict__: 存储实例属性(若未用__slots__)
- __slots__: PyMemberDef(紧凑C数组), 无__dict__开销

【边界】"它在哪里交出控制权？"
- 元类: 所有类创建都经过元类(type或其子类), 即type.__call__是对象创建的统一入口
- __new__可能返回非本类实例(如int.__new__返回int)
- __del__析构时机不确定(由GC决定)
- 多线程下__del__可能在任意线程调用

【内部关联】
- class --[使用(类型→元类型)]--> metaclass (默认type)
- instance.ob_type --[配对(实例→类)]--> PyTypeObject
- method --[配对(方法→实例绑定)]--> self (通过描述符__get__)
- __dict__ --[包含(类/实例→属性)]--> 属性键值对

【薄概念合并】 C070(class)+C071(__init__)+C072(self) 同属类生命周期, 独立成卡不增关系边。

【示例】
```python
class Point:
    __slots__ = ('x', 'y')  # 紧凑存储, 无__dict__
    def __init__(self, x, y):
        self.x = x
        self.y = y
    def dist(self):
        return (self.x**2 + self.y**2)**0.5

p = Point(3, 4)
print(p.dist())   # 5.0
# print(p.__dict__)  # AttributeError (用了__slots__)
```

║  【类型系统】继承与MRO                                     ║
║  编号: E019 | 来源: 提取清单C073+C074+C079                ║
╚═══════════════════════════════════════════════════════════╝

【定义】 类可继承一个或多个父类获取其属性和方法; MRO(Method Resolution Order)用C3线性化算法确定多继承时属性查找顺序; super()按MRO委托下一个类。

【结构】"它长什么样？"
- 单继承: class Child(Parent), __bases__ = (Parent,)
- 多继承: class Child(A, B), __bases__ = (A, B), MRO由C3算法计算
- MRO: 单调(子类在父类之前), 一致(所有父类的局部顺序在MRO中保持不变)
- super(): 返回绑定到当前实例的代理对象, super().method() = MRO中当前类之后第一个定义了method的父类

【时序】"它按什么顺序动？"
- 属性查找MRO: instance.attr → type(instance).__mro__[0].__dict__ → __mro__[1].__dict__ → ... → object.__dict__
- super()查找: 从当前类在MRO中的位置+1开始 → 沿MRO查找 → 找到返回绑定方法
- __init__协作: 多继承中super().__init__()按MRO顺序初始化——保证每个父类__init__恰好被调用一次
- 菱形继承(D→B→A, D→C→A): C3确保A只出现一次, 且出现在B和C之后
- MRO计算时机: 类创建时(元类__new__), mro()方法缓存结果在__mro__

【实体】"它的最小数据单元？"
- __bases__: tuple of class objects
- __mro__: tuple of class objects (C3线性化结果)
- _PyType_Lookup: C函数, 在MRO中查找属性

【边界】"它在哪里交出控制权？"
- 深度继承: __mro__很长时, 每次属性查找O(n)扫描, 可能性能退化
- super()必须传递当前类和self: 编译时静态确定__class__变量(零参数super()依赖此编译器魔法)
- __init__协作: 若某父类未调用super().__init__(), MRO链在该处中断

【内部关联】
- class.__bases__ --[包含(类→父类)]--> 父类对象
- class.__mro__ --[触发(C3计算→mro())]--> C3线性化算法
- super() --[触发(查找→MRO)]--> __mro__[pos+1:]

【薄概念合并】 C073+C074+C079 均涉及继承与MRO机制, 四维重合。

【示例】
```python
class A:
    def f(self): return "A"
class B(A):
    def f(self): return f"B→{super().f()}"
class C(A):
    def f(self): return f"C→{super().f()}"
class D(B, C):
    def f(self): return f"D→{super().f()}"

print(D.__mro__)  # D, B, C, A, object
print(D().f())    # D→B→C→A

# 菱形继承协作
class Base:
    def __init__(self):
        print("Base init")
class X(Base):
    def __init__(self):
        super().__init__()
        print("X init")
class Y(Base):
    def __init__(self):
        super().__init__()
        print("Y init")
class Z(X, Y):
    def __init__(self):
        super().__init__()
        print("Z init")
Z()  # Base init → Y init → X init → Z init
```

║  【类型系统】描述符与属性                                   ║
║  编号: E020 | 来源: 提取清单C075+C076+C077+C078           ║
╚═══════════════════════════════════════════════════════════╝

【定义】 描述符是实现 __get__/__set__/__delete__ 中任意方法的对象, 用于控制属性访问行为, 是property、classmethod、staticmethod等内置特性的底层机制。

【结构】"它长什么样？"
- 数据描述符(data descriptor): 实现__set__或__delete__ (优先级>实例__dict__)
- 非数据描述符(non-data descriptor): 仅实现__get__
- property: 内置数据描述符, 包装get/set/del函数
- classmethod: 非数据描述符, __get__返回绑定到类的method(第一个参数cls)
- staticmethod: 非数据描述符, __get__返回原始函数(无绑定)
- 魔术方法(__str__, __repr__, __eq__, __add__, __len__等): 非数据描述符, 定义对象行为

【时序】"它按什么顺序动？"
- 属性访问(obj.attr)的查找优先级:
  1. 数据描述符 (type(obj).__dict__中且定义了__set__)
  2. 实例__dict__ (obj.__dict__["attr"])
  3. 非数据描述符 (type(obj).__dict__中仅定义了__get__)
  4. 类变量 (type(obj).__dict__中普通值)
- 属性赋值(obj.attr = value):
  1. 若type(obj).__dict__有数据描述符 → 调用__set__
  2. 否则 → 写入obj.__dict__
- property存取: p.x → property.fget(self); p.x = v → property.fset(self, v); del p.x → property.fdel(self)
- classmethod绑定: C.method → bound(C, original); instance.method → bound(type(instance), original)
- staticmethod: 直接返回原始函数, 无绑定过程

【实体】"它的最小数据单元？"
- PyDescrObject: 描述符对象
- Property: {fget, fset, fdel, __doc__}
- PyClassMethodDescrObject: {d_common + d_type}
- 魔术方法: 在类型对象tp_as_number/tp_as_sequence/tp_as_mapping中C函数指针映射

【边界】"它在哪里交出控制权？"
- 描述符查找: 每次属性访问穿越类__dict__ 查找
- property的setter: 调用用户代码, 无法预知开销
- 魔术方法: C扩展快速通道(via tp_slots), 纯Python类需穿越__dict__查找

【内部关联】
- property --[使用(描述符→函数)]--> fget/fset/fdel
- classmethod.__get__ --[触发(绑定→类型)]--> type(instance)/cls
- obj.attr --[触发(查找→优先级)]--> 数据描述符 > 实例dict > 非数据描述符

【薄概念合并】 C075+C076+C077+C078 底层均为描述符协议的不同实例。

【示例】
```python
class Temperature:
    def __init__(self, celsius=0):
        self._celsius = celsius
    @property
    def celsius(self):
        return self._celsius
    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("Below absolute zero")
        self._celsius = value

t = Temperature(25)
t.celsius = 30   # 调用setter
print(t.celsius) # 30 (调用getter)

class Foo:
    @classmethod
    def cm(cls): return cls.__name__
    @staticmethod
    def sm(): return "static"

print(Foo.cm())   # Foo
print(Foo().cm()) # Foo (实例调用也绑定到类)
print(Foo.sm())   # static
```
