╔═══════════════════════════════════════════════════════════╗
║  【代码组织】模块与导入系统                                ║
║  编号: E024 | 来源: 提取清单C080+C081+C082+C083+C086     ║
╚═══════════════════════════════════════════════════════════╝

【定义】 模块(module)是Python代码的单文件组织单元, 每个.py文件为一个模块, 拥有独立的全局名字空间; 包(package)是包含__init__.py的子目录, 支持命名空间层级组织; import系统通过sys.path查找并执行模块代码。

【结构】"它长什么样？"
- PyModuleObject: {ob_refcnt, ob_type, md_dict(名字空间dict), md_name, md_state}
- 模块名字空间: __dict__是模块内部所有变量/函数/类的字典
- import系统状态: sys.modules(dict) — 已加载模块字典(缓存, 避免重复加载)
- sys.path: list of str — 模块搜索路径
- __init__.py: 包的标识文件, 被导入时首先执行(普通包); Python 3.3+支持隐式命名空间包(无__init__.py)
- __all__: 模块公开API列表, 控制"from mod import *"

【时序】"它按什么顺序动？"
- import执行顺序(以 import spam.eggs 为例):
  1. 检查 sys.modules["spam"] (是否已加载)
  2. 若未加载: 在sys.path中查找模块
  3. 找到后: 创建空PyModuleObject → 写入sys.modules
  4. 执行模块字节码 → 填充模块__dict__
  5. 导入子模块 spam.eggs (递归1-4)
  6. 将eggs模块对象设为spam模块的属性
  7. 返回顶层模块(spam)
- from X import Y:
  1. 执行 import X (步骤同上, 但不绑定X到当前名字空间)
  2. X的__dict__["Y"] 绑定到当前名字空间的"Y"
- from X import *:
  1. 若X有__all__: 导入__all__中列出的名字
  2. 否则: 导入X.__dict__中以下划线开头以外的所有名字
- 缓存机制: 首次import后模块对象缓存在sys.modules, 后续import直接返回
- 模块重载: importlib.reload(m) 重新执行模块字节码, 但保留同一模块对象

【实体】"它的最小数据单元？"
- md_dict: 全局名字空间(dict)
- sys.modules: 所有已加载模块的全局字典
- sys.path: 搜索路径列表(list of str)

【边界】"它在哪里交出控制权？"
- 文件查找: 在sys.path中逐目录扫描 → 依赖文件系统
- 模块执行: import时执行模块顶级代码(可能有副作用)
- 循环导入: A import B, B import A → A中只能看到B被import前已定义的属性
- 包内相对导入: from . import sub — 只能在包内使用, __name__必须有"."
- 导入钩子: sys.meta_path + sys.path_hooks 可自定义查找逻辑(如从zip/db导入)

【内部关联】
- import --[触发(查找→sys.path)]--> 搜索路径扫描
- import --[触发(加载→sys.modules)]--> sys.modules缓存
- module.__dict__ --[包含(模块→名字)]--> 所有模块级变量/函数/类

【薄概念合并】 C080+C081+C082+C083+C086 均为导入系统的不同侧面。

【示例】
```python
import os
print(os.getcwd())  # 模块.属性

from math import pi, sin
print(sin(pi/2))    # 直接使用导入的名字

import sys
print(sys.path[:2])  # 当前目录 + .zip

# 包内相对导入 (放在包内__init__.py或子模块中)
# from . import sibling   # 导入同级模块
# from .. import parent   # 导入上级模块
```

║  【名字空间】__name__与模块入口                            ║
║  编号: E025 | 来源: 提取清单C084+C085                     ║
╚═══════════════════════════════════════════════════════════╝

【定义】 名字空间(namespace)是名字到对象的映射, 以字典(dict)实现; __name__是模块的全局变量, 直接运行时等于"__main__", 被导入时等于模块名。

【结构】"它长什么样？"
- 名字空间 = dict映射: 变量名 → PyObject*
- 各层名字空间:
  - Global: 模块的 __dict__
  - Local: 函数帧的 f_locals
  - Built-in: builtins.__dict__
  - 实例: instance.__dict__
  - 类: class.__dict__
- __name__: 模块对象 md_dict["__name__"] 的值
- func_qualname: 函数/类的完整限定名(含模块名)

【时序】"它按什么顺序动？"
- 模块加载时__name__被设置:
  - python spam.py → __name__ = "__main__"
  - python -m spam → __name__ = "__main__"
  - import spam → __name__ = "spam"
- if __name__ == "__main__": 块仅在直接运行时执行(不会因import触发)
- 名字空间创建: import时创建module.__dict__, 函数调用时创建f_locals(惰性)
- 名字空间访问: LOAD_NAME/STORE_NAME字节码操作f_locals→f_globals→builtins

【实体】"它的最小数据单元？"
- 名字空间自身: PyDictObject

【边界】"它在哪里交出控制权？"
- IF __name__ == "__main__"是区分"库"与"脚本"的标准方式
- id(module.__dict__)在模块生命周期内不变
- f_locals惰性创建: 若无locals()/exec则可能不起

【内部关联】
- 名字空间 --[使用(映射→存储)]--> dict (PyDictObject)
- __name__ --[触发(检查→入口)]--> "__main__" 比较

【薄概念合并】 C084(__name__)+C085(名字空间)

【示例】
```python
# my_module.py
print(f"Loaded: {__name__}")

def main():
    print("Running main")

if __name__ == "__main__":
    main()  # 仅在 python my_module.py 时执行
```
