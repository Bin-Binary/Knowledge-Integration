╔═══════════════════════════════════════════════════════════╗
║  【异常机制】异常体系与处理                                ║
║  编号: E026 | 来源: 提取清单C090+C091+C092+C093          ║
╚═══════════════════════════════════════════════════════════╝

【定义】 异常(exception)是运行时错误信号, 沿调用栈向上传播直到被except捕获或抵达顶层终止程序; Python异常层次结构以BaseException为根, Exception为常规异常基类。

【结构】"它长什么样？"
- 异常层次结构:
  - BaseException
    - SystemExit (sys.exit())
    - KeyboardInterrupt (Ctrl+C)
    - GeneratorExit (生成器close)
    - Exception (所有常规异常的基类)
      - ArithmeticError → ZeroDivisionError, OverflowError
      - LookupError → IndexError, KeyError
      - AssertionError
      - AttributeError, NameError, TypeError, ValueError
      - OSError → FileNotFoundError, PermissionError, TimeoutError
      - RuntimeError, StopIteration, StopAsyncIteration
      - ImportError, ModuleNotFoundError
      - SyntaxError, IndentationError
      - MemoryError, RecursionError
      - 用户自定义异常(继承Exception)

【时序】"它按什么顺序动？"
- raise exc: 创建异常对象 → 设置traceback → 开始栈展开
- 栈展开(Stack Unwinding):
  1. 当前帧遇到raise → 检查except子句
  2. 若类型匹配 → 绑定到except子句变量 → 执行except体 → 可选执行else → 必须执行finally
  3. 若未匹配 → 弹出当前帧 → 向上帧重复1-3
  4. 到栈顶仍无匹配 → sys.excepthook → 打印traceback → 进程退出
- except Exception as e: e绑定到异常实例, except块结束后e被删除(防止循环引用)
- except (A, B) as e: 同时匹配多种类型
- else: try块无异常时执行(在finally之前)
- finally: 无论是否有异常、是否被捕获、是否return/break都执行
- raise (无参数): 在except块中重新抛出当前异常(保留原traceback)
- raise X from Y: 异常链, X.__cause__ = Y

【实体】"它的最小数据单元？"
- PyExceptionObject: {BaseException: args(tuple), __traceback__, __cause__, __context__, __suppress_context__}
- traceback对象: tb_frame → tb_lineno → tb_next (链表, 从内向外)
- 异常捕获: except子句通过type(obj) == exc_type or isinstance(obj, exc_type) 匹配

【边界】"它在哪里交出控制权？"
- finally中的return/break会吞掉异常(覆盖未处理异常)
- 异常链: raise X from Y 创建异常链, X.__context__自动记录隐式链
- finally中的 raise: 替换当前异常
- C扩展: C代码调用PyErr_SetString设定异常状态

【内部关联】
- raise --[触发(异常→传播)]--> 栈帧展开链
- except --[触发(捕获→匹配)]--> isinstance检查
- finally --[配对(无论如何→执行)]--> try块退出
- X.__traceback__ --[使用(异常→来源)]--> tb_frame链

【薄概念合并】 C090+C091+C092+C093 同属异常处理机制全流程。

【示例】
```python
def divide(a, b):
    try:
        result = a / b
    except ZeroDivisionError as e:
        print(f"Cannot divide by zero: {e}")
        raise ValueError("Invalid input") from e
    except TypeError:
        print("Type mismatch")
        return None
    else:
        print("Division succeeded")
        return result
    finally:
        print("Cleanup done")

try:
    divide(1, 0)
except ValueError as e:
    print(f"Caught: {e}")
    print(f"Original: {e.__cause__}")

# 异常匹配多种类型
try:
    d = {}
    x = d["missing"]
except (KeyError, IndexError) as e:
    print(f"Missing key or index: {e}")
```

║  【资源管理】上下文管理器与with语句                        ║
║  编号: E027 | 来源: 提取清单C094+C095                     ║
╚═══════════════════════════════════════════════════════════╝

【定义】 上下文管理器(context manager)是实现__enter__/__exit__的对象, with语句确保进入时获取资源(__enter__), 退出时无条件释放(__exit__, 即使发生异常), 是RAII的Python实现。

【结构】"它长什么样？"
- __enter__(self) → 返回值绑定到 as 子句变量(可选)
- __exit__(self, exc_type, exc_val, exc_tb) → 返回True吞掉异常, False让异常继续传播
- contextlib.contextmanager: 将生成器函数转换为上下文管理器(yield前=__enter__, yield后=__exit__)
- 常见上下文管理器: open(), threading.Lock, decimal.localcontext, contextlib.suppress
- 嵌套with: with A() as a, B() as b: 等价于嵌套 (Python 3.1+)

【时序】"它按什么顺序动？"
- with expr as var:
  1. 计算expr获得上下文管理器对象 cm
  2. cm.__enter__() → 返回值绑定到var
  3. 执行with体
  4. 无论3是否成功: cm.__exit__(exc_type, exc_val, exc_tb)
  5. 若__exit__返回True → 吞掉异常
- 若__enter__本身抛异常: __exit__不会被调用
- 嵌套with退出顺序: 后进先出(LIFO)

【实体】"它的最小数据单元？"
- PyCMObject: 上下文管理器无强制继承, 鸭子类型(实现__enter__/__exit__即可)
- contextlib._GeneratorContextManager: 包装生成器的上下文管理器

【边界】"它在哪里交出控制权？"
- with语句的核心价值: 保证资源释放(即使异常), 等价于try/finally的语法糖
- __exit__可能抛出新异常: 替换原异常
- 异步上下文: async with使用__aenter__/__aexit__ (需await)
- __exit__方法签名必须精确(含3个异常参数, 即使不使用)

【内部关联】
- with --[触发(进入→资源获取)]--> cm.__enter__
- with结束 --[触发(退出→资源释放)]--> cm.__exit__ (LIFO)
- __exit__返回True --[触发(吞异常→抑制)]--> 异常传播终止

【薄概念合并】 C094+C095 紧密配对。

【示例】
```python
with open("test.txt", "w") as f:
    f.write("hello")
# f自动关闭(即使write抛异常)

# 嵌套with
with open("a.txt") as fa, open("b.txt") as fb:
    data_a = fa.read()
    data_b = fb.read()

# 自定义上下文管理器
class Trace:
    def __init__(self, name):
        self.name = name
    def __enter__(self):
        print(f"Enter {self.name}")
        return self
    def __exit__(self, *args):
        print(f"Exit {self.name}")
        return False  # 不吞异常

with Trace("block"):
    print("working")
# Enter block → working → Exit block

# contextlib方式
from contextlib import contextmanager

@contextmanager
def temp_dir():
    import tempfile, os
    d = tempfile.mkdtemp()
    try:
        yield d
    finally:
        os.rmdir(d)

with temp_dir() as path:
    print(f"Using {path}")
```
