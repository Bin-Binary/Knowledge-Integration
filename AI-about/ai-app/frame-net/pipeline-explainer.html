语料处理 · 语义框架挖掘

frame-net / src

从产品文档里，自动挖出「动词 + 名词」的固定搭配
一句话：它读入一堆中文产品文档（云龙 CloudDragon 的 DevOps 说明），
像一条流水线，自动筛出「动词 + 名词」的固定搭配，
输出 FrameNet 式的语义框架候选 —— 一个触发词 + 若干角色。
文档成山 —— 待处理的海量语料

✧先懂一个概念：语义框架✧

语言里的每个「场景」，都能拆成「一个触发词 + 几个角色」。
触发词通常是动词，角色是这个场景里的参与者。

✧六步流水线✧

从「原始文档」到「框架候选」，一步步缩小范围。每步下方的小图，就是这一步实际做的事。
P0 · 解析

切句分词

标出词性
parser.py

把句子切开，标出每个词的词性（动词 v / 名词 n）。

➤
P1 · 抽取

数搭配

记录共现
bigram.py

统计「哪个动词和哪个名词老是一起出现」，记下次数。

➤
P2 · 过滤

去碰巧

统计检验
llr.py

同现远超「随机」才算真有关系，碰巧的淘汰。

➤
P3 · 提纯

辨真伪

看宾语专一否
entropy.py

宾语专一的是真谓词；跟谁都行的（如「进行」）是套话。

➤
P4 · 组合

补上下文

组成三元
trigram.py

在动词前后补上下文，凑成「副-动-名」「介-名-动」。

➤
P5 · 定稿

出模板

最后一筛
trigram.py

产出完整的「框架骨架模板」，交给人审。

✧关键一问：专一还是花心✧

整套方法最关键的一步，看动词的宾语。
宾语专一 → 真谓词；宾语花心 → 轻动词（如「进行」），只是套话。
真谓词 · 保留
轻动词 · 淘汰

✧成品长什么样✧

「部署流水线」
⇣
动词 部署 ＝ 触发词 (LU)
名词 流水线 ＝ 角色槽位 (FE)
每步都同时产出 .json（给机器）和 .md（给人）两份结果。

✧十个文件，各管一段✧

每个文件负责一个环节，pipeline.py 把它们串起来。

pipeline.py 编排

串联六步，输出报告

P0→P1→P2→P3→P3.5→P4→P5 依次跑，最后写 run_report.json 汇总。

parser.py 解析

P0 · 分词 + 句法

规则版（jieba 词性 + 找主宾），另可切换 hanlp 深度解析。

bigram.py 抽取

读语料 + P1 二元

递归读 .txt、分句去噪，统计「动词-名词」共现。

llr.py 过滤

P2 · LLR 显著性

Dunning 对数似然比，判「真有关系」还是「偶然同现」。

entropy.py 提纯

P3 熵 + 义项

按宾语分布熵打标签，上下文聚类识别一词多义。

trigram.py 三元

P4 + P5

组「副-动-名」「介-名-动」三元，算 PMI 产出框架模板。

domain_dict.py 词典

领域词典 · 喂给分词器

让 jieba 认得「流水线 / pipeline_id / MR」等专名，别切错。

io_utils.py 落盘

JSON + Markdown

统一写文件、渲染 Markdown 表格的工具。

cli.py 入口

命令行开关

python -m 运行，可改语料路径、阈值等参数。

config.py 参数

所有阈值

频率、LLR、熵、PMI 等全部可调，也可被环境变量覆盖。

读文档 → 找搭配 → 去伪存真 → 生成「触发词 + 角色」的框架候选 —— frame-net / src
