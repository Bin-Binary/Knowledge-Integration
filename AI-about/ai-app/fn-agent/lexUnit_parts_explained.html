词条档案剩下的四个栏目

lexeme · semType · valences · subCorpus —— 在一个"词条文件"里各管什么

规则：schema/lexUnit.xsd · 实例：lu/lu2.xml 等
01 · 先看全景

一个词条文件 = 一张「词条档案表」

以 <lexUnit> 为根的 XML，像一张按栏目填好的档案表，六个栏目按固定顺序出现：

<lexUnit name="cause.v" ← 封面：词条名 + 词性 + 属于哪个 frame
  ├─ ◆ header　（上一集讲过了：出处 + 颜色图例）
  ├─ <definition> "be the cause of..."　词典释义
  ├─ ◆ <lexeme />　← 名词条本身长什么样
  ├─ ◆ <semType />　← 这个词条被打的"语义类别标签"（可选）
  ├─ ◆ <valences>　← 这个词在句子里的"搭配模式公式"
  └─ ◆ <subCorpus>　← 真实例句 + 每种词的人工标注
lexeme是"哪个词"身份信息
→
semType词条分类语义标签
→
valences搭配公式规律总结
→
subCorpus例句仓库证据 + 标注
02 · lexeme

lexeme = 这个"词条"的登记名字

最朴素的栏目：说清楚"这里研究的是哪个词"。规则来自 commonTypes.xsd 的 lexemeType。

规则（xsd）实例（lu2.xml 第 57 行）
<xsd:element name="lexeme" type="fn:lexemeType" minOccurs="1" maxOccurs="unbounded"/>
至少 1 个，可多个（词组有多词时不止一个）；每个必须有 name（词） 和 POS（词性）。		 <lexeme POS="V" name="cause"/>
含义：词条是动词 cause。选择受限：POS 只能从 A/ADV/V/N… 等固定枚举里选。

🔤 有什么用 1

文件"自我介绍"：给机器定位是哪个词、什么词性，其它栏目（valences/subCorpus）都默认是围绕它讲的。

🎯 有什么用 2

一个词条可以是"多词表达式"，比如 all right：那时会写多个 lexeme，每个带顺序。

🗂️ 有什么用 3

文件名 lu2.xml 只是编号，真正可读的名字在 lexeme 里——方便人眼检索与索引。

03 · semType

semType = 打在整个词条上的「类别标签」

不是每个词条都有（可选栏目）。有的话，就是一两个"这个词的语义归类"，像图书馆贴的分类贴纸。

📖 规则（commonTypes.xsd）

<xsd:complexType name="semTypeRefType">
  ├─ <attribute ID (整数) />
  └─ <attribute name (名字) />
只允许"ID + 名字"两个信息，不能乱加。

格式跟 header 里的 corpus 一样，属于"引用型"栏目——只写一个 ID 去关联系统的语义类型表。

💡 实例

lu10294.xml（different.a）第 35 行：
<semType name="Negative" ID="99"/>
lu10123.xml：Extragalactic
<semType name="Sensory_modality" ID="92"/>

含义："different 这个词条的词义，属于"负面(Negative)"这一类语义。"
而 cause.v（lu2.xml）没有 semType，因为它是可选的。

⭐ 有什么用：批量做语义研究的"筛子"——例如"把所有 Negative 语义的词一块儿取出来"对比观察，不用一个个读文件。

04 · valences（这集的重头戏）

valences = 这个词的真实「搭配模式」总结

上面是"身份与标签"，这里是真正的"语法知识"：大量例句统计后，这个动词的每个语义角色(FE)在句子里通常出现在什么语法位置 GF、用什么短语形式 PT。

<valences>　内部只有三种"零件"
  ├─ <governor />　支配词（本文件未使用，规则预留）
  ├─ <FERealization> ×N　：单个语义角色每次是怎么被"说出来的"
  │　 ├─ <FE name="Actor"/>　哪个角色
  │　 └─ <pattern total="24">　一种句式，出现24次
  │　    ├─ <valenceUnit GF="Ext" PT="NP" FE="Actor"/>　主语·名词短语
  │　    └─ <annoSet ID="784448"/> ×24　指向例句仓库的具体标注
  └─ <FEGroupRealization> ×N　：多个角色"一起组合出现"的模式

从 lu2.xml 里"解码"出来的一句话总结

Actor 最常见的两种样子

<FE name="Actor"/> ×26
<pattern total="24"> GF=Ext PT=NP → "actor 当主语，名词短语"
<pattern total="2"> GF=Dep PT=PP[by] → "by XXX 介词短语当 actor"
角色组合例子（FEGroupRealization）

Effect 最常见的两种样子

<FE name="Effect"/> ×115
<pattern total="89"> GF=Obj PT=NP → "effect 当宾语"，如 caused the loss

三兄弟一起出场 top1

Cause + Effect 组合 ×66 → str#1（44次）：Cause当主语(Ext,Np) + Effect当宾语(Obj,Np)，即 "X caused Y"

⭐ 有什么用：把标注语料的规律自动算成语法公式。NLP 里这就是"配价词典"——生成语法、语义角色标注、词典学、教学都能直接查。

05 · subCorpus

subCorpus = 例句仓库 + 人工标注

上面的 valences 是"总结"，这里是"原始证据"：一仓库真实英文句子，每条句子都被人工标注了每个词属于哪个语义角色、什么语法位置、什么短语类型。

<subCorpus name="V-429-s20-rcoll-change">
  └─ <sentence ID="651962">　一条真实例句
     ├─ <text> "What caused you to change your mind ?" 原句
     └─ <annotationSet ID="784392" status="MANUAL"> 人工标注集
        └─ <layer name="FE">　语义角色层
           ├─ <label name="Cause" start="0" end="3"/>
           └─ <label name="Effect" start="12" end="14"/> ...
  还有 layer：GF(语法位置) / PT(短语类型) / Target(目标词) / BNC(词性) …
What caused you to change your mind ?
Cause 起因 caused = Token=Tasg=目标词 Effect 结果

⭐ 有什么用：这就是 FrameNet 的核心资产——金标(manually-annotated)训练数据。机器学习/语义解析用它当标准答案；其中 valences 的 annoSet ID 就是从这些句子堆里统计来的。

06 · 把四处连成一张网

它们四个不是独立栏目，而是环环相扣

以 annoSet 编号为"接头暗号"，四个栏目在文件内部互相咬合：

header 颜色图例FE 的缩写与底色
→
valences 公式pattern 后面挂着 annoSet ID
→
subCorpus 例句annotationSet 有相同 ID，status=MANUAL

🔬 实锤例子：annoSet ID = 784392（lu2.xml）

栏目内容
valences → Cause<annoSet ID="784392"/> 挂在 pattern: GF=Ext · PT=NP · FE=Cause
valences → Effect<annoSet ID="784392"/> 挂在 pattern: GF=Obj · PT=NP · FE=Effect
subCorpus → sentence 651962<annotationSet ID="784392" status="MANUAL"> label: Cause(0-3) 当主语，Effect(12-14 & 16-34) 当宾语

同一个 ID 把"公式"和"例句证据"钉在一起：valences 说 Actor 常作主语，subCorpus 里就能翻到"What caused you…"那条真句验证。整个文件因此可交叉核对、可自动校验，也永远自圆其说。

07 · 回到你的问题

一句话总结四个栏目

🔤

lexeme

登记"这是哪个词、什么词性"——身份栏。

🏷️

semType

给整个词条贴"语义类别"标签，便于归类检索——分类栏（可选）。

📐

valences

把大量例句统计成"这个语义角色常在句中哪个位置、长成什么短语"的配价公式——规律栏。

📚

subCorpus

真实例句 + 逐词人工标注，是公式的证据来源，也是 NLP 训练金标数据——证据栏。

lexeme 说是谁 → semType 说是哪类 → valences 说怎么造句 → subCorpus 拿出真句子当证据。
前三个是"结论"，最后一个是"依据"；依靠 annoSet 编号，整份文件环环可查。
