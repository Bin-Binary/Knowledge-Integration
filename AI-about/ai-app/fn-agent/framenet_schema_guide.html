案件导入：这是什么案？

读懂这三句话，再往下看图

① FrameNet 是"人话的语义词典"：它不管一个词怎么读，只管"这个词背后是件什么事、谁在里面扮演什么角色"。

② 这套 schema 就是给这些数据划好的卷宗格式——11 个 .xsd 文件，规定了每一份 XML 卷宗该长什么样。

③ 整件事只有三步循环：先立案件模板（Frame） → 把词签进来（LexUnit） → 拿真实句子当证物做标注（sentence）。

壹

卷宗结构：11 个文件怎么分工

先记三种颜色：橙=词典定义 · 紫=注释证据 · 青=检索索引

橙 · 词典卷宗 紫 · 注释卷宗 青 · 检索索引 绿 · 公共部件（复用） 深蓝 · 类型地基 实线箭头 = 拼装复用（include） · 虚线箭头 = 兜底的公共引用

逐项破译：八个证物卡片

对着上面的关系图，一个卡片一句话看懂

①

Frame 框架

frame.xsd · 主卷宗

一个事件/情景的"模板卷宗"，比如 Killing 杀人。ID 是案号，name 首字母大写，所有证据围绕它归档。

②

FE 框架元素

frame.xsd · 角色

模板里的参与方：凶手/被害人/凶器。Core 丢了案不成立，Peripheral 可有可无；还能用 requires / excludes 互相约束。

③

LexUnit 词汇单元

lexUnit.xsd · 词条

把一个具体词"签进"框架，如 murder.v。日后读到这个词，就能触发对应框架。

④

Lexeme 词形基元

lexUnit.xsd · 词形

词的最小形态单元（murder）。标注是不是句头（headword）、是否要断词。一条词含 1 个以上。

⑤

valences 配价阵

lexUnit.xsd · 句式

这个词在句子里"角色怎么出场"的全部套路：领导词 governor + 每条 pattern（FE + PT 实现方式 + GF 语法关系）。

⑥

标注证据链

sentence.xsd / fullText.xsd

子语料库→句子→注解集（按 frameID/luID 挂回①③）→层（目标词/词性/角色）→标签（精确起止位置）。

⑦

FrameRelation

frameRelations.xsd · 牵连网

框架之间的"办案牵连"：继承/使用/视角/因果…用 super / sub 两个 ID 把大图连起来；FERelation 把角色也绑定。

⑧

SemType 语义标签

semTypes.xsd · 标签库

给框架/角色/词条贴通用标签（实体/交通工具…），按标签就能批量调档。

肆

收尾：三种索引怎么配合查案

数据全靠 ID 串联，索引就是把最常用的三条 ID 路改成"目录"

索引文件查什么相当于
frameIndex.xsd 框架名 ↔ 案号（ID）的快速目录 卷宗索引卡
luIndex.xsd 词条 ↔ 归属框架 ↔ 有没有标注（hasAnnotation / numAnnotInstances） 词条登记簿
fulltextIndex.xsd 语料 / 文档级目录，正文按文件归档 档案库柜号

commonTypes.xsd 是唯一被全库引用的"地基"，header.xsd 与 sentence.xsd 是被复用的公共部件 —— 看懂这三层，整个设计就通了。
