commonTypes.xsd — 公共类型库

一句话理解

所有其他 XSD 都 include 这个文件，它定义了到处复用的基础数据类型——就像一栋大楼的砖块和螺丝钉。

所有XSD的依赖 7个简单类型 + 2个复杂类型 + 2个属性组

7 个简单类型 (SimpleType)

dateTimeType

日期时间格式
MM/DD/YYYY HH:MM:SS TZ Day
如 06/10/2002 03:08:32 PDT Mon

defType

定义文本类型
xsd:string 的限制
用于 FE/LU 的 definition

IDType

通用 ID
xsd:int ≥ 0
Frame/FE/LU/... 全用这个

labelSpanType

标注起止位置
xsd:int ≥ 0
Label 的 start/end 属性

orderType

顺序编号
xsd:int ≥ 0
lexeme 的 order、段落号等

countType

计数值
xsd:int ≥ 0
句数、标注数等

RGBColorType

颜色值
[0-9A-Fa-f]{6}
FE 的前景/背景色

POSType

14种词性枚举
V N A ADV AVP PREP C SCON CCON PRON ART NUM INTJ IDIO

coreType

FE 核心类型 4 选 1
Core | Peripheral | Extra-Thematic | Core-Unexpressed

LUNameType

LU 名称格式
.+\..+ 即"词.词性"
如 avenge.v

frameNameType

Frame/FE 名称
[A-Z].* 大写开头
如 Revenge

2 个复杂类型 (纯属性)

lexemeType

词素：name + POS(必填)
breakBefore / headword / order(可选)
用于 lexUnit 下的 lexeme 元素

semTypeRefType

语义类型引用：ID + name
被 FE、lexUnit、semTypes 使用
是"引用"，完整定义在 semTypes.xsd

2 个属性组 (AttributeGroup)

frameReference

frameID + frame
在 lexUnit、annotationSet 中引用 Frame

basicLUAttributes

ID + name + POS + incorporatedFE + status
lexUnit 的基础属性复用组

header.xsd — 文档头信息

一句话理解

每个 lexUnit XML 和 fullText XML 开头都有一个 <header>，它记录"这段标注来自哪个语料库、哪篇文档、属于哪个 Frame 的哪些 FE"——是上下文说明，让后面的标注数据可追溯。

被 lexUnit + fullText 两个 XSD include
headerType
corpus (0+)
IDnamedescription
frame (0..1)
仅包含 FE 子元素
corpus 下
document (0+)
ID / name / description
frame 下
FE (0+)
name / abbrev / type / bgColor / fgColor
实例：avenge.v 的 header 里列出 Revenge 框架全部 13 个 FE 的名称和配色，方便标注时使用
<header> <corpus ID="195" name="ANC" description="American National Corpus"> <document ID="25397" name="chapter8_911report"/> </corpus> <frame> <FE name="Avenger" type="Core" bgColor="FF0000" fgColor="FFFFFF"/> <FE name="Offender" type="Core" bgColor="9F79EE" fgColor="FFFFFF"/> ... </frame> </header>

sentence.xsd — 句子标注结构

一句话理解

这是 FrameNet 最核心的标注数据结构。一句真实文本(如 "They took revenge")，被拆成多层 label —— Target层标触发词、FE层标框架元素、GF层标语法功能、PT层标短语类型……每一层都是一套 span 标注。

被 lexUnit + fullText 两个 XSD include 4 层嵌套：sentence → annotationSet → layer → label

lexUnit.xsd — 词汇单元详情

一句话理解

每个 lexUnit 是一个独立 XML 文件(如 lu6056.xml = avenge.v)，它包含四大部分：header(上下文) + definition(释义) + valences(配价模式统计) + subCorpus(标注语料句子)。是 FrameNet 里信息密度最高的文件。

include: commonTypes + header + sentence 核心新增：valences(配价) + subCorpus(语料)

valences — 配价模式 (语言学的"句式表")

valences
governor (0+)
支配词 lemma + type

单 FE 实现模式

多 FE 组合模式
valenceUnit 是最小配价单元，三个属性：FE="Avenger" + PT="NP" + GF="Ext"
含义："Avenger 这个 FE 以名词短语(NP) 的形式出现在外部语法位置(Ext)"

FERealization

每个 FE 在语料中各有多少种表达方式。
如 Avenger: NP.Ext(25句) / CNI(7句) / Poss(1句)

FEGroupRealization

多个 FE 组合出现的模式。
如 Avenger+Injury 同时以什么 PT/GF 表达。

governor

支配词：配价模式中的上层控制词。
含 lemma + type + annoSet 列表。

<!-- avenge.v 的 Avenger FE 实现模式 --> <FERealization total="33"> <FE name="Avenger"/> <pattern total="7"> <valenceUnit FE="Avenger" PT="CNI" GF=""/> <!-- 构造性空缺 --> <annoSet ID="1313398"/> ... </pattern> <pattern total="25"> <valenceUnit FE="Avenger" PT="NP" GF="Ext"/> <!-- 名词短语外部 --> <annoSet ID="1313328"/> ... </pattern> </FERealization>

fullText.xsd — 全文标注

一句话理解

和 lexUnit 不同，fullText 的标注对象不是"某个词的用法"，而是一整篇真实文档——比如一篇新闻的每个句子都被标注，每个句子里可能有多个词触发不同 Frame。它是"文档级"视角，lexUnit 是"词汇级"视角。

include: header + sentence 结构极简：header + sentence*
fullTextAnnotation
header (1)
headerType
sentence (0+)
sentenceType
同一句话可触发多个 Frame！如下面这句，fire.n 触发 Fire_burning 框架，rage.v 也触发 Fire_burning，continue.v 触发 Process_continue 框架——每个触发对应一个独立的 annotationSet。
<fullTextAnnotation> <header> ... </header> <sentence ID="4164976"> <text>Forest fires continue to rage in Spain</text> <!-- 第1个标注：fire.n → Fire_burning --> <annotationSet luName="fire.n" frameName="Fire_burning"> <layer name="Target"><label start="7" end="11" name="Target"/></layer> <layer name="FE"> <label start="0" end="5" name="Fuel" bgColor="800080"/> <label start="7" end="11" name="Fire" bgColor="0000FF"/> </layer> </annotationSet> <!-- 第2个标注：rage.v → Fire_burning --> <annotationSet luName="rage.v" frameName="Fire_burning"> ... </annotationSet> <!-- 第3个标注：continue.v → Process_continue --> <annotationSet luName="continue.v" frameName="Process_continue"> ... </annotationSet> </sentence> </fullTextAnnotation>

一句话理解

frameRelations.xsd — 框架间关系（全局版）

一句话理解

frame.xsd 里的 frameRelation 只记录单个 Frame 的关系。而 frameRelations.xsd 是一个全局汇总文件(frRelation.xml)，把所有 Frame 间关系集中存储，还多了关键的一层——FERelation（FE 之间的映射），记录"上层 FE 如何对应到下层 FE"。

3 层嵌套：frameRelationType → frameRelation → FERelation

frameRelationType.name = 关系类型名，如 "Inherits from", "Causative_of"
superFrameName / subFrameName 两层都有，区分类型级和实例级
<!-- Causative_of 关系：Cause_to_move_in_place 是 Moving_in_place 的使役形式 --> <frameRelationType name="Causative_of" superFrameName="Causative" subFrameName="Inchoative/state"> <frameRelation superFrameName="Cause_to_move_in_place" subFrameName="Moving_in_place" supID="276" subID="670"> <FERelation superFEName="Theme" subFEName="Theme" supID="2388" subID="4486"/> <FERelation superFEName="Place" subFEName="Place" supID="2389" subID="4491"/> ... </frameRelation> </frameRelationType>
FERelation 告诉我们：上层 Frame 的 Theme FE → 对应下层 Frame 的 Theme FE
有时命名不同(如 supItem→subEntity)，这就是 FE 映射的核心价值

完整实例：一句话走通全部 11 个 Schema

"They took revenge for the deaths of two loyalist prisoners."

从一句话到全库串联

① frameIndex — 查目录，找到 Revenge 框架

在 frameIndex.xml 中按 name 搜索 → 找到 Revenge (ID:347)

<frame ID="347" name="Revenge" mDate="..."/>

② commonTypes — 类型支撑

frameIndex 用的 IDType、frameNameType、dateTimeType 全在 commonTypes 里定义。后续所有数据结构都依赖这套基础类型。

IDType = int≥0, frameNameType = [A-Z].*, dateTimeType = MM/DD/YYYY ...

③ frame — 框架详情

打开 Revenge.xml → 看到 13 个 FE、2 个 FEcoreSet、1 条继承关系、13 个 lexUnit。

Avenger Offender Punishment Injury Injured_party Manner Time Result ...
FEcoreSet: {Injury ↔ Injured_party}, {Avenger ↔ Punishment}
frameRelation: Inherits from → Rewards_and_punishments

④ semTypes — FE 的语义标签

Avenger FE 引用了 semType "Sentient"(ID:5)，说明填充者必须是有知觉的存在。Injury FE 没有显式 semType。

Avenger FE → <semType name="Sentient" ID="5"/> ↓ Sentient → superType: Animate_being(65) → ... → Physical_object

⑤ frameRelations — 全局框架关系 + FE 映射

Revenge Inherits from Rewards_and_punishments。在 frRelation.xml 中查找该关系，能看到上层 FE 如何映射到下层 FE。

frameRelationType name="Inherits from" frameRelation superFrameName="Rewards_and_punishments" subFrameName="Revenge" FERelation: super FE "Reward" → sub FE "Punishment" (名称不同！) FERelation: super FE "Evaluee" → sub FE "Offender"

⑥ luIndex — 定位 avenge.v 或 revenge.n

在 luIndex.xml 查找 → revenge.n (ID:6067, status:Finished_Initial, frameID:347)

<lu ID="6067" name="revenge.n" status="Finished_Initial" frameName="Revenge" hasAnnotation="true" numAnnotInstances="34"/>

⑦ lexUnit — avenge.v 的完整详情

打开 lu6056.xml → header 列出所有13个FE的配色 → definition → lexeme(avenge) → valences(配价统计) → subCorpus(33条标注语料)

valences: FERealization[Avenger]: NP.Ext(25句) / CNI(7句) / Poss(1句) FERealization[Injury]: NP.Obj(14句) / NP.Ext(4句) / PP[for](1句) / PP[of](1句) FERealization[Offender]: PP[on].Dep(16句) / NP.Obj(4句) / ... subCorpus → sentence*: "They took revenge for the deaths..."

⑧ header — lexUnit 里的上下文信息

avenge.v 的 <header> 记录：属于哪个语料库、哪篇文档、Revenge 框架的 FE 全部配色方案（方便标注软件渲染）

<header> <corpus ID="195" name="ANC">...</corpus> <frame> <FE name="Avenger" type="Core" bgColor="FF0000" fgColor="FFFFFF"/> <FE name="Offender" type="Core" bgColor="9F79EE" fgColor="FFFFFF"/> ... </frame> </header>

⑨ sentence — 标注该句的多层标签

在 subCorpus 中找到该句，annotationSet 包含 Target/FE/GF/PT 等多层 label：

<text>They took revenge for the deaths of two loyalist prisoners.</text> Target 层: start=9 end=15 → "revenge" FE 层: "They"(0-3) = Avenger bgColor=FF0000 "for the deaths..."(17-end) = Injury bgColor=00008B GF 层: "They" = Ext PT 层: "They" = NP itype: Offender = INI(固有空缺，复仇句中常不提对方)

⑩ fullText — 这句话也出现在全文语料中

如果该句来自某篇全文标注文档(如 ANC 语料)，同一句话会同时出现在 fullText XML 中——词汇视角(lexUnit)和文档视角(fullText)都能看到同一标注。

fullText XML: 同一 sentence → 可能有多个 annotationSet - revenge.n → Revenge 框架 - 其他词触发的不同框架标注

⑪ fulltextIndex — 反查语料来源

想知道这篇文档属于哪个语料库？查 fulltextIndex → corpus=ANC, document=chapter8_911report

<corpus ID="195" name="ANC" description="American National Corpus"> <document ID="25397" name="chapter8_911report"/> </corpus>
