# qa（架构与设计决策问答库）
* **定位**：按架构粒度拆分的长效问答档案，用于承载持续增长的模块设计与工程实践 QA。
* **规范**：单条问答统一使用 `### Q<编号>：<标题>` 标题层级，确保 Markdown 切片器精准按标题分块。
* **目录**：[[QA_01_Architecture_And_DIP]] | [[QA_02_Registry_And_Routing]] | [[QA_03_Patterns_And_Contracts]] | [[QA_04_Micro_Tricks_And_Storage]]

提示词：

提炼上两轮中可以收敛到以下粒度的问题，并按输出要求沉淀为QA对

1. 粒度收敛标准（四选一，严禁自创分类）
* **[[QA_01_Architecture_And_DIP]]（粗粒度）**：方法论、架构原则（DIP/六边形/ACL）、系统边界、模块依赖方向、全链路生命周期。
* **[[QA_02_Registry_And_Routing]]（中观粒度）**：插件注册机制、路由与分发策略、多策略组合（Chain/Composite）、状态流转控制。
* **[[QA_03_Patterns_And_Contracts]]（细粒度）**：标准抽象基类、设计模式（模板方法/策略/适配器）、数据契约边界（贫血/充血模型）、接口签名与职责切分。
* **[[QA_04_Micro_Tricks_And_Storage]]（精细粒度）**：微观代码技巧、特定算法（如哈希/并查集）、序列化/存储格式（Markdown/Pydantic 校验）、防呆与边界防御细节。

2. QA 输出格式规范
必须使用三级标题 `### Q<X>：<问题核心标题>` 开头（若未知当前最大编号，暂用 `Q_NEW` 占位），并包含以下完整字段：

> **归属档案**：`[[对应的QA文件名]]`（标注具体粒度）
> **核心疑惑**：用一句话精准描述触发本次讨论的痛点、反直觉点或设计矛盾。
> **核心释义**（可选）：若涉及特定设计模式或专有概念，用 1~2 句话给出大白话定义。
> **核心答案**：直击本质的结论与架构原则，说明“为什么这么做”以及“不这么做的后果”。
> **真实正反例对比**：必须结合当前项目的真实类名、方法名或业务场景编写（禁止使用 `Foo/Bar` 等无意义占位符）：
> * ❌ **反例（Anti-Pattern）**：展示会导致耦合、静默错误或违反原则的写法，并标注死穴所在。
> * ✅ **正例（Best Practice）**：展示符合当前架构规范的写法，并标注核心收益。
